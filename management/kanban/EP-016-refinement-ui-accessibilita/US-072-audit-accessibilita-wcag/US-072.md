# US-072 — Audit e fix accessibilità WCAG 2.2 AA baseline

## Descrizione
Come utente con disabilità, voglio che l'intera applicazione rispetti la baseline WCAG 2.2 AA su contrasto, target touch, focus visibile, navigazione tastiera, heading hierarchy, form labels, alt immagini e zoom 200%, affinché possa utilizzare tutte le funzionalità indipendentemente dalle mie capacità fisiche o sensoriali. [^src: wiki/concepts/material-design-3-accessibility.md §Accessibilita WCAG 2.2 AA (baseline)]

## Business Rules
- Contrasto testo: >= 4.5:1 (normale), >= 3:1 (grande).
- Contrasto UI components: >= 3:1.
- Target touch: >= 24x24 CSS px (idealmente 48x48 su mobile).
- Focus visibile: sempre presente; no outline rimosso senza alternativa equivalente (SC 2.4.11/2.4.13).
- Tastiera: tutte le interazioni completabili da sola tastiera; ordine tab logico.
- Heading hierarchy: un solo h1 per vista; no salti di livello.
- Form labels: `<label for>` o `aria-label` esplicite; error message via `aria-describedby`.
- Immagini: `alt` semantico; icone decorative con `aria-hidden="true"`.
- Zoom: supporto fino a 200% senza loss of content o funzionalità.
[^src: wiki/concepts/material-design-3-accessibility.md §Accessibilita WCAG 2.2 AA (baseline)]

## Acceptance Criteria
- [ ] Punteggio Lighthouse Accessibility >= 95 su tutte le viste principali (login, dashboard, analisi, deep analysis, top picks, watchlist, screener, profilo).
- [ ] Audit axe-core: zero issue di severità serious o critical.
- [ ] Verifica manuale con tastiera: flussi critici (login, analisi ticker, deep analysis, top picks) completabili senza mouse.
- [ ] Verifica manuale con screen reader (VoiceOver/NVDA): annuncio corretto di heading, form, risultati analisi.
- [ ] Zoom 200% su tutte le viste: nessun loss of content, scroll orizzontale, o sovrapposizione.
- [ ] Un solo h1 per vista verificato su tutte le pagine.
- [ ] Tutte le icone decorative hanno `aria-hidden="true"`; tutte le immagini informative hanno `alt` semantico.
