# US-083 — Hardening E2E a11y post-incident run locale

## Descrizione
Come sviluppatore che esegue la suite FE in locale, voglio che `npm run test:e2e` (Playwright mocked, esclusi skip cutover-smoke) sia verde dopo `playwright install`, affinché i 4 fallimenti funzionali emersi nel rerun post-incident non blocchino la validazione locale mentre CI resta il riferimento di regressione. [^src: wiki/incidents/2026-05-27-local-fe-test-run.md §Aggiornamenti (v2026-05-27) — Rerun post `playwright install`]

## Business Rules
- Scope: solo i 4 test E2E falliti documentati nell'incident (3× `accessibility-keyboard`, 1× `deep-analysis` happy path); i 10 skip `cutover-smoke` restano fuori scope.
- Vitest (`npm test`) resta verde — nessuna regressione unitaria richiesta da questa storia.
- CI #131 su `4c7ca73` resta riferimento: il fix è hardening/robustezza test locali, non hotfix applicativo bloccante.
- Allineamento con US-072 / TSK-193: i flussi tastiera e deep analysis devono restare verificabili senza mouse, senza assert flaky su stati transitori non osservabili in mock veloce.

## Acceptance Criteria
- [x] `accessibility-keyboard` Flow 1 (login Tab): focus raggiunge `login-email` con strategia robusta (non solo conteggio Tab fisso fragile).
- [x] `accessibility-keyboard` Flow 2 (search Tab): focus raggiunge l'input ricerca con strategia robusta.
- [x] `accessibility-keyboard` Shift+Tab: focus raggiunge `login-submit` con strategia robusta.
- [x] `deep-analysis` happy path AAPL: test passa senza flake su `deep-analysis-loading` (assert allineato a mock veloce o osservabilità garantita).
- [x] `npm run test:e2e` in `src/frontend/`: 30 pass, 0 fail, 10 skip (cutover-smoke) in locale dopo `npx playwright install`.
- [x] Nessuna modifica al comportamento utente in produzione richiesta oltre a eventuali `data-testid` / ordine tab già previsti da US-072.
