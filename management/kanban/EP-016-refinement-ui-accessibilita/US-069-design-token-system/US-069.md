# US-069 — Sistema design token colori, tipografia e shape

## Descrizione
Come designer, voglio che l'interfaccia utilizzi un sistema di design token semantici per colori (primary, secondary, tertiary, surface, surface-container), tipografia (scala display/headline/title/body/label) e shape (corner radius small/medium/large), derivati da un seed color, affinché l'UI sia visivamente coerente e facilmente adattabile a nuovi temi o brand. [^src: wiki/concepts/material-design-3-accessibility.md §Design Token System M3]

## Business Rules
- I colori sono derivati da un seed color tramite schema dinamico con ruoli semantici: `primary`, `secondary`, `tertiary`, `surface`, `surface-container`, etc.
- La tipografia segue una scala semantica: `display`, `headline`, `title`, `body`, `label` con sizing coerente.
- I corner radius usano token semantici: `shape.small`, `shape.medium`, `shape.large`.
- I token sostituiscono i valori hardcoded nei componenti UI esistenti.
- `pending_clarification: [Q_004]` — la scelta della libreria di implementazione dei token (M3 nativo vs token system allineato all'infrastruttura componenti corrente) è in attesa di decisione architetturale.

## Acceptance Criteria
- [ ] Esiste un file di token semantici che definisce colori, tipografia e shape.
- [ ] Almeno 5 componenti UI principali (bottoni, card, input, navigation, dialog) usano i token semantici invece di valori hardcoded.
- [ ] Cambiare il seed color aggiorna coerentemente tutti i colori derivati nell'intera UI.
- [ ] La scala tipografica è usata in modo coerente (un solo `display` per pagina hero, `headline` per sezioni principali, `body` per testo corrente).
- [ ] I corner radius sono coerenti su componenti simili (es. tutte le card usano `shape.medium`).
