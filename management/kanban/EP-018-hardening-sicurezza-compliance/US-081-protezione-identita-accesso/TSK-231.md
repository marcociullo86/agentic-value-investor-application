# TSK-231 — BE HibpClient: verifica password compromesse k-anonymity

## Context
US-081 richiede integrazione HIBP per verifica password compromesse in fase di registrazione e cambio password.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-081-protezione-identita-accesso/US-081.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §5]

## Technical Specs
- **BE:** `HibpClient` in package `client`
- **API:** HIBP k-anonymity (https://api.pwnedpasswords.com/range/{first5SHA1})
- **Privacy:** solo primi 5 char SHA-1 inviati, nessuna password in chiaro
- **Integrazione:** chiamato in fase di registrazione e cambio password
- **Se compromessa:** rifiutare con messaggio user-friendly (non rivelare quante volte)
- **Resilience:** se API HIBP non raggiungibile → log warning, ammetti password (non bloccare utente)
- **Config:** `app.security.hibp.enabled`, `app.security.hibp.api-url`

## Implementation Steps
1. Creare HibpClient con WebClient/RestClient
2. Implementare SHA-1 hash + prefix 5 char
3. Implementare query API HIBP range
4. Implementare confronto suffix nella response
5. Integrare in registrazione e cambio password
6. Implementare resilience: HIBP down → warning, ammetti

## Definition of Done
- [ ] Password compromessa → rifiutata
- [ ] Password sicura → accettata
- [ ] Solo prefix SHA-1 inviato (k-anonymity)
- [ ] HIBP down → graceful degradation
- [ ] Code review approvata

## Dependencies
Nessuna.
