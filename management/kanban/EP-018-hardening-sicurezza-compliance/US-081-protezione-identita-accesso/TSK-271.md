# TSK-271 — QA E2E Playwright mocked-tier flusso CAPTCHA login

## Context

La review TSK-238 (finding F-238-3-001) ha rilevato che gli AC "Login con CAPTCHA valido accettato" e "captchaRequired con token assente/invalido → errore" sono coperti solo da unit test Vitest con `TurnstileWidget` stubbed component. Manca una spec Playwright che eserciti l'intero flusso trigger-widget-solve-resubmit a livello di pagina.

Questo task implementa una suite Playwright **mocked-tier**: `page.route()` intercetta `POST /api/auth/login` senza toccare la CDN Cloudflare (zero dipendenza da rete esterna in CI). Il widget Turnstile può essere simulato via `page.route()` sull'URL `https://challenges.cloudflare.com/turnstile/v0/api.js` o tramite test-attr selectors se il componente espone un hook di simulazione.

Nota: questo test NON dipende dal fix BE CSP (TSK-270) e può essere sviluppato e portato verde in CI in parallelo. Un eventuale E2E reale su deploy di produzione (che richiede la CSP BE corretta) resta un lavoro separato, al momento bloccato dal gap `be-csp-missing-turnstile-allowlist`.

## Technical Specs

- **Framework:** Playwright (suite esistente `frontend/e2e/`)
- **Strategia:** mocked-tier — `page.route()` per stubare sia `POST /api/auth/login` (risposta con `captchaRequired: true`) sia l'eventuale script Cloudflare CDN
- **Scenari da coprire:**
  1. **Login sotto soglia (baseline):** `page.route` → risposta normale → login riuscito; widget non visibile
  2. **captchaRequired → widget appare:** `page.route` → risposta `{ captchaRequired: true, ... }` al primo submit → widget Turnstile diventa visibile
  3. **Solve + resubmit → login OK:** simula il solve del widget (token iniettato) → secondo submit → risposta login OK → redirect corretto
  4. **Token assente/invalido → errore:** `captchaRequired: true` + token invalido → mock risponde 400 → messaggio di errore visibile all'utente
- **Nessuna dipendenza da CDN Cloudflare** in CI (tutto via `page.route()`)

## Implementation Steps

1. Creare spec `frontend/e2e/captcha-login.spec.ts` (o integrare in suite auth esistente)
2. Configurare `page.route('**/api/auth/login', ...)` con handler che restituisce `captchaRequired: true` per il primo submit e successo per il secondo
3. Facoltativamente: stubare anche `**/challenges.cloudflare.com/**` per prevenire richieste reali CDN in CI
4. Implementare scenario baseline (no captcha), trigger widget, solve + resubmit, errore token invalido
5. Verificare che i selettori del widget Turnstile (o del suo wrapper FE) siano presenti/assenti come atteso
6. Eseguire in CI (`pnpm playwright test`) — verde senza accesso rete esterna

## Definition of Done

- [ ] Spec Playwright copre scenario baseline (no CAPTCHA gate)
- [ ] Spec copre trigger widget (`captchaRequired: true`)
- [ ] Spec copre solve + resubmit → login riuscito
- [ ] Spec copre token invalido → errore visibile utente
- [ ] Nessuna dipendenza da CDN Cloudflare in CI (tutto mocked)
- [ ] Suite verde in CI (`pnpm playwright test`)
- [ ] Code review approvata
