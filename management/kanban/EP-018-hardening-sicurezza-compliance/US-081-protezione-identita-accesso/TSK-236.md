# TSK-236 — QA Test HIBP: password compromessa rifiutata, sicura accettata

## Context
US-081 AC richiede verifica integrazione HIBP per password compromesse.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-081-protezione-identita-accesso/US-081.md §AC]

## Technical Specs
- **QA:** JUnit 5 + WireMock (mock API HIBP)
- **Scenari:**
  - Password nota compromessa (es. "password123") → registrazione rifiutata con messaggio user-friendly
  - Password sicura (non nel dataset) → registrazione accettata
  - HIBP API non raggiungibile → warning loggato, password ammessa (graceful degradation)
  - Solo prefix SHA-1 (5 char) inviato nella request mock

## Implementation Steps
1. Setup WireMock per mock API HIBP /range/{prefix}
2. Test password compromessa: mock response con match → rifiutata
3. Test password sicura: mock response senza match → accettata
4. Test graceful degradation: WireMock down → ammessa con warning
5. Verifica k-anonymity: solo 5 char prefix nella request

## Definition of Done
- [ ] Password compromessa → rifiutata
- [ ] Password sicura → accettata
- [ ] Graceful degradation HIBP down
- [ ] k-anonymity verificata
- [ ] Code review approvata
