# TSK-229 — BE RateLimitingFilter per login/register/password-reset

## Context
US-081 richiede rate limiting su endpoint di autenticazione per mitigare brute force e credential stuffing.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-081-protezione-identita-accesso/US-081.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §5]

## Technical Specs
- **BE:** `RateLimitingFilter` in package `security/filter`
- **Limiti configurabili** (`app.security.rate-limiting.*`):

| Endpoint | Per IP | Per account |
|---|---|---|
| POST /api/auth/login | 10 req/5 min | 5 req/5 min |
| POST /api/auth/register | 5 req/5 min | — |
| POST /api/auth/password-reset | 3 req/5 min | 3 req/5 min |

- **Response al superamento:** 429 Too Many Requests con header `Retry-After`
- **Storage:** query su tabella `login_attempts` (TSK-226)
- **Config:** valori in application.yml

## Implementation Steps
1. Creare RateLimitingFilter servlet filter
2. Implementare conteggio per IP e per account da login_attempts
3. Implementare risposta 429 con Retry-After header
4. Configurare limiti in application.yml
5. Registrare filter per gli endpoint target

## Definition of Done
- [ ] Rate limiting per IP funzionante
- [ ] Rate limiting per account funzionante
- [ ] 429 con Retry-After al superamento
- [ ] Limiti configurabili da yaml
- [ ] Code review approvata

## Dependencies
- TSK-226 (tabella login_attempts)
