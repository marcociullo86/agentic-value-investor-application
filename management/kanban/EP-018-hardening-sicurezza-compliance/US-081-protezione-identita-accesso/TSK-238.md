# TSK-238 — FE Login CAPTCHA Turnstile quando captchaRequired

## Context
US-081 AC richiede CAPTCHA dopo 10 tentativi falliti dallo stesso IP in 5 minuti. TSK-230 espone `captchaRequired: true` nella response di login; serve widget FE + verifica server-side.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-081-protezione-identita-accesso/US-081.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §5]

## Technical Specs
- **FE:** componente CAPTCHA sulla pagina `/login` (e register se applicabile)
- **Provider:** Cloudflare Turnstile (ADR-025 raccomandazione; env `NEXT_PUBLIC_TURNSTILE_SITE_KEY`)
- **UX:** se response login/register include `captchaRequired: true`, mostrare widget e richiedere token prima del submit
- **BE coordination:** inviare `captchaToken` nel body; backend verifica via API Turnstile siteverify prima di processare credenziali
- **Failure:** token assente/invalido con captchaRequired → 400 ProblemDetail

## Implementation Steps
1. Aggiungere dipendenza/widget Turnstile al form login
2. Leggere `captchaRequired` dalla response API e condizionare UI
3. Includere `captchaToken` nel payload POST login quando richiesto
4. Gestire errori CAPTCHA con messaggio user-friendly
5. Verificare che senza CAPTCHA (sotto soglia) il flusso login resta invariato

## Definition of Done
- [ ] Widget visibile solo quando `captchaRequired: true`
- [ ] Login con CAPTCHA valido accettato
- [ ] Login con captchaRequired e token assente/invalido → errore
- [ ] Flusso sotto soglia invariato
- [ ] Code review approvata

## Dependencies
- TSK-230 (BruteForceProtectionService espone captchaRequired + verifica server-side)
