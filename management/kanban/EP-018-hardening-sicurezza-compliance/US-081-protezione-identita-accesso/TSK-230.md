# TSK-230 — BE BruteForceProtectionService: lockout progressivo + CAPTCHA + cleanup

## Context
US-081 richiede progressive lockout, CAPTCHA dopo soglia e alert su nuovo device/IP.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-081-protezione-identita-accesso/US-081.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §5]

## Technical Specs
- **BE:** `BruteForceProtectionService` in package `service`
- **Progressive lockout:**

| Tentativi falliti | Azione |
|---|---|
| 1-4 | Login fallito con messaggio generico |
| 5+ (5 min, stesso account) | Ritardo progressivo 2^(n-5) sec (cap 60s) |
| 10+ (5 min, stesso IP) | Flag `captchaRequired: true` nella response |
| 20+ (15 min, stesso account) | Lockout 30 min (auto-unlock) |

- **Login attempt logging:** registra ogni tentativo in `login_attempts`
- **New device/IP detection:** confronto con ultimi 5 login → flag `newDevice=true` in SecurityEventLogger
- **Session fixation:** conferma rigenerazione session ID (refresh token rotation) post-login
- **Cleanup:** @Scheduled pulizia login_attempts > 90 giorni

## Implementation Steps
1. Creare BruteForceProtectionService con logica progressive lockout
2. Implementare logging tentativi in login_attempts
3. Implementare CAPTCHA threshold (flag nella response)
4. Implementare lockout temporaneo 30 min
5. Implementare new device/IP detection
6. Implementare @Scheduled cleanup > 90 giorni

## Definition of Done
- [ ] Progressive lockout funzionante
- [ ] CAPTCHA threshold flag
- [ ] Lockout 30 min auto-unlock
- [ ] New device/IP detection loggato
- [ ] Cleanup 90 giorni
