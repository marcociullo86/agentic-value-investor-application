# US-082 — Dichiarazione scope PCI-DSS e ADR sicurezza

## Descrizione
Come compliance officer, voglio che esista un ADR esplicito che dichiari lo scope PCI-DSS dell'applicazione (verosimilmente "non applicabile" trattandosi di un tool di screening azionario che non tratta dati di carta di pagamento), insieme alle scelte di sicurezza rilevanti (storage token, threat model baseline), affinché l'applicazione abbia una postura di compliance documentata e auditabile. [^src: wiki/concepts/fintech-security-compliance.md §5.4 — Scope PCI-DSS (condizionale)]

## Business Rules
- REQ-05 §5.4 richiede una dichiarazione esplicita dello scope PCI-DSS:
  - Se l'applicazione tratta dati di carta di pagamento: tokenization, iframe provider certificato, flusso dati carta documentato.
  - Se non applicabile: dichiararlo esplicitamente nell'ADR di sicurezza con le motivazioni.
- L'ADR consolida le scelte di sicurezza rilevanti: storage token (US-075), threat model (US-079/080/081), scope PCI-DSS.
- `pending_clarification: [Q_005]` — ADR-025 §8 dichiara PCI-DSS non applicabile (`status: proposed`); chiusura Q richiede ADR `accepted` + TSK-237 `done`. US resta `ready` (soft, non `blocked`).
[^src: wiki/concepts/fintech-security-compliance.md §5.4 — Scope PCI-DSS (condizionale)]

## Acceptance Criteria
- [ ] Esiste un ADR che dichiara esplicitamente lo scope PCI-DSS dell'applicazione con le motivazioni.
- [ ] L'ADR documenta la scelta di storage token (in-memory + httpOnly cookie).
- [ ] L'ADR documenta il threat model baseline con le mitigazioni adottate.
- [ ] L'ADR ha status `accepted` con deciders documentati.
- [ ] Nessun flusso di dati di carta di pagamento è implementato nell'applicazione (verificato via grep/search nel codebase).
