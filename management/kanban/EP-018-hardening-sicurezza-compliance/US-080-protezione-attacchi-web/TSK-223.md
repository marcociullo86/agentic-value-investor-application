# TSK-223 — BE CsrfTokenConfig per endpoint cookie-based

## Context
US-080 richiede protezione CSRF per gli endpoint che usano cookie httpOnly (coordinamento ADR-024/025).
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-080-protezione-attacchi-web/US-080.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §3]

## Technical Specs
- **BE:** `CsrfTokenConfig` in package `config`
- **Primaria:** SameSite=Strict su tutti i cookie
- **Defense-in-depth:** header `X-CSRF-Token` richiesto su:
  - `POST /api/auth/refresh`
  - `POST /api/auth/logout`
- **Implementazione:** Spring Security `CsrfTokenRepository` con cookie `XSRF-TOKEN` leggibile da JS + header validation
- **Scope:** CSRF solo per endpoint cookie-based; altri endpoint API usano Bearer header → CSRF non necessario

## Implementation Steps
1. Configurare CsrfTokenRepository cookie-based
2. Abilitare CSRF solo per /api/auth/refresh e /api/auth/logout
3. Disabilitare CSRF per gli altri endpoint API (Bearer auth)
4. Configurare SameSite=Strict su tutti i cookie

## Definition of Done
- [ ] CSRF attivo per /api/auth/refresh e /api/auth/logout
- [ ] POST senza CSRF token → 403
- [ ] SameSite=Strict su tutti i cookie
- [ ] Altri endpoint non richiedono CSRF
- [ ] Code review approvata

## Dependencies
- TSK-209 (Sprint 14 — AuthController cookie-based necessario perché CSRF ha senso solo con cookie auth)
