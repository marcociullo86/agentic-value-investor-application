# TSK-221 — BE SecurityHeadersConfig CSP header

## Context
US-080 richiede Content Security Policy rigorosa con script-src senza unsafe-inline, configurata come header HTTP.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-080-protezione-attacchi-web/US-080.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §2]

## Technical Specs
- **BE:** `SecurityHeadersConfig` in package `config`
- **CSP header HTTP** (non meta tag):
  ```
  default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:; connect-src 'self'; font-src 'self';
  frame-src 'none'; object-src 'none'; base-uri 'self'; form-action 'self'
  ```
- **script-src senza 'unsafe-inline'**
- **style-src 'unsafe-inline'** accettabile per Tailwind/Radix
- **Spring Security:** `http.headers().contentSecurityPolicy()`

## Implementation Steps
1. Creare/estendere SecurityConfig con CSP header
2. Configurare tutte le direttive CSP
3. Verificare che script-src non ha unsafe-inline
4. Verificare che l'applicazione funziona con CSP attiva

## Definition of Done
- [ ] Header CSP presente su tutte le response
- [ ] script-src senza unsafe-inline
- [ ] Applicazione funzionante con CSP
- [ ] Code review approvata

## Dependencies
Nessuna.
