# TSK-220 — QA Test defense-in-depth: 401, 403, filtro userId, payload invalido

## Context
US-079 AC richiede verifica: endpoint senza token → 401, senza permessi → 403, dati filtrati per utente, payload crafted rifiutato.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-079-defense-in-depth/US-079.md §AC]

## Technical Specs
- **QA:** JUnit 5 + REST Assured + Playwright
- **Scenari:**
  - Endpoint protetto senza token (curl diretto) → 401
  - Endpoint protetto con token utente senza permessi → 403
  - Endpoint con dati per-utente: 2 utenti concorrenti → nessun dato cross-user
  - Payload invalido (crafted) → rifiutato con errore validazione
  - Nessun calcolo critico (MoS, Graham) eseguito solo client-side (verifica grep)

## Implementation Steps
1. Test 401: curl endpoint protetto senza Authorization header
2. Test 403: curl con token utente base su rotta admin
3. Test isolamento dati: 2 utenti, verificare non vede dati altrui
4. Test payload crafted: inviare DTO con campi invalidi
5. Verifica grep: nessun calcolo finanziario client-side
