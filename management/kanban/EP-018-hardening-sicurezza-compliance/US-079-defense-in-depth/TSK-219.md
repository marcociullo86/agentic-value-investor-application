# TSK-219 — BE Audit + enforcement defense-in-depth

## Context
US-079 richiede validazione input server-side, filtro dati per permessi e nessuna business logic critica solo client-side.
[^src: management/kanban/EP-018-hardening-sicurezza-compliance/US-079-defense-in-depth/US-079.md §AC]
[^src: design_&_architecture/decisions/ADR-025-security-hardening-pci-dss.md §1]

## Technical Specs
- **BE:** Audit e fix degli endpoint esistenti
- **@Valid su tutti i @RequestBody DTO:** aggiungere Bean Validation constraints dove mancanti
- **Filtro dati per permessi:** @PreAuthorize o filtro nel service layer — ogni query filtra per userId dal SecurityContext
- **No logic critica client:** verificare che calcoli finanziari (MoS, Graham, DCF) sono esclusivamente backend
- **Endpoint protetti:** rifiutano 401 (no token) / 403 (no permessi) indipendentemente dall'header

## Implementation Steps
1. Audit tutti gli endpoint: verifica @Valid su ogni DTO
2. Aggiungere Bean Validation constraints mancanti
3. Verificare filtro per userId nei service layer con dati per-utente
4. Verificare che nessun calcolo critico è solo client-side
5. Verificare 401/403 su endpoint protetti con curl diretto

## Definition of Done
- [ ] @Valid su tutti i DTO endpoint
- [ ] Filtro userId nei service con dati per-utente
- [ ] Nessun calcolo critico solo client
- [ ] 401/403 su endpoint protetti
- [ ] Code review approvata

## Dependencies
Nessuna — audit su codice esistente.
