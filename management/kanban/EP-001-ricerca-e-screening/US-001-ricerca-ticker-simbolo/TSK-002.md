# TSK-002 — SearchController + SearchService: GET /api/search e GET /api/search/{ticker}

## Obiettivo

Implementare gli endpoint di ricerca ticker descritti nel contratto OpenAPI.

## Scope tecnico

- `SearchController` con:
  - `GET /api/search?query={q}` → chiama `SearchService.search(query)` → ritorna
    `SearchResultList`.
    [^src: design_&_architecture/api/openapi.yaml §/api/search]
  - `GET /api/search/{ticker}` → `SearchService.validateTicker(ticker)` → 200/404
    strutturato.
    [^src: design_&_architecture/api/openapi.yaml §/api/search/{ticker}]
- `SearchService`: normalizza query in uppercase, delegaThen a `FmpAdapter.searchSymbol()` e
  `FmpAdapter.getProfile()`.
  [^src: design_&_architecture/components/backend-components.md §SearchService]
- `FmpAdapter` / `FmpAdapterRestClient`: metodi `searchSymbol(query)` e `getProfile(ticker)`.
  [^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Adapter pattern]
- DTO di risposta: `StockProfile`, `SearchResultItem`, `SearchResultList` aderenti agli
  schemas OpenAPI.
  [^src: design_&_architecture/api/openapi.yaml §components/schemas]
- Gestione 404 tramite `GlobalExceptionHandler` → ProblemDetails (RFC 9457).
  [^src: design_&_architecture/decisions/ADR-007-api-contract.md]

## Vincoli e note

- Input normalizzato a uppercase PRIMA della chiamata FMP (US-001 AC).
- Il ticker non trovato produce 404 strutturato, non eccezione non gestita.
- `FmpAdapter` utilizza `FmpCacheService` per profilo (TSK dipende da TSK-010 per la cache layer).

## Criteri di completamento (DoD)

- [ ] `GET /api/search?query=AAPL` ritorna lista non vuota per ticker esistente.
- [ ] `GET /api/search/{ticker}` con ticker esistente → 200; con ticker inesistente → 404
  ProblemDetails.
- [ ] Input `aapl` normalizzato a `AAPL` prima della FMP call.
- [ ] Unit test `SearchServiceTest` con `FmpAdapter` mockato (fixture).
