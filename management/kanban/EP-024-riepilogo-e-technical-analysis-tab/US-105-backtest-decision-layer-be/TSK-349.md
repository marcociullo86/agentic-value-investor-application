# TSK-349 — QA BacktestEngine

## Obiettivo

Coprire i rischi critici del motore di backtest: correttezza della disciplina point-in-time (nessun look-ahead), idempotenza del risultato, gestione di `INSUFFICIENT_HISTORY`, correttezza di `timingEdgePct`, e scenari rappresentativi incluso lo scenario stile-COPART (il caso motivante dell'intera epica).

## Scope

### Test point-in-time no look-ahead (AC critico)
- Fixture con filing artificiale con `acceptedDate = t + 1 month`: verificare che il gate VI a `t` NON usi quel filing.
- Fixture EOD con barre artificiali nel futuro rispetto a `t`: verificare che gli indicatori TA a `t` NON usino quelle barre.
- Test parametrico su almeno 3 date `t` distinte nella stessa finestra.

### Test idempotenza
- Stesso input `(ticker, years, horizonMonths)` → stesso output `BacktestResultDto` in due chiamate consecutive (incluso ordine dei trade, metriche aggregate, `timingEdgePct`).

### Test INSUFFICIENT_HISTORY
- Ticker con storico simulato insufficiente (IPO recente, < `horizonMonths + 1` mese): risposta `status: INSUFFICIENT_HISTORY` con `insufficientHistoryReason`, senza trade né metriche parziali.
- Ticker con storico sufficiente ma finestra `years` troppo lunga: `INSUFFICIENT_HISTORY` su anni non coperti da FMP.

### Test round-trip causale uscita
- Trade che scade per `VI_TARGET`: `exitReason = VI_TARGET`, `exitPrice ≥ dcfIntrinsicValue`.
- Trade che scade per `STOP_HIT`: `exitReason = STOP_HIT`, `exitPrice ≤ stopPrice`.
- Trade che scade per `HORIZON`: `exitReason = HORIZON` al raggiungimento dell'orizzonte.

### Test timingEdge
- Fixture con `EP024_ENTER_NOW` avgReturnPct > `VI_ONLY` avgReturnPct + 2%: `timingEdge = POSITIVE_EDGE`.
- Fixture con `EP024_ENTER_NOW` avgReturnPct < `VI_ONLY` avgReturnPct - 2%: `timingEdge = NEGATIVE_EDGE`.
- Fixture con 0 segnali ENTER_NOW: `trades = 0`, `noSignalsInPeriod: true`, baseline calcolate, `timingEdge = NEUTRAL`.

### Scenario stile-COPART (VI-positivo ma timing sfavorevole)
- Fixture: ticker VI-positivo con TA che produce `WAIT_FOR_SETUP` per la maggior parte della finestra; solo pochi punti `ENTER_NOW`.
- Verificare che `EP024_ENTER_NOW` abbia meno trade ma `avgReturnPct` migliore di `VI_ONLY` (il timing filtra gli ingressi peggiori).

### Contract drift
- Test OpenAPI drift su schema `BacktestResultDto` + enum `ExitReason`, `TimingEdgeLabel`, `BacktestStrategy`, `BacktestStatus`.

## Acceptance Criteria
- [ ] Test no look-ahead: filing con `acceptedDate > t` escluso dal gate VI a `t` — `passed`.
- [ ] Test no look-ahead: EOD future rispetto a `t` escluse dal calcolo TA — `passed`.
- [ ] Test idempotenza: stesso input → stesso output — `passed`.
- [ ] Test `INSUFFICIENT_HISTORY`: storico insufficiente → `status: INSUFFICIENT_HISTORY` senza dati parziali — `passed`.
- [ ] Test causale uscita: `VI_TARGET`, `STOP_HIT`, `HORIZON` ciascuno testato — `passed`.
- [ ] Test `timingEdge`: `POSITIVE_EDGE`, `NEGATIVE_EDGE`, caso 0 segnali — tutti `passed`.
- [ ] Scenario CPRT-style: EP024 meno trade ma `avgReturnPct` > VI_ONLY — `passed`.
- [ ] Contract drift OpenAPI `BacktestResultDto` — `passed`.
