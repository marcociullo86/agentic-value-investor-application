# TSK-347 — BacktestEngine: round-trip entry→exit + metriche 3 strategie + timingEdge

## Obiettivo

Implementare la simulazione del round-trip (apertura → chiusura del trade) e il calcolo delle metriche aggregate per le 3 strategie (`EP024_ENTER_NOW`, `VI_ONLY`, `BUY_AND_HOLD`), producendo il campo `timingEdgePct` che è il cuore della verifica: il layer di timing TA ha davvero aggiunto soldi?

## Scope

### Simulazione round-trip per strategia EP024_ENTER_NOW
- Per ogni data `t` con verdetto `ENTER_NOW` (prodotto da TSK-346): aprire un trade simulato al prezzo EOD di `t`.
- Chiusura alla **prima** condizione verificata (in ordine di priorità):
  1. `VI_TARGET` — prezzo EOD ≥ `dcfIntrinsicValue` calcolato a `t` (la MoS si è chiusa).
  2. `STOP_HIT` — prezzo EOD ≤ `stopSuggestion.stopPrice` dell'advisor US-100 calcolato a `t`.
  3. `HORIZON` — raggiunto `horizonMonths` senza target né stop.
- Output per trade: `entryPrice`, `exitPrice`, `exitReason` (`VI_TARGET | STOP_HIT | HORIZON`), `returnPct`, `holdingDays`, `maxIntraTradeDrawdownPct`.
- Vincolo di non-sovrapposizione: se un trade è aperto, i segnali `ENTER_NOW` successivi non aprono nuovi trade (evitare piramiding artificioso).

### Strategia baseline B1 — VI_ONLY
- Per ogni data `t` in cui il gate VI (solo fondamentali, ignorando il verdetto TA) è positivo: aprire un trade con le stesse regole di uscita (VI_TARGET / STOP_HIT / HORIZON).
- Nessun filtro TA sul timing: risponde alla domanda "comprare appena era a sconto era sufficiente?"

### Strategia baseline B2 — BUY_AND_HOLD
- Trade unico: compra al prezzo EOD del primo giorno della finestra, vendi all'ultimo giorno.
- `totalReturnPct` semplice; nessuna regola di uscita intermedia.

### Metriche aggregate `summary` per strategia
Per `EP024_ENTER_NOW` e `VI_ONLY`:
- `trades`, `winRate`, `avgReturnPct`, `medianReturnPct`, `avgHoldingDays`, `avgRealizedRewardRisk`, `totalReturnPct` (round-trip composti), `maxTradeDrawdownPct`, `exitBreakdown` (`{VI_TARGET, STOP_HIT, HORIZON}`).

Per `BUY_AND_HOLD`: solo `totalReturnPct` e periodo.

### Campo timingEdge
- `timingEdgePct` = `avgReturnPct(EP024_ENTER_NOW) − avgReturnPct(VI_ONLY)`.
- Etichetta `POSITIVE_EDGE` se `timingEdgePct > +2%`, `NEGATIVE_EDGE` se < -2%, `NEUTRAL` altrimenti (soglie configurabili via property).
- Caso 0 segnali `ENTER_NOW` in finestra: `trades = 0`, `winRate = null`, `timingEdge = NEUTRAL` con nota `noSignalsInPeriod: true`.

### Blocco caveats (sempre presente)
- `lookAheadResidual`: fondamentali FMP ristrutturati.
- `singleTicker: true`.
- `notPortfolioPerformance: true`.

## Acceptance Criteria
- [ ] Round-trip chiude alla prima condizione (`VI_TARGET` / `STOP_HIT` / `HORIZON`) con causale esposta.
- [ ] Non-sovrapposizione trade: nessun piramiding artificioso.
- [ ] Metriche `summary` calcolate per le 3 strategie con tutti i campi US-105 §"Metriche aggregate".
- [ ] `timingEdgePct` = `avgReturnPct(EP024) − avgReturnPct(VI_ONLY)` con etichetta `POSITIVE/NEUTRAL/NEGATIVE_EDGE`.
- [ ] Caso 0 segnali gestito: `trades = 0`, `noSignalsInPeriod: true`, baseline comunque calcolate.
- [ ] Blocco `caveats` sempre presente nel payload (`lookAheadResidual`, `singleTicker`, `notPortfolioPerformance`).
- [ ] Calcolo pure-function Kotlin, nessuna call LLM, nessuna scrittura DB per `equity`.
