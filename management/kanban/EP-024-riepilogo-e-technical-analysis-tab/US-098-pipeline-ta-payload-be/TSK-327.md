# TSK-327 — QA pipeline TA base (US-098)

## Obiettivo
Coprire l'endpoint `/technical` con integration test su 3 fixture rappresentative, contract test OpenAPI drift, e test di non-regressione che garantiscano l'invarianza del rule engine `/api/analysis/{ticker}`.

## Scope

### Integration test BE
- Fixture in `src/backend/src/test/resources/fixtures/`:
  - **AAPL** — uptrend tipico → `trend.classification = UPTREND`, blocchi momentum/levels/priceContext valorizzati.
  - **Titolo downtrend conclamato** → `trend.classification = DOWNTREND`.
  - **Storico corto (< 200 sedute)** → `trend.classification = INDETERMINATE`, `confidenceReduced = true`.
- Asserzioni esplicite sui valori dei 6 blocchi e sui flag.

### Contract test
- Drift OpenAPI sullo schema `TechnicalAnalysisResponse` + sotto-schemi 6 blocchi (pattern EP-002 TSK-037).
- Verifica che la response generata corrisponda allo schema documentato.

### Non-regressione
- Test esistenti su `/api/analysis/{ticker}` (rule engine + `contextFlags` EP-013) continuano a passare; nessuna chiamata FMP aggiuntiva nel flusso rule engine.

## Acceptance Criteria
- [ ] Integration test su 3 fixture (AAPL uptrend, downtrend conclamato, storico corto) con asserzioni esplicite su trend/blocchi.
- [ ] Caso storico corto verifica `INDETERMINATE` + `confidenceReduced = true`.
- [ ] Contract test OpenAPI drift su `TechnicalAnalysisResponse` `passed`.
- [ ] Non-regressione `/api/analysis/{ticker}` (rule engine + contextFlags EP-013 invariati) `passed`.
- [ ] Verifica assenza di nuove chiamate FMP nel flusso rule engine.
