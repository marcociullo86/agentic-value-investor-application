# US-102 — QA Pipeline Technical Analysis: contract + integration + E2E

## Descrizione

Come QA engineer, voglio coprire l'intera pipeline Technical Analysis (US-098 BE payload + US-099 entry-timing + US-100 stop-sizing + US-101 FE tab) con contract test OpenAPI drift, integration test BE su fixture rappresentative (uptrend tipico, downtrend conclamato, scenario stile-COPART), e smoke E2E Playwright sulla navigazione utente, affinche il rilascio della Fase 1 di EP-024 abbia evidenza di non-regressione e coerenza con le regole documentate. [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Il caso motivante: COPART"]

## Business Rules

### Contract test

- Riuso pattern EP-002 TSK-037 / EP-010 TSK-291 / EP-019 (CQRL): contract test drift sul nuovo schema OpenAPI `TechnicalAnalysisResponse` (US-098), `EntryTimingAdvisor` (US-099), `StopSuggestion` e `PositionSizing` (US-100).
- Verifica enum tipati: `EntryTimingVerdict`, `ReentryConditionCode`, `StopType`, `RewardRiskLabel`, `TrendClassification`, `SupportType`.
- Verifica che l'endpoint `/api/analysis/{ticker}/technical` sia documentato e che la response generata corrisponda allo schema.

### Integration test BE

Fixture richieste, archiviate in `src/backend/src/test/resources/fixtures/`:

| Fixture | Profilo atteso | Verifica chiave |
|---|---|---|
| AAPL — uptrend tipico | `UPTREND` + RSI Neutral + MACD rialzista | `entryTiming = ENTRY_FAVORABLE` o `ENTRY_NEUTRAL`; stop `SUPPORT_BASED`; reward/risk >= 2 |
| CPRT — scenario stile-COPART (uptrend ma RSI overbought con MACD flat) | `UPTREND` + RSI Overbought + MACD flat | `entryTiming = WAIT` con `reentryCondition.code = RSI_BELOW_50`; **questo e' il test-anchor della motivazione dell'epica** |
| Generic — titolo in downtrend conclamato | `DOWNTREND` | `entryTiming = ENTRY_UNFAVORABLE` |
| Generic — storico corto (<200 sedute) | `INDETERMINATE` | `confidenceReduced = true`; `entryTiming = INDETERMINATE` |
| Generic — stop NOT_CALCULABLE (no support, no SMA200 sotto, no ATR) | mixed | `stopSuggestion = NOT_CALCULABLE` |

### E2E Playwright (mocked-tier coerente con EP-016/EP-018)

- Test 1 — happy path uptrend: utente apre `/analysis?ticker=AAPL`, clicca tab "Technical Analysis", vede verdetto + chart + pannelli; nessun errore console.
- Test 2 — scenario stile-COPART: fixture CPRT → tab Technical Analysis mostra verdetto `WAIT` evidenziato + banner condizione re-entry visibile + disclaimer "advisory" presente.
- Test 3 — input equity nel position sizing: utente modifica equity, vede ricalcolo shares + warning `POSITION_EXCEEDS_EQUITY` quando applicabile.
- Test 4 — lazy load: navigando direttamente a `/analysis?ticker=AAPL`, nessuna chiamata a `/technical` finche il tab non viene cliccato (verifica via network interception).
- Test 5 — a11y smoke: keyboard navigation sul tab + chart accessibile via tabella alternativa.

### Non-regressione

- Tutti i test esistenti su `/api/analysis/{ticker}` (rule engine + contextFlags EP-013) continuano a passare.
- Tab Analisi Base e tab Deep Analysis invariati nel rendering (snapshot test FE).

### CQRL coverage

- Coerente con il ruleset canonical di EP-019: tutti i TSK derivati da US-098..US-101 hanno copertura CQRL. I TSK QA di questa US sono i naturali consumatori dei task BE/FE.

## Acceptance Criteria

- [ ] Contract test OpenAPI drift sul nuovo schema `TechnicalAnalysisResponse` (+ sub-schema) passa in CI.
- [ ] Integration test BE su 5 fixture (AAPL uptrend, CPRT stile-COPART, downtrend, storico corto, stop NOT_CALCULABLE) passano con asserzioni esplicite sul verdetto atteso.
- [ ] Test stile-COPART (CPRT) verifica esplicitamente: `entryTiming = WAIT`, `reentryCondition.code = RSI_BELOW_50`, presenza di citazioni wiki TA nel rationale.
- [ ] E2E Playwright copre i 5 scenari elencati; tutti `passed` in CI.
- [ ] Lazy load del tab `/technical` verificato via network test (no chiamata se tab non cliccato).
- [ ] Lighthouse a11y >= 95 e axe-core zero serious/critical sul tab Technical Analysis.
- [ ] Test di non-regressione sul tab Analisi Base e Deep Analysis `passed` (snapshot Vitest + Playwright).
- [ ] Tutti i test integrazione + E2E sono deterministici (no flake; pattern dello Sprint 15.5 hotfix di EP-016 rispettato).
- [ ] CQRL review `passed` sui task QA derivati.
