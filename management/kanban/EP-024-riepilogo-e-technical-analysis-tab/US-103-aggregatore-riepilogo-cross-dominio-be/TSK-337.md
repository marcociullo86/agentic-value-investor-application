# TSK-337 — Corpus WIKI in pgvector + indicizzazione

## Obiettivo
Estendere il vector store pgvector di EP-011 con un secondo corpus WIKI tramite colonna discriminante `corpus_kind`, indicizzare le pagine wiki dei due domini come corpus WIKI ed esporre un endpoint admin di reindex idempotente, senza regredire la similarity search sui filing (ADR-030 §2).

## Scope

### Migration Flyway additiva
- Colonna `corpus_kind` (enum `FILING | WIKI`, default `FILING`, backfill `FILING` per i record esistenti) sulla tabella chunk pgvector di EP-011. Un solo indice HNSW, una sola pipeline di similarity search.

### WikiCorpusIndexer
- Chunka + embedda (sidecar arctic-embed-l-v2 EP-011) le pagine in `wiki/concepts/` e `wiki/syntheses/` con frontmatter `domain ∈ {value-investing, technical-analysis-trading}`, salvandole come `corpus_kind = WIKI`.

### Endpoint admin reindex
- Endpoint amministrativo **triggered** (non al boot dell'app), idempotente per la chiave `(corpus_kind, source_id, chunk_index)`.

### Non-regressione
- Regression test che la similarity search sui filing (`corpus_kind = FILING`) resti invariata dopo la migration.

## Acceptance Criteria
- [ ] Migration Flyway additiva aggiunge `corpus_kind` (FILING/WIKI, default FILING) con backfill dei record esistenti.
- [ ] `WikiCorpusIndexer` indicizza le pagine `wiki/concepts/` + `wiki/syntheses/` con domain ∈ {value-investing, technical-analysis-trading} come corpus WIKI.
- [ ] Endpoint admin reindex triggered e idempotente per `(corpus_kind, source_id, chunk_index)`.
- [ ] Regression test: similarity search sui filing invariata post-migration.
