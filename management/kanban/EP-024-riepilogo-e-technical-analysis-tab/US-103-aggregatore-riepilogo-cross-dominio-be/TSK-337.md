# TSK-337 — Corpus WIKI in pgvector + indicizzazione

> **Completato (2026-06-08):** migration `V033` consegnata e validata (7 asserzioni verdi su Postgres pgvector pg17) + parte BE: `FilingChunkEntity`/`FilingChunkRepository` adeguati al multi-corpus, `WikiCorpusIndexer` (chunk+embed Qwen3-0.6B delle pagine wiki VI+TA come corpus WIKI, idempotente delete+upsert), endpoint admin triggered `POST /admin/rag/wiki/reindex` (hasRole ADMIN). `gradle compileKotlin` SUCCESSFUL. Accesso runtime a `wiki/` risolto via property `rag.wiki.corpus-path` + gap `be-wiki-runtime-corpus-mount` (mount/COPY a carico di infra). Regression/idempotency test → TSK-341 (QA). Vedi `wiki/log.md` 2026-06-08.

## Obiettivo
Estendere il vector store pgvector di EP-011 con un secondo corpus WIKI tramite colonna discriminante `corpus_kind`, indicizzare le pagine wiki dei due domini come corpus WIKI ed esporre un endpoint admin di reindex idempotente, senza regredire la similarity search sui filing (ADR-030 §2).

## Scope

### Migration Flyway additiva `V033` (su tabella reale `filing_chunks`, ADR-030 §2)
Schema reale verificato (V014): `filing_chunks` ha `filing_blob_id BIGINT NOT NULL REFERENCES filing_blob(id) ON DELETE CASCADE`, unicità `uq_filing_chunks_blob_chunk UNIQUE (filing_blob_id, chunk_index)`, `embedding vector(1024)`, indice HNSW `idx_filing_chunks_hnsw`. **NON esiste colonna `source_id`.** La migration `V033` deve:
1. aggiungere `corpus_kind VARCHAR(10) NOT NULL DEFAULT 'FILING'` (backfill banale dal default per i record esistenti);
2. rendere `filing_blob_id` **nullable** (i record WIKI hanno `filing_blob_id IS NULL`);
3. aggiungere `wiki_source_id VARCHAR(255) NULL` (slug/path pagina, es. `ta-vs-vi-decision-layer`) + `wiki_domain VARCHAR(40) NULL`;
4. mantenere `uq_filing_chunks_blob_chunk` per i FILING e aggiungere il partial unique index `CREATE UNIQUE INDEX uq_wiki_chunks ON filing_chunks (wiki_source_id, chunk_index) WHERE corpus_kind = 'WIKI'`.

Un solo indice HNSW e una sola pipeline di similarity search per entrambi i corpus. DDL puntuale a carico del db-dev; qui sono fissati nomi reali e invarianti.

### WikiCorpusIndexer
- Chunka + embedda (modello reale **Qwen3-Embedding-0.6B** 1024-dim via sidecar EP-011, ADR-018; arctic = fallback) le pagine in `wiki/concepts/` e `wiki/syntheses/` con frontmatter `domain ∈ {value-investing, technical-analysis-trading}`, salvandole con `corpus_kind = WIKI`, `wiki_source_id`, `wiki_domain`, `filing_blob_id = NULL`.

### Endpoint admin reindex
- Endpoint amministrativo **triggered** (non al boot dell'app), idempotente per la chiave WIKI `(corpus_kind=WIKI, wiki_source_id, chunk_index)`.

### Non-regressione
- Regression test che la similarity search sui filing (`corpus_kind = FILING`) resti invariata dopo la migration.

## Acceptance Criteria
- [ ] Migration `V033` additiva aggiunge `corpus_kind` (default FILING + backfill), rende `filing_blob_id` nullable, aggiunge `wiki_source_id`/`wiki_domain` e il partial unique index WIKI; nessuna colonna `source_id`.
- [ ] `WikiCorpusIndexer` indicizza le pagine `wiki/concepts/` + `wiki/syntheses/` con domain ∈ {value-investing, technical-analysis-trading} come corpus WIKI (embedding Qwen3 1024-dim).
- [ ] Endpoint admin reindex triggered e idempotente per `(corpus_kind=WIKI, wiki_source_id, chunk_index)`.
- [ ] Regression test: similarity search sui filing invariata post-migration.
