# TSK-341 — QA SummaryService

## Obiettivo
Verificare il mapping deterministico del Riepilogo (≥10 casi incl. test-anchor), l'invarianza del verdetto rispetto al prompt LLM, il caching, il caso NOT_INDEXED e il contract drift.

## Scope

### Unit test mapping (≥10 casi)
- Tutte le righe della tabella di mapping, incl.:
  - VI-RED + TA-FAVORABLE → `AVOID` (la TA non promuove VI-negativo).
  - VI-GREEN + Munger RISCHIO_ESTREMO → `AVOID` (override Munger).
  - VI-GREEN + TA-WAIT → `WAIT_FOR_SETUP` con `warningAntiCopart` non vuoto **(test-anchor della motivazione dell'epica)**.

### Invarianza LLM
- Test che, cambiando solo il testo del prompt mantenendo gli input strutturati, il `summaryVerdict` resti invariato.

### Integration
- Cache hit: seconda chiamata con stessi snapshot servita da cache.
- `deepAnalysisStatus = NOT_INDEXED`: Summary funzionante con `deepVerdict = null`.
- Contract drift OpenAPI `SummaryVerdictResponse` + enum.

## Acceptance Criteria
- [ ] Unit mapping ≥10 casi `passed`, inclusi VI-RED+TA-FAVORABLE→AVOID, VI-GREEN+RISCHIO_ESTREMO→AVOID, VI-GREEN+TA-WAIT→WAIT_FOR_SETUP con warningAntiCopart.
- [ ] Test invarianza LLM: prompt diverso, verdetto invariato.
- [ ] Integration cache hit `passed`.
- [ ] Caso `deepAnalysisStatus = NOT_INDEXED` funzionante con `deepVerdict = null`.
- [ ] Contract drift `passed`.
