# US-100 — Stop-placement + position-sizing advisor 2%/6% Rule (BE)

## Descrizione

Come investitore value che ha gia identificato un titolo VI-positivo con timing favorevole, voglio che il backend mi suggerisca **dove mettere lo stop** in modo strutturalmente ancorato (Murphy: sotto support / sotto SMA200 / ATR-based) e **quanto investire** secondo la 2% Rule e la 6% Rule di Elder, affinche uno stop colpito non distrugga la tesi fondamentale ne il portafoglio. Il caso COPART documenta empiricamente che uno stop arbitrario a percentuale fissa puo essere colpito dal noise e chiudere prematuramente una tesi VI corretta. [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Il caso motivante: COPART"] [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Principio 1: lo stop risponde alla struttura, non alla percentuale"] [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Principio 2: la distanza dello stop determina la size (2% Rule)"]

## Business Rules

### Stop suggerito (output `stopSuggestion`)

Il servizio calcola **3 candidati** di stop e ritorna il primo applicabile in ordine di priorita (strutturale > tecnico-medio > volatility-based):

1. **`SUPPORT_BASED`** — sotto il support piu' vicino sotto il prezzo corrente (da US-098 `levels.support[0]`), con buffer di 0.5% sotto il livello per evitare il noise. Citazione Murphy §Page 82. [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Stop sotto il support (per i long)"]
2. **`SMA200_BASED`** — sotto la SMA200, con buffer 0.5%. Applicabile solo se prezzo > SMA200 (in `UPTREND`/`SIDEWAYS` con prezzo sopra trend). [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Livelli di support utilizzabili per lo stop"]
3. **`ATR_BASED`** — `currentPrice − 2 × ATR14`, fallback quando supporti non identificati e SMA200 non applicabile. Citazione Elder ATR-based stop. [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"Stop ATR-based come fallback"]

Output `stopSuggestion`:

```
{
  "type": "SUPPORT_BASED" | "SMA200_BASED" | "ATR_BASED",
  "stopPrice": 47.20,
  "stopDistance": 0.80,        // currentPrice - stopPrice
  "stopDistancePct": 1.67,     // % del prezzo
  "anchorReference": "support@$47.5 (SWING_LOW)" | "SMA200@$45.0" | "ATR14=$0.45",
  "rationale": "Stop ancorato al support strutturale piu' vicino con buffer 0.5% (Murphy §Page 82)"
}
```

Edge case: se nessuno dei 3 candidati e' calcolabile (es. ATR mancante + no support + prezzo sotto SMA200), `stopSuggestion = NOT_CALCULABLE` con rationale esplicito.

### Position sizing 2% Rule (output `positionSizing.twoPercentRule`)

Formula canonica Elder §50: [^src: wiki/syntheses/ta-stop-placement-position-sizing.md §"La formula"]

```
maxRisk = equity × 0.02
shares  = floor(maxRisk / stopDistance)
positionValue = shares × currentPrice
positionPctEquity = positionValue / equity
```

**Input `equity`**: parametro di query `?equity=50000` (default ragionevole se assente: 50000 USD, documentato e configurabile). Mai persistito lato BE.

Output:

```
{
  "equity": 50000,
  "maxRiskAllowed": 1000.00,    // 2% di equity
  "stopDistance": 0.80,
  "sharesRecommended": 1250,
  "positionValueRecommended": 60000.00,
  "positionPctEquity": 1.20,
  "warning": "POSITION_EXCEEDS_EQUITY"  // se positionValue > equity: stop troppo stretto, posizione enorme
}
```

Quando `positionValue > equity` (stop molto stretto), il sistema NON propone shares oltre `equity / currentPrice` e flagga `warning = POSITION_EXCEEDS_EQUITY` con suggerimento testuale.

### 6% Rule heat di portafoglio (output `positionSizing.sixPercentRule`)

Citazione Elder §51 "Iron Triangle": [^src: wiki/concepts/elder-risk-management-2pct-6pct.md]

```
maxAggregateRisk = equity × 0.06    // soma rischi di tutti i trade aperti
```

Output: campo `maxAggregateRiskPerMonth = 0.06 × equity` ed esplicito disclaimer: "Questo singolo trade impegna `positionRiskUsd` su un budget mensile di `maxAggregateRiskPerMonth`. Conferma di non superare 6% su tutti i trade aperti."

**Nota di scope**: il BE **non** tiene traccia delle altre posizioni dell'utente (non lo sa); espone solo il calcolo del singolo trade. La gestione del budget aggregato resta responsabilita dell'utente. Decisione esplicita per non confondere lo scope con un portfolio tracker.

### Rapporto Reward/Risk vs DCF intrinsic value (output `rewardRiskRatio`)

Riusa `dcfIntrinsicValue` da `/api/analysis/{ticker}` (gia esposto, EP-007). Calcolo:

```
upside = dcfIntrinsicValue - currentPrice    // positivo se VI-positivo
downside = stopDistance
rewardRiskRatio = upside / downside
```

Indicazione testuale:

- `rewardRiskRatio >= 3` → "Eccellente: 3:1 o superiore" (Elder §54 raccomanda minimo 2:1).
- `rewardRiskRatio >= 2` → "Accettabile".
- `rewardRiskRatio >= 1` → "Marginale, valutare se aspettare prezzo migliore".
- `rewardRiskRatio < 1` → "Sfavorevole: stop piu' lontano dell'upside fondamentale residuo".
- `dcfIntrinsicValue` assente o `<= currentPrice` → `NOT_APPLICABLE` con rationale.

### Separazione di responsabilita

- Lo `stopSuggestion` e' calcolato in pure-function Kotlin, no LLM.
- Il position sizing e' calcolato in pure-function Kotlin, no LLM.
- Nessuna persistenza dell'`equity` lato BE.
- Allineamento EP-021: se done, output tipato sealed; altrimenti pattern legacy con nota refactor.

## Acceptance Criteria

- [ ] Esiste output `stopSuggestion` nel `TechnicalAnalysisResponse` (esteso da US-098) o su endpoint dedicato, con campi `type`, `stopPrice`, `stopDistance`, `stopDistancePct`, `anchorReference`, `rationale`.
- [ ] Su ticker con support identificato e prezzo > support: `stopSuggestion.type = SUPPORT_BASED`.
- [ ] Su ticker senza support utile ma prezzo > SMA200: `stopSuggestion.type = SMA200_BASED`.
- [ ] Su ticker senza support e prezzo < SMA200 ma ATR disponibile: `stopSuggestion.type = ATR_BASED`.
- [ ] Su edge case (no support, no SMA200 applicabile, no ATR): `stopSuggestion = NOT_CALCULABLE` con rationale esplicito.
- [ ] `positionSizing.twoPercentRule` calcola `sharesRecommended`, `positionValueRecommended`, `positionPctEquity` con la formula Elder dato `equity` da query param.
- [ ] Flag `warning = POSITION_EXCEEDS_EQUITY` quando `positionValueRecommended > equity` (stop molto stretto).
- [ ] `positionSizing.sixPercentRule.maxAggregateRiskPerMonth = 0.06 × equity` esposto con disclaimer testuale.
- [ ] `rewardRiskRatio` calcolato vs `dcfIntrinsicValue` letto da `/api/analysis/{ticker}` con etichette `EXCELLENT/ACCEPTABLE/MARGINAL/UNFAVORABLE/NOT_APPLICABLE`.
- [ ] Equity mai persistita server-side (verificato con test che ispeziona l'assenza di scritture DB).
- [ ] Test unitari coprono almeno 6 scenari: support-based normale, support-based con buffer, SMA200-based, ATR-based, NOT_CALCULABLE, POSITION_EXCEEDS_EQUITY.
- [ ] Schema OpenAPI aggiornato con enum tipati per `stopSuggestion.type` e `rewardRiskRatio.label`.
- [ ] Javadoc/kdoc cita esplicitamente [[ta-stop-placement-position-sizing]] e [[elder-risk-management-2pct-6pct]].
