# TSK-029 — WatchlistController: CRUD watchlist utente

## Obiettivo

Implementare gli endpoint di gestione watchlist personale.

## Scope tecnico

- `WatchlistController`:
  - `GET /api/watchlist` (auth): ritorna watchlist default con `items[]`.
    [^src: design_&_architecture/api/openapi.yaml §/api/watchlist GET]
  - `POST /api/watchlist/items` (auth): body `{ticker}`, idempotente (200 se già presente).
    [^src: design_&_architecture/api/openapi.yaml §/api/watchlist/items POST]
  - `DELETE /api/watchlist/items/{ticker}` (auth): 204 se rimosso, 404 se non in watchlist.
    [^src: design_&_architecture/api/openapi.yaml §/api/watchlist/items DELETE]
- `WatchlistService`:
  - `getWatchlist(userId)`: recupera watchlist default o la crea on-first-access (is_default=true).
  - `addTicker(userId, ticker)`: upsert `watchlist_items`, upsert `stocks` row se non esiste.
  - `removeTicker(userId, ticker)`: delete `watchlist_items` entry.
  [^src: design_&_architecture/components/backend-components.md §WatchlistService]
- Auth: endpoint tutti gated, 401 senza token.
  [^src: design_&_architecture/decisions/ADR-006-authentication.md §Endpoint policy]
- `watchlist_items` → unique `(watchlist_id, ticker)` gestisce idempotenza.
  [^src: design_&_architecture/data/er-diagram.md §watchlist_items]

## Criteri di completamento (DoD)

- [ ] `POST /api/watchlist/items` due volte stesso ticker → 200 entrambe, una sola row in DB.
- [ ] `DELETE /api/watchlist/items/AAPL` → 204; seconda DELETE → 404.
- [ ] `GET /api/watchlist` → lista con ticker aggiunti.
- [ ] Watchlist persiste tra sessioni (verificato con nuovo token per stesso user).
- [ ] Integration test con Testcontainers.
