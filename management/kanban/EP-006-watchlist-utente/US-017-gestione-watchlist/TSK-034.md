# TSK-034 — Login, Register pages e useAuthStore

## Obiettivo

Implementare le pagine di autenticazione e lo store Zustand per la gestione del token.

## Scope tecnico

- `app/(auth)/login/page.tsx`: form email + password, submit → `POST /api/auth/login`.
  [^src: design_&_architecture/components/frontend-components.md §app/(auth)/login]
- `app/(auth)/register/page.tsx`: form email + password + displayName.
- `lib/store/useAuthStore.ts`:
  - `accessToken: string | null` in memoria (non localStorage).
  - `login(email, password)`: chiama backend, salva `accessToken`, refresh in `httpOnly`
    cookie (gestito automaticamente da browser se risposta usa `Set-Cookie`).
  - `logout()`: chiama `POST /api/auth/logout`, azzera `accessToken`.
  - `refresh()`: chiama `POST /api/auth/refresh` con cookie.
    [^src: design_&_architecture/components/frontend-components.md §useAuthStore]
  - ADR-006: access token in memoria, refresh in httpOnly cookie.
    [^src: design_&_architecture/decisions/ADR-006-authentication.md §Conseguenze §Frontend]
- `client.ts` interceptor 401: chiama `refresh()`, poi riprova; se fallisce → `logout()`.
- Navbar: mostra user display name se autenticato, link login/logout.

## Criteri di completamento (DoD)

- [ ] Login con credenziali valide → `accessToken` in store, navigazione post-login.
- [ ] Token scaduto → interceptor esegue refresh silenzioso.
- [ ] Logout → store pulito, redirect a `/`.
- [ ] `accessToken` non persiste a localStorage (reload pagina → necessario re-login o
  refresh automatico).
- [ ] Unit test `useAuthStore`: login, logout, stato iniziale.
