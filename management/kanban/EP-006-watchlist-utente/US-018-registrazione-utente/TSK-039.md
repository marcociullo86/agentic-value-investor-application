# TSK-039 — GlobalExceptionHandler: 409 Conflict per email duplicata

## Context

US-018 AC#2 richiede che la registrazione con email già esistente venga rifiutata con messaggio chiaro. ADR-010 formalizza il mapping HTTP: `EmailAlreadyRegisteredException` → `409 Conflict` con Problem Details `type=https://api/errors/email-already-registered`. L'implementazione Sprint 3 (TSK-033) gestisce il vincolo UNIQUE a livello DB ma non ha ancora un `GlobalExceptionHandler` dedicato che emetta il formato RFC 9457 corretto.
[^src: management/kanban/EP-006-watchlist-utente/US-018-registrazione-utente/US-018.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-010-auth-consolidation.md §1. Registrazione (US-018) — error mapping formale]

## Technical Specs

- **BE:** `GlobalExceptionHandler` (`@ControllerAdvice`) — se non esiste, crearlo in package `api/exception/`.
- Gestire `EmailAlreadyRegisteredException` (custom, da creare o verificare esistenza in `service/AuthService.kt`) con risposta:
  - HTTP status: `409 Conflict`
  - `Content-Type: application/problem+json`
  - Body RFC 9457: `{ "type": "https://api/errors/email-already-registered", "title": "Conflict", "status": 409, "detail": "Email already registered: <masked>" }`
  - L'email viene riflessa nel `detail` solo quando è l'email appena inviata dal client (non leak per enum-attack).
- Gestire anche `MethodArgumentNotValidException` (Jakarta Bean Validation) → `400 Bad Request` con `type=https://api/errors/validation-failed` (se non già presente).
- **Standards:** RFC 9457 Problem Details, RFC 9110 §15.5.10 Conflict.
[^src: design_&_architecture/decisions/ADR-010-auth-consolidation.md §1. Registrazione (US-018) — error mapping formale]
[^src: design_&_architecture/decisions/ADR-007-api-contract.md §Error format]

## Implementation Steps

1. Verificare se `EmailAlreadyRegisteredException` esiste; se assente, crearla in `service/exception/`.
2. Verificare se `AuthService.register()` solleva questa eccezione sulla violazione UNIQUE email; se gestisce `DataIntegrityViolationException`, convertirla nel custom exception.
3. Creare o aggiornare `GlobalExceptionHandler` con `@ExceptionHandler(EmailAlreadyRegisteredException::class)` che ritorna `ResponseEntity` con `ProblemDetail` (Spring 6 built-in o custom DTO).
4. Aggiungere handler `MethodArgumentNotValidException` → 400 se assente.
5. Verificare che `SecurityConfig` non intercetti il 409 prima del handler.

## Definition of Done

- [ ] `POST /api/auth/register` con email duplicata → risposta `409` con `Content-Type: application/problem+json` e `type=https://api/errors/email-already-registered`.
- [ ] `POST /api/auth/register` con email non valida (sintassi) → `400` con `type=https://api/errors/validation-failed`.
- [ ] Unit test `GlobalExceptionHandlerTest`: verifica shape del body 409.
- [ ] Integration test `AuthControllerIT`: scenario email duplicata → 409.
