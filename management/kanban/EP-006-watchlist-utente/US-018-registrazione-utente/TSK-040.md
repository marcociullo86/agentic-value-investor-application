# TSK-040 — Flyway V009: aggiunta colonna first_issued_at a refresh_tokens

## Context

ADR-010 §3 introduce il concetto di **sliding refresh con cap assoluto 30 giorni**. L'algoritmo del cap assoluto richiede la colonna `first_issued_at TIMESTAMPTZ NOT NULL` nella tabella `refresh_tokens`, che traccia l'istante del login originale per la catena di refresh. Questa colonna non esiste nello schema corrente (V001–V008).
[^src: design_&_architecture/decisions/ADR-010-auth-consolidation.md §3. Session inactivity (US-019 AC#6) — sliding refresh]
[^src: management/kanban/EP-006-watchlist-utente/US-018-registrazione-utente/US-018.md §Business Rules]

## Technical Specs

- **DB:** Nuova migration Flyway `V009__add_first_issued_at_to_refresh_tokens.sql`:
  ```sql
  ALTER TABLE refresh_tokens ADD COLUMN first_issued_at TIMESTAMPTZ;
  UPDATE refresh_tokens SET first_issued_at = expires_at - INTERVAL '30 days' WHERE first_issued_at IS NULL;
  ALTER TABLE refresh_tokens ALTER COLUMN first_issued_at SET NOT NULL;
  ```
- La backfill `expires_at - 30d` è conservativa per le righe esistenti: non altera i refresh attivi (TTL non tocca), imposta solo il valore del cap assoluto.
- Aggiornare l'entity JPA `RefreshToken` aggiungendo il campo `firstIssuedAt: Instant`.
- Aggiornare `RefreshTokenRepository` se necessario (nessuna query aggiuntiva richiesta dal solo campo).
[^src: design_&_architecture/decisions/ADR-010-auth-consolidation.md §3. Session inactivity (US-019 AC#6) — sliding refresh]

## Implementation Steps

1. Creare `src/backend/src/main/resources/db/migration/V009__add_first_issued_at_to_refresh_tokens.sql` con il contenuto indicato.
2. Aggiornare l'entity `RefreshToken.kt` con campo `firstIssuedAt: Instant` annotato `@Column(name = "first_issued_at", nullable = false)`.
3. Eseguire `flyway validate` per verificare il checksum delle migration V001–V009.

## Definition of Done

- [ ] `flyway validate` verde su schema V001–V009.
- [ ] `refresh_tokens.first_issued_at` esiste con vincolo `NOT NULL`.
- [ ] Righe pre-esistenti (se presenti in test DB) hanno valore non-null dopo la migration.
- [ ] Entity JPA `RefreshToken` compila senza errori con il nuovo campo.
