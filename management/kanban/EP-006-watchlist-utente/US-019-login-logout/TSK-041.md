# TSK-041 — AuthService: sliding refresh con cap assoluto (ADR-010 §3)

## Context

US-019 AC#6 richiede che la sessione decada per inattività. ADR-010 §3 formalizza l'algoritmo: refresh token con TTL **sliding 7 giorni** dall'ultimo `/refresh` riuscito, più un **cap assoluto 30 giorni** dal `first_issued_at` (login originale). L'implementazione attuale in TSK-033 usa un TTL assoluto di 30 giorni senza sliding, e non considera il cap. Questo task aggiorna `AuthService.login()` e `AuthService.refresh()`.
[^src: management/kanban/EP-006-watchlist-utente/US-019-login-logout/US-019.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-010-auth-consolidation.md §3. Session inactivity (US-019 AC#6) — sliding refresh]

## Technical Specs

- **BE:** `AuthService.kt` — modifiche a `login()` e `refresh()`.
- **login():** emettere refresh token con:
  - `expires_at = now() + 7 days` (sliding TTL iniziale)
  - `first_issued_at = now()` (inizio catena)
- **refresh() — algoritmo completo:**
  1. Carica `refresh_tokens` by `token_value`; se assente → throw `InvalidRefreshTokenException` (401).
  2. Se `revoked_at IS NOT NULL` → throw `InvalidRefreshTokenException` (401).
  3. Se `expires_at < now()` → throw `InvalidRefreshTokenException` (401, inactivity).
  4. Se `first_issued_at + 30d < now()` → throw `InvalidRefreshTokenException` (401, cap assoluto raggiunto).
  5. Marca il refresh corrente `revoked_at = now()` (rotation).
  6. Emetti nuovo access token (TTL 15 min) + nuovo refresh token con `expires_at = now() + 7d`, `first_issued_at = previous.first_issued_at` (catena preservata).
- **application.yml:** aggiungere/aggiornare proprietà:
  ```yaml
  app.jwt.access-ttl-minutes: 15
  app.jwt.refresh-sliding-ttl-days: 7
  app.jwt.refresh-absolute-cap-days: 30
  ```
- Leggere le proprietà via `@ConfigurationProperties` o `@Value` nel service.

## Implementation Steps

1. Aggiungere/aggiornare le proprietà in `application.yml` (o `application.properties`).
2. Iniettare i valori nel `AuthService` (o in un `JwtConfig` bean `@ConfigurationProperties`).
3. Modificare `login()`: usare `refreshSlidingTtlDays` per `expires_at`; impostare `firstIssuedAt = Instant.now()`.
4. Modificare `refresh()`: implementare i passi 1–6 con il controllo del cap assoluto via `firstIssuedAt + refreshAbsoluteCapDays`.
5. Verificare che il nuovo refresh emesso preservi `firstIssuedAt` dal token precedente.

## Definition of Done

- [ ] `POST /api/auth/login` → refresh token con `expires_at = now+7d` e `first_issued_at = now`.
- [ ] `POST /api/auth/refresh` entro 7 giorni → nuovo token con `first_issued_at` invariato.
- [ ] `POST /api/auth/refresh` con token scaduto (inactività) → `401 invalid-refresh`.
- [ ] `POST /api/auth/refresh` oltre 30 giorni da `first_issued_at` → `401 invalid-refresh`.
- [ ] Proprietà configurabili via `application.yml`.
- [ ] Unit test `AuthServiceTest`: sliding ok, inactivity, cap assoluto.
