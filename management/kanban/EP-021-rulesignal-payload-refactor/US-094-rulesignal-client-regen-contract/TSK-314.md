# TSK-314 — FE Rigenerazione client TypeScript dal nuovo OpenAPI

## Obiettivo

Rigenerare il client TypeScript dell'API da `openapi.yaml` aggiornato (TSK-311) ottenendo union
types con discriminator per `RuleSignal` (13 sotto-tipi tipati), che permettano il type narrowing
sicuro via `ruleId`.

## Scope

1. Eseguire `openapi-generator-cli` (o toolchain equivalente già configurata nel progetto FE) sul
   `design_&_architecture/api/openapi.yaml` aggiornato da TSK-311.

2. Verificare che il client generato in `src/frontend/src/api-generated/` contenga:
   - Un union type `RuleSignal = RuleSignalSize | RuleSignalEarningsStability10y | ... (13 membri)`.
   - Ogni membro ha `ruleId` come literal type (es. `ruleId: 'SIZE_LATEST'`), che abilita il
     type narrowing TypeScript.

3. Se la generazione produce `any` / union non discriminato (problema noto — ADR-028 §5):
   - **Path A**: riapplicare `useUnionTypes=true` o flag equivalente nella config del generator.
   - **Path B**: post-processing script Node che riscrive il file TS generato.
   - **Path C** (last resort): type guards manuali `isRuleSignalSize(s): s is RuleSignalSize`.
   - Documentare la scelta in handoff con motivazione.

4. Assicurarsi che i campi legacy deprecati (`observedValue?`, `rationale?`, `threshold?`) siano
   presenti come opzionali (non rompono il type narrowing).

## Invarianti

- Il client generato compila senza errori TypeScript (`tsc --noEmit`).
- Nessuna modifica al rendering FE in questo task (US-095).
- I type esistenti per gli endpoint diversi da `GET /api/analysis/{ticker}` restano invariati.
