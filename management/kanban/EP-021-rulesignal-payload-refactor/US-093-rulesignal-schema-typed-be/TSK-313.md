# TSK-313 — QA Test unitari 13 sotto-tipi RuleSignal

## Obiettivo

Verificare per ognuna delle 13 strategie `ValuationRule` che:
1. Il DTO di output è il sotto-tipo concreto atteso (es. `assertThat(result).isInstanceOf(RuleSignal.Size::class.java)`).
2. I campi tipati specifici contengono i valori corretti dato un input deterministico.
3. La logica del segnale GREEN/YELLOW/RED/INDETERMINATE/NOT_CALCULABLE è invariata rispetto ai test esistenti.

## Scenari per ogni rule

Per ogni ruleId, almeno un test per stato rilevante:
- Input nominale → segnale GREEN + campi tipati valorizzati correttamente.
- Input sotto-soglia → segnale RED/YELLOW con campi tipati corretti.
- Input con campi mancanti → `INDETERMINATE` o `NOT_CALCULABLE` secondo la rule.

## Test retrocompabilità JSONB

Verificare che la deserializzazione di un payload JSONB pre-EP-021 (senza campi tipati) non sollevi
eccezioni e produca un oggetto con campi tipati `null` e `rationale` + `observedValue` valorizzati:
```kotlin
val legacyJson = """{"ruleId":"SIZE_LATEST","signal":"GREEN","observedValue":500000000,"rationale":"...","threshold":"$100M"}"""
val result: RuleSignal = objectMapper.readValue(legacyJson)
assertThat(result).isInstanceOf(RuleSignal.Size::class.java)
assertThat((result as RuleSignal.Size).revenueLatest).isNull()  // campo tipato mancante → null
assertThat(result.observedValue).isEqualTo(500_000_000.0)       // legacy valorizzato
```
