# TSK-312 — BE Adeguamento 13 strategie ValuationRule a emettere il sotto-tipo RuleSignal tipato

## Obiettivo

Modificare le 13 implementazioni `ValuationRule` (in `src/backend/.../ruleengine/rules/*.kt`) affinché
il metodo `evaluate()` ritorni il sotto-tipo concreto corrispondente (`RuleSignal.Size`,
`RuleSignal.EarningsStability10y`, ecc.) anziché l'istanza flat precedente.

## Scope

Per ognuna delle 13 rule:
- Il metodo `evaluate(dataset: FinancialDataset): RuleSignal` ritorna il sotto-tipo concreto (es.
  `RuleSignal.Size(signal = ..., revenueLatest = ..., thresholdUsd = ..., observedValue = ..., rationale = ...)`).
- I campi tipati vengono popolati dai valori già calcolati internamente dalla regola (es. per
  `SizeRule`: `revenueLatest = dataset.balanceSheet.totalRevenue`, `thresholdUsd = SIZE_THRESHOLD`).
- I campi legacy `observedValue` e `rationale` vengono ancora compilati (finestra transizione ADR-028 §8).
- La logica del segnale GREEN/YELLOW/RED/INDETERMINATE/NOT_CALCULABLE è invariata.

Regole da adeguare:
1. `SizeRule` → `RuleSignal.Size`
2. `EarningsStabilityRule` → `RuleSignal.EarningsStability10y`
3. `EpsGrowthRule` → `RuleSignal.EpsGrowth10y`
4. `Pe3yAvgRule` → `RuleSignal.Pe3yAvg`
5. `PbLatestRule` → `RuleSignal.PbLatest`
6. `DividendContinuityRule` → `RuleSignal.DividendContinuity20y`
7. `RoeRule` → `RuleSignal.Roe10yAvg`
8. `RoicRule` → `RuleSignal.Roic10yAvg`
9. `GrossMarginRule` → `RuleSignal.GrossMargin10yAvg`
10. `NetMarginRule` → `RuleSignal.NetMargin10yAvg`
11. `CurrentRatioRule` → `RuleSignal.CurrentRatioLatest`
12. `DebtToIncomeRule` → `RuleSignal.DebtToIncomeLatest`
13. `CapexIntensityRule` → `RuleSignal.CapexIntensity10yAvg`

## Invarianti

- Zero modifica alla logica di soglia; solo il costruttore del DTO di ritorno cambia.
- I test esistenti del Rule Engine (TSK-276..TSK-288 da Sprint 18) passano senza modifica funzionale
  (eventuale adeguamento minimo solo per nome campi se un test accedeva direttamente a `observedValue`
  per asserire un valore — documentare in handoff).
