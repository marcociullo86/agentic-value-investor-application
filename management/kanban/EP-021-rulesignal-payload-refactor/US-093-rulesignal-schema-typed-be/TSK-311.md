# TSK-311 — BE RuleSignal sealed interface Kotlin + schema OpenAPI oneOf/discriminator

## Obiettivo

Refactoring di `RuleSignal` da `data class` flat a **sealed interface polimorfica** Jackson-aware con
13 sotto-tipi tipati per `ruleId`, e aggiornamento dello schema OpenAPI 3.1 con `oneOf`/`discriminator`.

## Scope

### 1. `RuleSignal.kt` — sealed interface

Refactorizzare `src/backend/.../ruleengine/RuleSignal.kt` in sealed interface con annotazioni
Jackson `@JsonTypeInfo(use = NAME, include = EXISTING_PROPERTY, property = "ruleId", visible = true)`
+ `@JsonSubTypes` per 13 sotto-tipi.

Ogni sotto-tipo implementa:
- `override val ruleId: String` (costante fissa)
- `override val signal: Signal`
- `@Deprecated("R+3") override val observedValue: Double?`
- `@Deprecated("R+3") override val rationale: String`
- I campi tipati specifici per `ruleId` (vedi ADR-028 §3 — mapping completo).

I 13 sotto-tipi da creare: `Size`, `EarningsStability10y`, `EpsGrowth10y`, `Pe3yAvg`, `PbLatest`,
`DividendContinuity20y`, `Roe10yAvg`, `Roic10yAvg`, `GrossMargin10yAvg`, `NetMargin10yAvg`,
`CurrentRatioLatest`, `DebtToIncomeLatest`, `CapexIntensity10yAvg`.

Nota: i sotto-tipi EP-023 (`NcavLatest`, `NetNetRatio`) sono opzionali qui se US-096 è in flight
parallelo (vedi ADR-029 §5 Scenario B); il be-dev coordina con TSK-317.

### 2. `openapi.yaml` — schema tipato

Sostituire il blocco `RuleSignal:` in `design_&_architecture/api/openapi.yaml` (righe ~1097-1148)
con:
- `RuleSignal: { oneOf: [...13 $ref...], discriminator: { propertyName: ruleId, mapping: {...} } }`
- `RuleSignalBase:` con campi comuni + legacy `deprecated`
- 13 sotto-schemi `RuleSignalSize`, `RuleSignalEarningsStability10y`, ... (allOf RuleSignalBase +
  campi tipati specifici)

Schema OpenAPI e sotto-tipi Kotlin devono essere simmetrici (stesso nome campo, stesso tipo).

### 3. Persistenza JSONB

Strategia "natural overwrite" (ADR-028 §4): nessuna migration. I record vecchi vengono letti via
deserializer polimorfico Jackson; i campi tipati mancanti nei record stale → `null` (tutti nullable).
Il fallback FE su `rationale` legacy copre il gap temporaneo (US-095 paranoid fallback).

## Invarianti

- La logica di valutazione GREEN/YELLOW/RED/INDETERMINATE/NOT_CALCULABLE di ogni strategia è invariata.
- L'ordinamento lessicografico `sortedBy { ruleId }` resta deterministico.
- `RuleEngineResultResponse.signals: List<RuleSignal>` invariato nel tipo (deserializza polimorfico).
- I campi legacy `observedValue`, `rationale`, `threshold` restano compilati nel payload (transizione).
