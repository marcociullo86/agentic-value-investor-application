# TSK-319 — FE Crea formatters.ts typed-driven per 13 ruleId

## Obiettivo

Creare il file `src/frontend/lib/rule-signals/formatters.ts` con 13 formatter typed-driven
(uno per ogni `ruleId`) che producono `{ title, subtitle, tooltip }` dai campi tipati del
client TS generato (TSK-314).

## Scope

### `formatters.ts`

```typescript
type FormatterOutput = { title: string; subtitle: string; tooltip: string };

const formatters: Record<RuleSignal['ruleId'], (s: RuleSignal) => FormatterOutput> = {
  SIZE_LATEST: (s) => { ... },
  EARNINGS_STABILITY_10Y: (s) => { ... },
  // ... 13 formatter
};

export function formatRuleSignal(s: RuleSignal): FormatterOutput {
  const f = formatters[s.ruleId];
  if (!f) {
    // paranoid fallback: ruleId ignoto → rationale legacy
    return { title: s.ruleId, subtitle: s.rationale ?? '', tooltip: '' };
  }
  return f(s);
}
```

Ogni formatter:
- Legge i campi tipati specifici del sotto-tipo via type narrowing (switch su `s.ruleId` o cast
  diretto dopo controllo).
- Produce `subtitle` con valore osservato + soglia in formato leggibile (percentuali `%`, monetario
  `M`/`B`, anni `y`).
- Implementa il **paranoid fallback sul proprio branch**: se i campi tipati attesi sono `null`
  (record JSONB stale pre-EP-021) → degrada su `s.rationale ?? 'N/A'` per il subtitle.

Formatter da implementare (da ADR-028 §6):
- `SIZE_LATEST`: "Revenue: $X M/B (soglia $100M)"
- `EARNINGS_STABILITY_10Y`: "X/Y anni positivi (X lossYears)"
- `EPS_GROWTH_10Y`: "CAGR X.X% (soglia Y.X%)"
- `PE_3Y_AVG`: "P/E 3y: X.X (soglia <15)"
- `PB_LATEST`: "P/B: X.X (soglia <1.5)"
- `DIVIDEND_CONTINUITY_20Y`: "X anni consecutivi (soglia 20y)"
- `ROE_10Y_AVG`, `ROIC_10Y_AVG`: "Media X.X% (soglia verde Y%, giallo Z%)"
- `GROSS_MARGIN_10Y_AVG`, `NET_MARGIN_10Y_AVG`: "Media X.X% (soglia verde Y%)"
- `CURRENT_RATIO_LATEST`: "Ratio: X.X (verde >Y, giallo >Z)"
- `DEBT_TO_INCOME_LATEST`: "Ratio: X.X (verde <Y, giallo <Z)"
- `CAPEX_INTENSITY_10Y_AVG`: "Media X.X% (verde <Y%)"

## Invarianti

- Il file `formatters.ts` è nuovo; non modifica componenti esistenti (quelli vengono migrati in
  TSK-320).
- Esportazione pulita: solo `formatRuleSignal` come API pubblica.
