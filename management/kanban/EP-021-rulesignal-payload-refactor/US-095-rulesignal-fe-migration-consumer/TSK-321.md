# TSK-321 — QA Test FE Vitest snapshot + Playwright smoke (US-095)

## Obiettivo

Coprire gli Acceptance Criteria di US-095 con test Vitest (componenti + formatters) e un smoke
test Playwright sull'intera pagina analisi.

## Test Vitest

### 1. Test `formatters.ts` — 13 × 3 stati visivi

Per ogni `ruleId` (13 totali):
- **GREEN**: input con campi tipati valorizzati correttamente → subtitle non vuoto, contiene valore
  osservato e soglia in formato leggibile.
- **RED** (o YELLOW dove applicabile): input con segnale corrispondente → subtitle non vuoto.
- **INDETERMINATE / NOT_CALCULABLE**: input con campi tipati `null` → paranoid fallback attivato
  (subtitle = `rationale` legacy o 'N/A'), senza errore di runtime.

Totale: ~39 unit test (13 × 3; alcuni ruleId non hanno stato YELLOW → test RED/INDETERMINATE).

### 2. Test fallback paranoid esplicito

Un test dedicato per ogni formatter verifica che se i campi tipati attesi sono tutti `null` (record
JSONB stale pre-EP-021), il formatter ritorna un output non vuoto (usa `rationale` legacy o stringa
di fallback) senza lanciare eccezioni.

### 3. Test componente `TrafficLightPanel` (Vitest/React Testing Library)

- Renderizzare il pannello con mock di 13 segnali (uno per ruleId), tutti GREEN.
- Verificare che ogni riga mostri un subtitle non vuoto derivato da `formatRuleSignal()`.
- Un caso con segnale INDETERMINATE: la riga è visibile con stile coerente (dimmed) e subtitle
  non genera errori.

## Test Playwright (smoke)

- Aprire la pagina `/analysis?ticker=AAPL` (o ticker usato nelle fixture E2E esistenti).
- Verificare che il pannello Traffic Light mostri 13 righe di segnale con subtitle visibili (no vuoti).
- Nessuna regressione visiva palese rispetto allo snapshot di riferimento (se disponibile).
