# US-047 — Universe screener service (NASDAQ + NYSE + 13-F + news scout)

## Descrizione
Come sistema backend, voglio un servizio `UniverseScreenerService` che restituisca l'elenco di candidati value-investing dell'universo NASDAQ + NYSE, ottenuto incrociando lo screener FMP `/stable/company-screener`, l'overlay 13-F dei top fund value tramite SEC EDGAR e lo scout news qualitativo, affinché il batch notturno (US-048) abbia un input deterministico e auditabile invece di scansionare ogni singolo ticker dell'universo. [^src: wiki/runbooks/defensive-investor-checklist.md §Universe screening]

## Business Rules
- Universo target: **NASDAQ + NYSE** (confermato dall'utente).
- Filtri base via `/stable/company-screener`: `exchange=NASDAQ,NYSE`, `marketCap > $3B`, `country = US`, settori esclusi dalla checklist difensiva Graham (es. settori volatili / hard-to-predict come da `wiki/runbooks/defensive-investor-checklist.md`).
- Overlay 13-F: il servizio integra l'elenco dei top holding dei principali fondi value (lista hardcoded versionata in `application.yaml`: Berkshire Hathaway, Baupost, Oakmark, ecc.) ottenuti via SEC EDGAR (US-038).
- News scout (qualitativo): Claude Opus 4.7 (`claude-opus-4-7`) viene chiamato su un set limitato di candidati top-200 post-screener-base per identificare eventuali ticker in panic-buy zone non già catturati. Esecuzione opzionale, cappata per costi.
- Output: `List<UniverseCandidate>` con `(ticker, source ∈ {screener, 13f, news_scout}, market_cap, sector)`. Lista finale ordinata per `market_cap` desc, deduplicata su `ticker`.
- Cap dimensionale: la lista finale è limitata a max 500 candidati / run (parametro `universe.cap.candidates` in `application.yaml`).
- Rate-limit dedicato: questo servizio usa un `RateLimiter` Resilience4j separato da quello on-demand (`fmp-batch` vs `fmp-online`), con quota dedicata che non sottrae throughput agli utenti diurni.
- Idempotenza: l'esecuzione di `screen()` due volte ravvicinate sullo stesso giorno deve restituire la stessa lista (cache 6 ore sui risultati screener/13F).
- Wiki: la specifica completa del servizio è codificata nel prototipo Python `agent.py` (segnalato al wiki-keeper per promozione a concept dedicato).

## Acceptance Criteria
- [ ] `UniverseScreenerService.screen()` restituisce una lista non vuota di candidati NASDAQ + NYSE filtrati.
- [ ] La lista contiene `source` valorizzato per ogni candidato.
- [ ] Il cap `universe.cap.candidates` è rispettato (lista finale ≤ 500).
- [ ] Esecuzioni ripetute entro 6 ore restituiscono lo stesso input (cache verificata in test).
- [ ] Il `RateLimiter` `fmp-batch` è configurato separatamente da `fmp-online` (verificato via configurazione + test integrazione).
- [ ] Test di integrazione su mock FMP + mock SEC verifica deduplicazione cross-source.
- [ ] Log evento al termine: `(run_date, total_candidates, breakdown_by_source, duration_ms)`.
