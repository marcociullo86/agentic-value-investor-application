# TSK-139 — OpenAPI schema /api/top-picks + contract test + integration test paginazione/filtri

## Cosa fare

1. Aggiornare il contratto OpenAPI con il path `GET /api/top-picks`, i query params e lo schema `TopPicksPageResponse`.
2. **Contract test**: verificare che lo schema OpenAPI includa `runDate`, `page`, `size`, `total`, `items` nella risposta 200; e i codici 400 con `problem+json`.
3. **Integration test** `TopPicksControllerTest` con Testcontainers PostgreSQL:
   - Pre-popolare `top_value_picks` con 30 record per `run_date = today`.
   - `GET /api/top-picks` → 30 items con `total = 30`.
   - `GET /api/top-picks?date=today` → stessa risposta.
   - `GET /api/top-picks?verdict=APPROVATO_PANIC_BUY` → solo items con quel verdict.
   - `GET /api/top-picks?sector=Technology` → solo items con sector contenente "technology" (case-insensitive).
   - `GET /api/top-picks?min_mos=20` → solo items con `score_mos >= 20`.
   - `GET /api/top-picks?page=1&size=10` → items 11-20.
   - `GET /api/top-picks?date=invalid` → 400 `problem+json`.
   - `GET /api/top-picks?date=2026-01-01` (nessun record) → 200 `total = 0`.
   - Verificare header `Cache-Control: public, max-age=3600` nella risposta.

## Acceptance Criteria

- [ ] Contract test: schema OpenAPI include tutti i campi.
- [ ] `GET /api/top-picks` → 30 items.
- [ ] Filtri: verdict, sector, min_mos funzionanti.
- [ ] Paginazione verificata.
- [ ] Date invalida → 400.
- [ ] Data senza run → 200 `total = 0`.
- [ ] `Cache-Control` header presente.
