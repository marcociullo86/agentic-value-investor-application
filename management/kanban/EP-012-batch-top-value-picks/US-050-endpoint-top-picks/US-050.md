# US-050 — Endpoint `GET /api/top-picks` paginato

## Descrizione
Come consumatore API, voglio un endpoint REST `GET /api/top-picks` che restituisca la classifica giornaliera Top Value Picks (default: ultima run disponibile) con supporto paginazione, filtri per data, verdict e settore, affinché frontend e integratori esterni possano consultare le top picks senza accesso diretto al database. [^src: wiki/concepts/analysis-api-pipeline.md §Pipeline]

## Business Rules
- Endpoint: `GET /api/top-picks`.
- Query parameter opzionali:
  - `date` (formato `YYYY-MM-DD`, UTC): se assente → ultima `run_date` disponibile in `top_value_picks`.
  - `verdict`: filtro su `verdict_class` (uno tra i 6 valori canonici di US-044).
  - `sector`: filtro substring case-insensitive su `sector`.
  - `min_mos`: filtro `score_mos >= min_mos`.
  - `page` (default 0), `size` (default 30, max 100).
- Risposta JSON: `{ "run_date": ..., "page": N, "size": M, "total": K, "items": [...] }` dove ogni item include `rank`, `ticker`, `verdict_class`, `score_mos`, `position_size_pct`, `market_cap_usd`, `sector`, `sources_json`.
- Risposta per `date` con nessun record: 200 con `total = 0` e `items = []` (non 404 — la classifica può semplicemente non esistere per quel giorno).
- Risposta per `date` malformata o in futuro: 400 con problem+json conforme RFC 9457 (US-021).
- Default ordinamento: per `rank` ascendente (≡ MoS decrescente).
- Caching HTTP: header `Cache-Control: public, max-age=3600` (la classifica giornaliera non cambia entro la giornata UTC).
- Endpoint pubblico (no auth richiesta per la lettura), coerente con `/api/analysis/{ticker}` esistente.
- OpenAPI: schema completo documentato nello YAML del contratto canonico.
- Audit: log evento `(timestamp, query_params, total_returned, duration_ms)` per ogni chiamata.

## Acceptance Criteria
- [ ] `GET /api/top-picks` senza parametri restituisce la classifica della `run_date` più recente.
- [ ] `GET /api/top-picks?date=2026-06-01` restituisce la classifica di quella data specifica.
- [ ] `GET /api/top-picks?verdict=APPROVATO_PANIC_BUY` filtra solo i panic-buy della classifica.
- [ ] `GET /api/top-picks?sector=Technology` filtra solo settore Technology (case-insensitive).
- [ ] `GET /api/top-picks?min_mos=20` restituisce solo ticker con MoS ≥ 20%.
- [ ] Paginazione: `page=1&size=10` restituisce gli elementi 11-20 della classifica.
- [ ] `GET /api/top-picks?date=invalid` risponde 400 con problem+json.
- [ ] `GET /api/top-picks?date=2026-01-01` (data senza run) risponde 200 con `total = 0`.
- [ ] Header `Cache-Control: public, max-age=3600` presente nella risposta 200.
- [ ] OpenAPI YAML aggiornato con schema completo.
- [ ] Contract-test e integration-test coprono i casi sopra.
