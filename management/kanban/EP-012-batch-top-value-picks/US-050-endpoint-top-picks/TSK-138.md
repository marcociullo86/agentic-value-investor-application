# TSK-138 — Implementa TopPicksController GET /api/top-picks con paginazione e filtri

## Cosa fare

1. Creare `TopPicksController` in `./src/backend/src/main/kotlin/com/valueinvesting/controller/TopPicksController.kt`.
2. Endpoint: `GET /api/top-picks` con query params opzionali:
   - `date` (String, `YYYY-MM-DD`): se assente → `TopValuePickRepository.findLatestRunDate()`.
   - `verdict` (String): filtro su `verdict_class`.
   - `sector` (String): filtro substring case-insensitive.
   - `min_mos` (Double): filtro `score_mos >= min_mos`.
   - `page` (Int, default 0), `size` (Int, default 30, max 100).
3. Risposta JSON: `TopPicksPageResponse(runDate, page, size, total, items: List<TopPickItemDto>)`.
4. Gestione errori:
   - `date` malformata → 400 con `problem+json` (RFC 9457).
   - `date` in futuro → 400 con `problem+json`.
   - `date` senza run → 200 con `total = 0, items = []`.
5. Header `Cache-Control: public, max-age=3600` nella risposta 200.
6. Endpoint pubblico (no auth).
7. Audit log per ogni chiamata.

## Acceptance Criteria

- [ ] `GET /api/top-picks` → classifica ultima `run_date`.
- [ ] `date` malformata → 400 `problem+json`.
- [ ] `date` senza run → 200 `total = 0`.
- [ ] Filtri `verdict`, `sector`, `min_mos` funzionanti.
- [ ] Paginazione `page=1&size=10` → elementi 11-20.
- [ ] Header `Cache-Control: public, max-age=3600` presente.
