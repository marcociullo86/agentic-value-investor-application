# US-051 — Pagina FE "Top Value Picks"

## Descrizione
Come investitore retail, voglio una pagina dedicata `/top-picks` sul frontend che mostri la classifica giornaliera dei migliori candidati value su NASDAQ + NYSE, ordinata per Margin of Safety decrescente, con filtri per verdetto, settore e market cap e con link diretto alla deep analysis di ogni ticker, affinché possa scoprire ogni mattina i candidati value-investing migliori senza analizzare manualmente l'universo. [^src: wiki/concepts/webapp-architecture-vi.md §Architettura applicativa]

## Business Rules
- Route: `/top-picks`.
- Sezioni in pagina (ordine fisso top-down):
  1. Header con data della classifica visualizzata (es. "Classifica del 2026-06-01") + datepicker per consultare classifiche storiche (ultimi 365 giorni grazie a retention US-049).
  2. Banner "Aggiornata ogni notte alle 02:00 UTC" + timestamp dell'ultima `run_date` effettiva.
  3. Filtri (sidebar o top-bar): verdict (multi-select), sector (multi-select), market cap range (slider), MoS minimo (slider).
  4. Tabella principale: colonne `Rank`, `Ticker`, `Verdict` (badge colorato), `MoS %`, `Position size`, `Market cap`, `Sector`, `Sources` (icone per screener / 13f / news scout / panic).
  5. Ogni riga della tabella ha link al dettaglio: cliccando il ticker si naviga a `/analysis/{ticker}/deep` (pagina di US-046).
- Sorgente dati: chiamata a `GET /api/top-picks` con query parameters mappati sui filtri della UI.
- Ordinamento default: per `rank` ascendente (= MoS decrescente). L'utente può ri-ordinare colonna per colonna.
- Paginazione tabella: 30 righe per pagina (default API), pulsanti "Pagina successiva" se la classifica filtrata supera la prima pagina.
- Stato vuoto: se `total = 0` (nessuna classifica per quella data) la pagina mostra messaggio dedicato "Nessuna classifica disponibile per questa data" + suggerimento di cambiare data.
- Stato errore: render dedicato per 400 (data invalida), 503 (API non disponibile) con call-to-action distinte.
- Accessibilità: i badge verdict hanno alternativa testuale + icona (coerenza con US-014 / US-046).
- Componenti riusati: badge verdict coerente con quello di US-046; pattern tabella filtrabile coerente con quella search/screener di US-003.
- Persistenza filtri: i filtri attivi sono riflessi negli URL query params (deep-linkable / shareable).

## Acceptance Criteria
- [ ] La pagina `/top-picks` carica e mostra la classifica della `run_date` più recente.
- [ ] Il datepicker permette di consultare classifiche degli ultimi 365 giorni.
- [ ] I filtri verdict / sector / market cap / MoS minimo modificano correttamente la tabella e l'URL query params.
- [ ] Cliccando il ticker l'utente è navigato a `/analysis/{ticker}/deep`.
- [ ] Stato vuoto mostrato correttamente per data senza run.
- [ ] Stato errore 400 mostrato per data malformata digitata manualmente nell'URL.
- [ ] Stato errore 503 mostrato se l'API è non disponibile.
- [ ] I badge verdict hanno alternativa testuale + icona (test accessibilità).
- [ ] URL deep-linkable: incollare l'URL con i filtri in finestra nuova ripristina la stessa vista.
- [ ] Test E2E (Playwright) coprono almeno: caricamento default, filtro verdict, navigazione a /deep, datepicker storico.
