# TSK-133 — Migration V017__top_picks_run_log + scheduler enable application.yaml

## Cosa fare

1. Creare `V017__top_picks_run_log.sql` in `./src/backend/src/main/resources/db/migration/`:
   ```sql
   CREATE TABLE top_picks_run_log (
     id                 BIGSERIAL PRIMARY KEY,
     run_date           DATE        NOT NULL,
     ticker_processed   INT,
     ticker_failed      INT,
     total_duration_min DECIMAL(6,2),
     top30_count        INT,
     top30_tickers      TEXT,
     started_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
     completed_at       TIMESTAMPTZ
   );
   CREATE INDEX idx_run_log_date ON top_picks_run_log (run_date DESC);
   ```
2. Aggiungere in `application.yaml` (profilo `production`):
   ```yaml
   spring:
     task:
       scheduling:
         enabled: true
         pool:
           size: 2
   ```
3. Aggiungere in `application.yaml` (profilo `default`/`dev`):
   ```yaml
   spring:
     task:
       scheduling:
         enabled: false
   ```
   (disattivare lo scheduler in sviluppo per evitare esecuzioni non intenzionali).

## Acceptance Criteria

- [ ] `V017__top_picks_run_log.sql` applicata da Flyway senza errori.
- [ ] Tabella `top_picks_run_log` esiste con i campi.
- [ ] Scheduler abilitato solo nel profilo `production` (test: lo scheduler non parte in profilo `test`).
- [ ] `flyway validate` passa.
