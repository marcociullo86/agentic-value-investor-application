# TSK-131 — Implementa TopValuePicksJob @Scheduled cron 02:00 UTC — pipeline batch + top 30 per MoS

## Cosa fare

1. Creare `TopValuePicksJob` in `./src/backend/src/main/kotlin/com/valueinvesting/job/TopValuePicksJob.kt`.
2. Annotare con `@Scheduled(cron = "0 0 2 * * *", zone = "UTC")`.
3. Il job esegue:
   a. `UniverseScreenerService.screen()` → lista candidati (US-047).
   b. Per ogni candidato: `VerdictCascadeService.compute(ticker)` (aka `MungerDecisionService.compute(ticker)`).
   c. Gestione errori per singolo ticker: `try-catch`, log + skip (non interrompe il batch).
   d. Filtra solo `verdettoCLasse ∈ {APPROVATO, APPROVATO_PANIC_BUY, WATCHLIST}`.
   e. Ordina per `marginOfSafety` decrescente, prende i top 30.
   f. Upsert in `top_value_picks` via `TopValuePickRepository` (idempotente su `run_date`).
4. Tracciamento in `top_picks_run_log`: `(runDate, tickerProcessed, tickerFailed, totalDurationMin, top30Count, top30Tickers)`.
5. Log WARNING se durata > 3h; abort con log ERROR se FMP irraggiungibile > 30 min.

## Acceptance Criteria

- [ ] Il job è annotato `@Scheduled(cron = "0 0 2 * * *", zone = "UTC")`.
- [ ] Esecuzione manuale (via test) produce record in `top_value_picks` con `run_date = oggi`.
- [ ] Riesecuzione stesso giorno → upsert, no errori.
- [ ] Errore su singolo ticker → skip + log, batch continua.
- [ ] Log WARNING se durata > 3h.
- [ ] `top_picks_run_log` registra ogni esecuzione.
- [ ] Tutti i ticker top 30 hanno `verdettoCLasse ∈ {APPROVATO, APPROVATO_PANIC_BUY, WATCHLIST}`.
