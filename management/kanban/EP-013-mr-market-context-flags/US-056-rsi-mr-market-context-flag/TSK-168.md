# TSK-168 — FE badge "Mr. Market Sentiment" (RSI flag)

## Cosa fare

1. Creare il componente `MrMarketSentimentBadge.tsx` in `src/frontend/components/analysis/`:
   - Props: `flag: "OVERSOLD" | "NEUTRAL" | "OVERBOUGHT" | "INDETERMINATE"`, `rsiLatest: number | null`, `rsiTimestamp: string | null`.
   - Rendering:
     - `OVERSOLD` → badge blu con label "Mr. Market: oversold (RSI {N})" + tooltip esplicativo
     - `NEUTRAL` → badge grigio "Mr. Market: neutro (RSI {N})"
     - `OVERBOUGHT` → badge giallo "Mr. Market: overbought (RSI {N})"
     - `INDETERMINATE` → badge tenue "Sentiment non disponibile"
   - Tooltip (accessibilità): "Indicatore tecnico RSI 14d. Advisory: NON sostituisce il giudizio fondamentale dei 13 ruleSignals."
   - **Colori distinti dai 13 ruleSignals**: NON usare green/red (riservati al TrafficLight). Usare palette blu/giallo/grigio.
2. Posizionare il badge in `AnalysisPageClient.tsx` **sopra** il `TrafficLightPanel`, in una nuova section "Context Flags" che contiene anche `LongTermTrendBadge` (TSK-169).
3. Estendere il tipo TypeScript `RuleEngineResultResponse` (auto-gen da OpenAPI o manuale) per includere `contextFlags.mrMarketRsi`.
4. Snapshot test + accessibility check (alt text, contrast ratio).

## Acceptance Criteria

- [ ] Pagina `/analysis/AAPL` mostra badge "Mr. Market Sentiment" sopra il TrafficLight.
- [ ] Badge colorato in modo distinto dal TrafficLight (no green/red).
- [ ] Tooltip accessibile spiega che è advisory.
- [ ] Per `INDETERMINATE` il badge è visibile ma tenue (no errore).
- [ ] Snapshot test verifica i 4 stati.
- [ ] No regression sul TrafficLightPanel.
