# TSK-164 — FmpAdapter.getTechnicalIndicator generico (riusato da US-056 + US-057)

## Cosa fare

1. Aggiungere all'interfaccia `FmpAdapter` (in `src/backend/src/main/kotlin/com/valueinvesting/webapp/fmp/FmpAdapter.kt`) il metodo generico:
   ```kotlin
   fun getTechnicalIndicator(
       ticker: String,
       indicator: String,           // "rsi" | "sma" | "ema" | ... (whitelist enum)
       periodLength: Int,
       timeframe: String = "1day"
   ): List<TechnicalIndicatorRecord>
   ```
2. Creare il DTO `TechnicalIndicatorRecord` in `src/backend/src/main/kotlin/com/valueinvesting/webapp/fmp/dto/`:
   - `date: Instant?` (timestamp del record)
   - `value: Double?` (valore dell'indicatore al record)
   - `open: Double?`, `high: Double?`, `low: Double?`, `close: Double?`, `volume: Long?` (OHLCV — FMP li ritorna insieme all'indicatore)
3. Implementare in `FmpAdapterRestClient`: `GET /stable/technical-indicators/{indicator}?symbol={ticker}&periodLength={n}&timeframe={tf}&apikey={key}`.
4. **Whitelist `indicator`**: accetta solo `rsi`, `sma` (per EP-013). Altri valori → `IllegalArgumentException`. Estendibile in futuro senza rompere il contract.
5. Cacheable: TTL 1h (giornaliero indicator → no senso TTL 24h come financial statements). `FmpCacheService` esistente con chiave `(ticker, indicator, periodLength, timeframe)`.
6. Resilience: riusa la chain Resilience4j esistente (`ResilientFmpAdapter` wrapper).
7. Gestire 404 + lista vuota come lista vuota (no exception).

## Acceptance Criteria

- [ ] `FmpAdapter.getTechnicalIndicator(ticker, "rsi", 14, "1day")` ritorna lista non vuota per AAPL.
- [ ] `getTechnicalIndicator(ticker, "sma", 200, "1day")` ritorna lista non vuota per AAPL con > 200 giorni di storico.
- [ ] Per un ticker IPO recente (< 200 giorni storico) con SMA200, lista vuota (no exception).
- [ ] Indicator non in whitelist → `IllegalArgumentException`.
- [ ] Cache hit entro TTL 1h: nessuna chiamata HTTP duplicata.
- [ ] Zero regressioni sui metodi `FmpAdapter` esistenti.
