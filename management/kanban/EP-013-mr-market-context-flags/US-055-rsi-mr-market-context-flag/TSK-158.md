# TSK-158 — Test QA cross — FmpAdapter.getTechnicalIndicator + 2 evaluator

## Cosa fare

1. Creare `FmpAdapterTechnicalIndicatorTest.kt` in `src/backend/src/test/kotlin/com/valueinvesting/webapp/fmp/`:
   - WireMock stub `/stable/technical-indicators/rsi?symbol=AAPL&periodLength=14&timeframe=1day` → JSON fixture con 30 record.
   - WireMock stub `/stable/technical-indicators/sma?symbol=AAPL&periodLength=200&timeframe=1day` → JSON fixture con 200+ record.
   - Test: indicator whitelist (rsi/sma OK, "macd" → IllegalArgumentException).
   - Test: 404 / lista vuota → lista vuota Kotlin (no exception).
   - Test: cache hit entro TTL 1h (seconda chiamata stesso ticker+indicator → no HTTP call).
2. Creare `RsiContextEvaluatorTest.kt` in `src/backend/src/test/kotlin/com/valueinvesting/webapp/contextflags/`:
   - Mock `FmpAdapter` con MockK.
   - 4 scenari: OVERSOLD (RSI 25), NEUTRAL (RSI 50), OVERBOUGHT (RSI 75), INDETERMINATE (lista vuota).
   - Edge: RSI esattamente 30.0 → NEUTRAL (boundary inclusive su NEUTRAL, non OVERSOLD); RSI 70.0 → NEUTRAL.
3. Creare `LongTermTrendEvaluatorTest.kt` nello stesso package:
   - 4 scenari: BELOW_TREND (price $80 / sma $100), NEAR_TREND (price $100 / sma $98), ABOVE_TREND (price $150 / sma $100), INDETERMINATE (sma null).
   - Edge: priceVsSmaPct = -0.05 exact → NEAR_TREND (boundary); +0.20 exact → NEAR_TREND.
   - Edge: currentPrice=null → INDETERMINATE; sma=0.0 → INDETERMINATE.
4. Integration test `AnalyzeTickerServiceContextFlagsIT.kt`: verifica che `GET /api/analysis/AAPL` includa `contextFlags.mrMarketRsi` + `contextFlags.longTermTrend` con WireMock per FMP completo.

## Acceptance Criteria

- [ ] Tutti i test unit passano (FmpAdapter + 2 evaluator).
- [ ] Integration test verifica presenza di entrambi i flag nel response.
- [ ] Boundary inclusive verificati (RSI 30/70, priceVsSmaPct -0.05/+0.20).
- [ ] WireMock fixture per rsi.json + sma.json riusabili in altri test.
