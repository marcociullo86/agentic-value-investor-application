# TSK-179 — BE SecurityEventLogger con metodi tipizzati per 6+ categorie

## Context
US-062 richiede logging strutturato di tutti gli eventi di sicurezza rilevanti con livello appropriato, userId e contesto. Gli eventi devono rispettare il formato US-058 e includere il Correlation ID US-059.
[^src: management/kanban/EP-014-logging-strutturato-observability/US-062-security-events-logging/US-062.md §AC]
[^src: design_&_architecture/decisions/ADR-021-structured-logging-pii-redaction.md §6]

## Technical Specs
- **BE:** `SecurityEventLogger` @Component in package `service`
- **Metodi tipizzati per evento:**

| Evento | Livello | Contesto |
|---|---|---|
| Login success | INFO | userId, ip (redatto), device fingerprint |
| Login failure | WARN | userId (se noto), motivo |
| Password change/reset | INFO | userId |
| MFA enable/disable/fallback | INFO | userId, metodo |
| Permission/role grant/revoke | INFO | userId, role/permission, grantedBy |
| Accesso 403 | WARN | userId, risorsa, ruolo attuale |

- **Marker Logback:** `SECURITY_EVENT` per routing retention differenziata (US-063)
- **Formato:** StructuredArgument logstash-logback-encoder per campi contesto
- **Integrazione:** correlationId da MDC (TSK-172), PII redatto (TSK-175)

## Implementation Steps
1. Creare `SecurityEventLogger` @Component
2. Definire marker Logback `SECURITY_EVENT`
3. Implementare metodi per 6+ categorie con StructuredArgument
4. Integrare nei punti di auth esistenti (AuthController, SecurityConfig)
5. Integrare nel GlobalExceptionHandler per 403

## Definition of Done
- [ ] 6+ categorie eventi coperte con metodi tipizzati
- [ ] Marker `SECURITY_EVENT` su tutti gli eventi
- [ ] Livello corretto: INFO success, WARN/ERROR failure
- [ ] Correlation ID presente in tutti gli eventi
- [ ] Code review approvata

## Dependencies
- TSK-170 (infrastruttura logging)
- TSK-172 (Correlation ID in MDC)
