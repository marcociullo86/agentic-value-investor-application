# US-062 — Logging eventi di sicurezza

## Descrizione
Come security auditor, voglio che tutti gli eventi di sicurezza rilevanti (login, password change, MFA, permessi, operazioni finanziarie, accessi negati) siano loggati con livello appropriato (INFO per successo, WARN/ERROR per fallimento), sempre con userId e contesto, affinché possa ricostruire l'attività di un utente e rilevare tentativi di compromissione tramite analisi dei log. [^src: wiki/concepts/fintech-security-compliance.md §5.6 — Security events da loggare]

## Business Rules
- Eventi da loggare con livello INFO (success) o WARN/ERROR (failure), sempre con userId e contesto:
  - Login success / failure (con motivo: credenziali errate, account bloccato, MFA fallita)
  - Password change, password reset request/completion
  - MFA enable / disable / fallback usage
  - Permission / role grant o revoke
  - Operazioni finanziarie rilevanti (creazione transazione, modifica beneficiario, cambio limiti)
  - Accesso fallito a risorse protette (403)
- Tutti gli eventi di sicurezza rispettano il formato strutturato di US-058 e includono il Correlation ID di US-059.
- I dati sensibili negli eventi di sicurezza sono redatti secondo le regole di US-060.
[^src: wiki/concepts/fintech-security-compliance.md §5.6 — Security events da loggare]

## UI Reference
Nessuna — storia backend-only.

## Acceptance Criteria
- [ ] Un login fallito produce un log WARN con userId, motivo del fallimento e Correlation ID.
- [ ] Un login riuscito produce un log INFO con userId e Correlation ID.
- [ ] Un accesso 403 a risorsa protetta produce un log WARN con userId, risorsa richiesta e Correlation ID.
- [ ] Un cambio password produce un log INFO con userId (senza la password in nessuna forma).
- [ ] Test di integrazione verifica che almeno 6 delle categorie di eventi documentate generano log con il formato corretto.
