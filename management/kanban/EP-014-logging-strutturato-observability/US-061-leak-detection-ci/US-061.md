# US-061 — Test leak detection PII in CI

## Descrizione
Come compliance officer, voglio che la pipeline CI esegua automaticamente una batteria di pattern regex contro i log generati durante i test per rilevare leak di dati sensibili (PAN, JWT, IBAN, email, API key, password), fallendo il build al primo match, affinché nessuna regressione PII raggiunga mai gli ambienti di staging o produzione. [^src: wiki/concepts/fintech-security-compliance.md §Test di leak detection in CI]

## Business Rules
- Una batteria di test CI genera log durante l'esecuzione dei test (inclusi scenari di errore intenzionali con dati PII di test).
- L'output log viene scansionato con pattern regex per: PAN, JWT, IBAN completo, email completa (in contesti INFO), API key, password.
- Il build fallisce al primo match di un pattern PII nel log di output.
- I test sono integrati nella pipeline CI esistente.
- I pattern devono coprire i formati PII documentati nella policy di redazione (US-060).
[^src: wiki/concepts/fintech-security-compliance.md §Test di leak detection in CI]

## UI Reference
Nessuna — storia CI/QA.

## Acceptance Criteria
- [ ] Un test che genera un log contenente un PAN non redatto causa il fallimento del build CI.
- [ ] Un test che genera un log contenente un JWT completo causa il fallimento del build CI.
- [ ] La batteria copre almeno 6 categorie: PAN, CVV, IBAN, JWT, API key, password.
- [ ] Il report di fallimento indica quale pattern è stato matchato e in quale log line.
- [ ] Con redazione PII attiva (US-060), tutti i test CI di leak detection passano (zero match).
