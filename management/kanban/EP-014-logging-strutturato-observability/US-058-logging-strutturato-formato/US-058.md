# US-058 — Logging strutturato con formato per ambiente

## Descrizione
Come sviluppatore in triage, voglio che ogni log entry del backend contenga un set fisso di campi strutturati (timestamp ISO 8601, level, service, traceId, spanId, userId, message, context) in formato JSON in produzione e pretty-print colorato in sviluppo locale, configurabile tramite variabile d'ambiente senza redeploy, affinché possa correlare e filtrare log in aggregatori senza aprire altri sistemi. [^src: wiki/concepts/structured-logging-backend.md §Formato per ambiente]

## Business Rules
- In produzione il formato è JSON strutturato; in sviluppo locale è pretty-print con colori.
- Il formato e il livello di log sono configurabili tramite variabile d'ambiente, senza necessità di redeploy.
- Campi obbligatori per ogni log entry: `timestamp` (ISO 8601 con timezone), `level` (TRACE/DEBUG/INFO/WARN/ERROR/FATAL), `service` (nome del servizio), `traceId`, `spanId`, `userId` (se autenticato, non PII-sensibile), `message` (linguaggio naturale inglese, verbo all'inizio), `context` (oggetto con dati rilevanti).
- I messaggi di log sono in linguaggio naturale inglese con verbo all'inizio: "Failed to process payment intent" invece di "PaymentService.process error".
- Stack trace inclusi solo da livello ERROR in su; i path filesystem del server non vengono mai esposti nelle risposte client.
- Il logging non deve aggiungere più di 2ms p99 alla latenza della richiesta; il logger deve essere asincrono/bufferizzato.
[^src: wiki/concepts/structured-logging-backend.md §Campi obbligatori per ogni log entry]

## UI Reference
Nessuna — storia backend-only.

## Acceptance Criteria
- [ ] Un log entry generato in ambiente produzione è un JSON valido con tutti e 7 i campi obbligatori popolati.
- [ ] Un log entry in ambiente sviluppo è pretty-printed con colori (non JSON raw).
- [ ] Cambiare la variabile d'ambiente del formato (JSON ↔ pretty) non richiede rebuild o redeploy.
- [ ] Cambiare la variabile d'ambiente del livello (es. INFO → DEBUG) non richiede rebuild o redeploy.
- [ ] Benchmark: il logging non aggiunge più di 2ms p99 su un campione di 1000 richieste sotto carico simulato.
- [ ] I messaggi di log degli endpoint principali iniziano con un verbo in inglese.
- [ ] Nessun path filesystem del server compare nelle risposte HTTP di errore.
