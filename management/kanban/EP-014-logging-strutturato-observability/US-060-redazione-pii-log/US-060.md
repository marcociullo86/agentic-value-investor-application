# US-060 — Redazione automatica PII nei log

## Descrizione
Come compliance officer, voglio che tutti i dati personali e finanziari sensibili siano automaticamente redatti nei log prima della scrittura, secondo regole centralizzate aggiornabili senza redeploy, affinché nessun dato PII compaia in chiaro nei sistemi di aggregazione log, in conformità con REQ-05 §5.1. [^src: wiki/concepts/fintech-security-compliance.md §5.1 — Data privacy nei log]

## Business Rules
- La lista dei campi sensibili è gestita centralmente come configurazione (non hardcoded nei singoli logger), aggiornabile senza redeploy.
- I pattern di redazione sono applicati ricorsivamente a oggetti nested, array e stringhe contenenti JSON serializzato.
- Regole di redazione minime:

| Campo | Regola |
|---|---|
| PAN (numero carta) | Solo BIN (prime 6) + ultime 4 cifre; mai PAN completo |
| CVV/CVC | Mai loggato in nessuna forma o livello |
| IBAN | Paese (2 char) + ultime 4; in DEBUG ammessa estesa solo in non-prod |
| Email | In INFO solo dominio; in DEBUG ammessa completa in non-prod |
| JWT, API key, refresh token, segreti, password | Mai loggati |
| IP address | Anonimizzazione ultimo ottetto IPv4 / ultimi 80 bit IPv6 |

- CVV e PAN completo non sono mai visibili in nessun ambiente e livello.
- La redazione è ambiente-aware: in produzione rigorosa su tutti i livelli; in non-prod con livello DEBUG ammessa estesa per IBAN ed email.
[^src: wiki/runbooks/pii-redaction-checklist.md §Step 1 — Definire la lista centralizzata dei campi sensibili]

## UI Reference
Nessuna — storia backend-only.

## Acceptance Criteria
- [ ] Un PAN inserito in un log entry (top-level, nested in context, o embedded in stringa JSON serializzata) viene mostrato come BIN + ultime 4 nel log di output.
- [ ] CVV non compare mai in nessun log, indipendentemente dal livello o ambiente.
- [ ] JWT completo inserito in un log entry viene completamente oscurato.
- [ ] IP address viene anonimizzato (ultimo ottetto IPv4 / ultimi 80 bit IPv6).
- [ ] Aggiornare la configurazione dei pattern di redazione non richiede rebuild.
- [ ] Test unitari coprono: campo PAN top-level, PAN nested in oggetto, PAN in stringa JSON dentro il campo message.
- [ ] Benchmark: la redazione non degrada la performance oltre il vincolo 2ms p99 complessivo del logging.
