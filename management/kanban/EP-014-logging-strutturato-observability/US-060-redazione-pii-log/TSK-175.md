# TSK-175 — BE PiiRedactionEncoder + config esternalizzata

## Context
US-060 richiede redazione automatica PII nei log prima della scrittura, con regole centralizzate aggiornabili senza redeploy. La redazione deve essere ricorsiva (nested, array, JSON-in-string).
[^src: management/kanban/EP-014-logging-strutturato-observability/US-060-redazione-pii-log/US-060.md §AC]
[^src: design_&_architecture/decisions/ADR-021-structured-logging-pii-redaction.md §4]

## Technical Specs
- **BE:** `PiiRedactionEncoder` custom Logback `CompositeJsonEncoder` wrapper, package `logging`
- **Config:** `PiiRedactionConfig` in `config`, pattern esternalizzati in `application.yml` sotto `app.logging.pii.patterns`
- **Regole di redazione:**

| Campo | Regola |
|---|---|
| PAN | BIN (prime 6) + `****` + ultime 4 |
| CVV/CVC | Completamente rimosso (mai presente) |
| IBAN | Paese (2 char) + `****` + ultime 4. In dev DEBUG: ammessa estesa |
| Email | In prod INFO+: solo dominio `***@example.com`. In dev DEBUG: completa |
| JWT, API key, refresh token, password | Sostituiti con `[REDACTED]` |
| IP address | Ultimo ottetto IPv4 → `0`. IPv6: ultimi 80 bit mascherati |

- **Ricorsività:** applicazione ricorsiva a oggetti nested, array, stringhe contenenti JSON serializzato
- **Ambiente-aware:** `app.logging.pii.environment-aware: true` (prod=strict, dev=relaxed)
- **Hot-reload:** pattern aggiornabili senza rebuild via Spring config refresh

## Implementation Steps
1. Creare `PiiRedactionConfig` che carica pattern da `app.logging.pii.patterns`
2. Implementare `PiiRedactionEncoder` che wrappa `logstash-logback-encoder`
3. Implementare regex per ciascuna categoria PII
4. Implementare scansione ricorsiva: nested objects, array, JSON-in-string
5. Implementare logica ambiente-aware (prod strict vs dev relaxed)
6. Integrare nel `logback-spring.xml` come encoder del profilo prod
7. Verificare che la redazione non degrada performance oltre 2ms p99

## Definition of Done
- [ ] PAN redatto come BIN + ultime 4
- [ ] CVV mai presente in nessun log
- [ ] JWT/API key/password → `[REDACTED]`
- [ ] IP anonimizzato
- [ ] Ricorsività funzionante su nested + JSON-in-string
- [ ] Config aggiornabile senza rebuild
- [ ] Code review approvata
