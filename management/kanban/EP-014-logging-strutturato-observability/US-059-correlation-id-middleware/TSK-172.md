# TSK-172 — BE CorrelationIdFilter servlet filter

## Context
US-059 richiede un Correlation ID end-to-end su ogni richiesta HTTP, propagato via header `X-Correlation-Id` e incluso in tutti i log della richiesta tramite MDC.
[^src: management/kanban/EP-014-logging-strutturato-observability/US-059-correlation-id-middleware/US-059.md §AC]
[^src: design_&_architecture/decisions/ADR-021-structured-logging-pii-redaction.md §3]

## Technical Specs
- **BE:** `CorrelationIdFilter` servlet filter Spring, `@Order(Ordered.HIGHEST_PRECEDENCE + 10)` (prima di `JwtAuthenticationFilter`)
- **Package:** `security/filter`
- **Logica:**
  1. Legge header `X-Correlation-Id` dalla request
  2. Se assente: genera UUID v4
  3. Inserisce in MDC `correlationId` (ereditato da tutti i log della richiesta)
  4. Aggiunge header `X-Correlation-Id` alla response
  5. Pulisce MDC nel `finally` block
- **Coesistenza:** correlationId (applicativo) coesiste con traceId/spanId (Micrometer Tracing)

## Implementation Steps
1. Creare classe `CorrelationIdFilter` implements `OncePerRequestFilter`
2. Implementare logica read/generate/MDC/response header
3. Registrare con `@Order(Ordered.HIGHEST_PRECEDENCE + 10)`
4. Pulire MDC in `finally` per evitare leak cross-request
5. Verificare che il correlationId appare in tutti i log successivi

## Definition of Done
- [ ] Header `X-Correlation-Id` presente in ogni response
- [ ] UUID v4 generato quando header assente nella request
- [ ] Header propagato quando presente nella request
- [ ] MDC `correlationId` presente nel 100% dei log della richiesta
- [ ] MDC pulito nel finally
- [ ] Code review approvata
