# EP-014 — Logging Strutturato e Observability Backend

> Dotare il backend di un sistema di logging strutturato, machine-readable in produzione e human-readable in sviluppo, con redazione automatica PII, Correlation ID end-to-end e logging eventi di sicurezza conforme GDPR.

## Obiettivo
Implementare il sistema di logging descritto in REQ-01 e nelle estensioni REQ-05 §5.1/5.6: formato JSON strutturato in produzione con campi obbligatori (timestamp, level, service, traceId, spanId, userId, message, context), pretty-print colorato in sviluppo, Correlation ID propagato al 100% nei log, redazione automatica PII su campi sensibili (PAN, CVV, IBAN, JWT, API key, IP), test CI di leak detection, logging degli eventi di sicurezza (login, password, MFA, permessi, operazioni finanziarie), e policy di retention GDPR. [^src: wiki/concepts/structured-logging-backend.md §Dettaglio] [^src: wiki/concepts/fintech-security-compliance.md §5.1 — Data privacy nei log]

## Valore di business
- Un log di errore consente triage completo (cosa, dove, per chi, quale richiesta) senza aprire altri sistemi.
- Zero leak di dati sensibili nei log, verificato automaticamente in CI ad ogni build.
- Audit trail completo degli eventi di sicurezza per compliance GDPR e incident response.
