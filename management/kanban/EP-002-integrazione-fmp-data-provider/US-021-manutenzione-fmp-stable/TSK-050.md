# TSK-050 — Migrazione FmpAdapterRestClient + DTO + fixture da v3 a /stable

## Context

FMP ha dismesso gli endpoint v3 il 2025-08-31; il sistema usa ancora path v3 implementati in TSK-009. Questo task esegue la migrazione tecnica dell'unico punto di contatto con il provider esterno, lasciando invariata l'interfaccia `FmpAdapter` e l'intera pipeline a valle (cache, resilienza, rule engine).
[^src: management/kanban/EP-002-integrazione-fmp-data-provider/US-021-manutenzione-fmp-stable/US-021.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Endpoint base URL]

## Technical Specs

**Configurazione**

- `src/main/resources/application.yml`: property `fmp.base-url` → `https://financialmodelingprep.com/stable`.
- `src/docker/.env.example`: variabile `FMP_BASE_URL` → `https://financialmodelingprep.com/stable`.

**`FmpAdapterRestClient.kt` — modifiche di routing**

- `fetchList(endpoint, ticker, limit)`: path corrente `/{endpoint}/{ticker}` diventa `/{endpoint}?symbol={ticker}&limit={limit}&apikey={key}`. Endpoint coinvolti: `income-statement`, `balance-sheet-statement`, `cash-flow-statement`, `key-metrics`, `profile`.
- `searchSymbol(query)`: path `/search?query=` diventa `/search-symbol?query=`.
  [^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Endpoint base URL]
- `screen(criteria)`: path `/stock-screener` diventa `/company-screener`.
  [^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Endpoint base URL]

**DTO in `src/backend/.../fmp/dto/`**

Verificare la compatibilità campo per campo dei seguenti DTO rispetto ai payload `/stable` documentati:
- `ProfileDto`
- `IncomeStatementDto`
- `BalanceSheetDto`
- `CashFlowDto`
- `KeyMetricsDto`
- `ScreenedStockDto`
- `SearchHitDto`

Aggiornare nomi e/o tipi se la nuova API li ha rinominati; mantenere tutti i campi come `val ...: Type?` (null-safety invariante).
[^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Adapter pattern]

**Fixture di test**

- Rigenerare i JSON in `src/backend/src/test/resources/fmp-fixtures/` (o path equivalente) con payload `/stable` reali o shape documentati.
- Aggiornare `FmpFixtureFactory` e `FmpFixtureLoader` di conseguenza.

**Test unit**

- `FmpAdapterRestClientTest`: allineare mock/stub ai nuovi path e parametri.

**Test integration / WebMvc**

Verificare compatibilità fixture nei seguenti test e aggiornare mock/response-stub dove necessario (nessuna modifica alla logica dei test, solo ai dati):
- `SearchControllerIT`
- `AnalysisControllerIT`
- `SearchControllerWebMvcTest`
- `HistoricalControllerWebMvcTest`
- `SearchServiceTest`
- `FinancialDataServiceTest`
- `HistoricalSeriesServiceTest`

## Vincoli e invarianti

1. **Non modificare** `FmpAdapter.kt` (signature dei metodi) — la pipeline a valle non deve cambiare.
2. **Non modificare** `FmpResilienceConfig.kt`, `ResilientFmpAdapter.kt`, `FmpCacheService.kt`, `FmpEventLogger.kt`, `FmpHealthIndicator.kt`, `FmpExceptions.kt`.
3. **Non modificare** le entità DB `FmpFinancialSnapshot`, `FmpProfileSnapshot`, `FmpApiEventLog` né le migration Flyway esistenti.
4. **Non modificare** ADR-004 §1-§6 (il §7 è già aggiornato con la nuova base URL).
5. **Non modificare** i TSK chiusi EP-002 (TSK-008/009/010/011/031/032/037/038).

## Implementation Steps

1. Aggiornare `application.yml` e `.env.example` con la nuova base URL `/stable`.
2. Modificare `FmpAdapterRestClient.kt`: aggiornare `fetchList` (symbol come query param), `searchSymbol` (path `/search-symbol`), `screen` (path `/company-screener`).
3. Confrontare ogni DTO con il payload della nuova API; applicare rename/aggiunta campi mantenendo null-safety.
4. Rigenerare le fixture JSON in `fmp-fixtures/`; aggiornare `FmpFixtureFactory` e `FmpFixtureLoader`.
5. Aggiornare `FmpAdapterRestClientTest` con i nuovi path e parametri attesi.
6. Verificare e allineare i test integration e WebMvc ai nuovi fixture; eseguire `./gradlew test` fino a verde completo.
7. Rebuild immagine container (`docker compose build`) e avvio smoke test: login → screener large+mega cap → ricerca TTD → click ticker pre-renderizzato.

## Definition of Done

- [ ] `GET /api/search?query=TTD` restituisce risultato non vuoto contenente "The Trade Desk Inc.".
- [ ] `GET /api/screener?marketCap=LARGE,MEGA` restituisce una pagina di risultati (non più 503 fmp-unavailable).
- [ ] `GET /api/analysis/AAPL` restituisce dati financials reali (non più 403/503 sotto FMP).
- [ ] `./gradlew test` verde: tutti i test unit + integration BE passano.
- [ ] Rebuild immagine container senza errori; container `vi-app` healthy.
- [ ] Smoke test manuale: login → screener large+mega cap funziona → ricerca TTD funziona → click ticker pre-renderizzato funziona.
- [ ] Nessun path `api/v3` residuo in `application.yml`, `.env.example`, `FmpAdapterRestClient.kt`.
