# US-021 — Migrazione FmpAdapterRestClient da API v3 deprecata a /stable

## Descrizione

Come sistema backend, voglio che `FmpAdapterRestClient` utilizzi esclusivamente gli endpoint `https://financialmodelingprep.com/stable` al posto dei deprecati endpoint v3 (EOL 2025-08-31), affinché le funzionalità di ricerca, screening e analisi finanziaria tornino operative senza errori di chiamata al provider esterno.
[^src: wiki/runbooks/fmp-api-quickstart.md §Migration from v3 to stable]

## Business Rules

- La base URL attiva deve essere `https://financialmodelingprep.com/stable`; quella v3 non deve comparire in nessun file di configurazione né fixture.
- Il ticker viene passato come query parameter `?symbol={ticker}` (non più come path variable) per gli endpoint di statement finanziario e profilo.
- L'endpoint di ricerca simbolo usa `/search-symbol` (non più `/search`).
- L'endpoint di screening usa `/company-screener` (non più `/stock-screener`).
- L'interfaccia `FmpAdapter.kt` e i contratti pubblici (`FmpCacheService`, `ResilientFmpAdapter`, rule engine) rimangono invariati.
- I DTO devono rimanere nullable-aware (`val ...: Type?`) per rispettare la regola "campi mancanti = assenti, mai 0" già fissata in US-004.

## Acceptance Criteria

- [ ] `GET /api/search?query=TTD` restituisce un risultato non vuoto contenente "The Trade Desk Inc.".
- [ ] `GET /api/screener?marketCap=LARGE,MEGA` restituisce una pagina di risultati (nessun errore 503 fmp-unavailable).
- [ ] `GET /api/analysis/AAPL` restituisce dati financials reali (nessun errore 403/503 su chiamata FMP).
- [ ] Tutti i test unit + integration BE passano (`./gradlew test`).
- [ ] L'immagine container si ricostruisce senza errori e il container `vi-app` risulta healthy.
