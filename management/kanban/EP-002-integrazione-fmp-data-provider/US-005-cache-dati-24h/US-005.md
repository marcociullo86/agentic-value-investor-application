# US-005 — Cache dei dati di bilancio con TTL 24h

## Descrizione
Come sistema backend, voglio mettere in cache per 24 ore i dati di bilancio scaricati dal data provider, affinché analisi ripetute sullo stesso ticker non consumino quota API e l'esperienza utente sia rapida. [^src: wiki/concepts/webapp-architecture-vi.md §Livello 2: Backend (Server)]

## Business Rules
- Il TTL della cache per i dati di bilancio è 24 ore.
- Cache hit valido (entro TTL): il sistema usa i dati cache e non chiama il provider esterno.
- Cache miss o scaduta: il sistema chiama il provider, popola la cache, restituisce i dati freschi.
- Ogni risultato fornito al consumatore deve includere il timestamp dei dati di origine (per trasparenza freschezza).

## Acceptance Criteria
- [ ] Una seconda analisi dello stesso ticker entro 24h non genera una nuova chiamata al provider esterno.
- [ ] Una analisi oltre le 24h dalla prima genera una nuova chiamata al provider.
- [ ] Il risultato finale include un timestamp di "dati al" comprensibile dall'utente.
- [ ] Eviction o invalidazione della cache non genera errori bloccanti per analisi in corso.
