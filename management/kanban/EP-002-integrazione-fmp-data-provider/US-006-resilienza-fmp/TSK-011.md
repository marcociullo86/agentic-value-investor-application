# TSK-011 — Resilience4j chain + fallback stale + FmpEventLogger

## Obiettivo

Avvolgere `FmpAdapterRestClient` con la chain Resilience4j e implementare il logging
degli eventi FMP su `fmp_api_event_log`.

## Scope tecnico

- `FmpResilienceConfig` (@Configuration): define `@Bean` per:
  - `RateLimiter`: 30 req/min (conservativo, gap `fmp-rate-limiting` aperto).
  - `Bulkhead`: semaphore 10 concorrenti.
  - `Retry`: max 3, backoff esponenziale 500ms→2s→4s.
  - `CircuitBreaker`: sliding 20, 50% failure rate, half-open dopo 60s.
  - Timeout: 10s.
  [^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Resilienza]
- `FmpAdapterRestClient`: ogni call FMP passa per la chain Resilience4j.
- Fallback in `AnalyzeTickerService.analyze()`:
  - Retry esaurito → `FmpCacheService.getStale()` → marca `is_stale=true`.
  - Nessuna cache → throw `FmpUnavailableException` → HTTP 503 via `GlobalExceptionHandler`.
  [^src: design_&_architecture/decisions/ADR-004-fmp-integration.md §Fallback su cache scaduta]
- `FmpEventLogger`: persiste eventi in `fmp_api_event_log`.
  [^src: design_&_architecture/data/er-diagram.md §fmp_api_event_log]
  - Tipi evento: `FMP_429_RATE_LIMITED`, `FMP_5XX`, `FMP_CIRCUIT_OPEN`,
    `FMP_FALLBACK_STALE`, `FMP_TICKER_NOT_FOUND`.
- `FmpHealthIndicator`: contribuisce a `/actuator/health` (stato circuit breaker).
  [^src: design_&_architecture/api/endpoints-overview.md §Endpoint trasversali]

## Criteri di completamento (DoD)

- [ ] Simulando errore transitorio: il sistema esegue almeno 1 retry prima di fallire.
- [ ] Con cache disponibile e adapter mockato come down: risposta stale marcata
  `X-Data-Stale: true`.
- [ ] Senza cache e adapter down: HTTP 503 ProblemDetails (no stack trace).
- [ ] Evento `FMP_5XX` trovato in `fmp_api_event_log` dopo errore simulato.
- [ ] Unit test `FmpResilienceConfigTest` con `@MockBean FmpAdapterRestClient`.
