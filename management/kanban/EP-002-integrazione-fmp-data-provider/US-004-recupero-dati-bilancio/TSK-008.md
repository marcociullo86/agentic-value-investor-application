# TSK-008 — Flyway migrations V003 + V004: fmp_financial_snapshot, fmp_profile_snapshot, rule_engine_result

## Obiettivo

Creare le migration per le tabelle di cache FMP e per i risultati del Rule Engine.

## Scope tecnico

- `V003__create_fmp_cache.sql`:
  - Tabella `fmp_financial_snapshot`: `id UUID PK`, `ticker FK`, `endpoint VARCHAR(40)`,
    `payload JSONB NOT NULL`, `fetched_at TIMESTAMPTZ`, `is_stale BOOLEAN DEFAULT false`,
    `stale_reason TEXT`.
    [^src: design_&_architecture/data/er-diagram.md §fmp_financial_snapshot]
  - Indice: `(ticker, endpoint, fetched_at DESC)`.
  - Tabella `fmp_profile_snapshot`: `id UUID PK`, `ticker FK`, `price NUMERIC(18,4)`,
    `market_cap`, `sector`, `industry`, `raw_payload JSONB`, `fetched_at`.
    [^src: design_&_architecture/data/er-diagram.md §fmp_profile_snapshot]
  - Indice: `(ticker, fetched_at DESC)`.
- `V004__create_rule_engine_result.sql`:
  - Tabella `rule_engine_result` con tutti i campi (`signals JSONB`, `graham_number`,
    `dcf_intrinsic_value`, `dcf_method`, `mos_signal`, `current_price_at_eval`,
    `source_snapshot_fetched_at`).
    [^src: design_&_architecture/data/er-diagram.md §rule_engine_result]
  - Indice: `(ticker, evaluated_at DESC)`.
  - FK: `ticker → stocks(ticker)`.

## Vincoli e note

- JSONB scelto per flessibilità payload FMP (ADR-003). [^src: design_&_architecture/decisions/ADR-003-database-postgresql.md]
- `is_stale`: usato dal fallback US-006 per marcare snapshot serviti come stale.

## Criteri di completamento (DoD)

- [ ] V003 applica su schema con V001+V002 senza errori.
- [ ] V004 applica su schema con V001+V002+V003 senza errori.
- [ ] Indici verificabili via `\d+ fmp_financial_snapshot` in psql.
- [ ] `flyway validate` pulito.
