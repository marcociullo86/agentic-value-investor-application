# TSK-073 — Implementa SizeRule (SIZE_LATEST) nel RuleEngineService

## Cosa fare

1. Creare la classe `SizeRule : Rule` in `./src/backend/src/main/kotlin/com/valueinvesting/rules/SizeRule.kt`.
2. La regola legge `revenue` dall'`IncomeStatementDto` dell'esercizio annuale più recente restituito da `FmpAdapter.getIncomeStatement(ticker)` (già implementato in TSK-009).
3. Applicare la logica di segnale:
   - `revenue >= 100_000_000` → `GREEN`
   - `revenue < 100_000_000` → `RED`
   - `revenue == null` o assenza di Income Statement → `INDETERMINATE`
4. Il `RuleResult` include i metadati: `revenueLatest` (Long, nullable), `thresholdUsd = 100_000_000`.
5. Registrare `SizeRule` nel `RuleEngineService` (aggiungere al registry delle regole esistenti).
6. Il `ruleId` nel response è `SIZE_LATEST`.
7. Non toccare le regole Buffett pre-esistenti (ROE, ROIC, GrossMargin, NetMargin, CurrentRatio, DebtToIncome, CapexIntensity).

## Acceptance Criteria

- [ ] `GET /api/analysis/{ticker}` risponde con `ruleId = SIZE_LATEST` nel payload accanto ai 7 ruleId Buffett.
- [ ] Per AAPL (revenue > $100M) il segnale è `GREEN` con `revenueLatest` valorizzato.
- [ ] Per un ticker con revenue < $100M il segnale è `RED`.
- [ ] Per un ticker senza Income Statement disponibile il segnale è `INDETERMINATE`, non `RED`.
- [ ] Nessuna regressione sui 7 ruleId Buffett preesistenti.
