# TSK-074 — Test integrazione SizeRule (SIZE_LATEST) — 3 scenari

## Cosa fare

1. Creare `SizeRuleTest.kt` in `./src/backend/src/test/kotlin/com/valueinvesting/rules/`.
2. Scrivere test unitari con fixture mock per i tre scenari:
   - **Verde**: `IncomeStatementDto(revenue = 500_000_000L)` → `RuleResult(signal = GREEN, revenueLatest = 500_000_000L)`.
   - **Rosso**: `IncomeStatementDto(revenue = 50_000_000L)` → `RuleResult(signal = RED, revenueLatest = 50_000_000L)`.
   - **Indeterminato**: `getIncomeStatement()` restituisce lista vuota → `RuleResult(signal = INDETERMINATE)`.
3. Scrivere un integration test (con Testcontainers PostgreSQL) che verifica che `GET /api/analysis/{ticker}` includa `SIZE_LATEST` nel campo `ruleResults` della risposta.
4. Verificare che il `ruleId = SIZE_LATEST` compaia nel contratto OpenAPI (contract test non duplica TSK-088 ma verifica la presenza minima del campo).

## Acceptance Criteria

- [ ] Test Verde: `SizeRule.evaluate()` con revenue 500M ritorna `GREEN`.
- [ ] Test Rosso: `SizeRule.evaluate()` con revenue 50M ritorna `RED`.
- [ ] Test Indeterminato: `SizeRule.evaluate()` con income statement vuoto ritorna `INDETERMINATE`.
- [ ] Integration test: `GET /api/analysis/AAPL` (mock FMP) include `ruleId = SIZE_LATEST` nel response.
- [ ] Tutti i test passano senza modifiche ai test dei 7 ruleId Buffett preesistenti.
