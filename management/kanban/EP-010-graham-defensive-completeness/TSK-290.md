# TSK-290 — FE — Aggiorna TrafficLight component React a 13 ruleId con sezione Graham Defensive

## Context

Con i 6 nuovi `ruleId` Graham implementati nel BE, il componente `TrafficLightPanel` deve visualizzarli in una sezione "Criteri Graham Defensive" separata dai 7 "Criteri Buffett Quality" preesistenti. Il contratto TypeScript deve riflettere i nuovi campi metadato.
[^src: wiki/concepts/value-investing-rule-engine.md §Output del Rule Engine: il "Traffic Light"]
[^src: wiki/concepts/webapp-architecture-vi.md §Architettura applicativa]

## Technical Specs

**Componente target:** `TrafficLightPanel` (o equivalente) in `./src/frontend/app/` (implementato in TSK-021)

**Modifiche:**
1. Aggiungere 6 `RuleSignalCard` per i nuovi ruleId Graham: `SIZE_LATEST`, `EARNINGS_STABILITY_10Y`, `EPS_GROWTH_10Y`, `PE_3Y_AVG`, `PB_LATEST`, `DIVIDEND_CONTINUITY_20Y`
2. Organizzare il panel in due sezioni visivamente distinte:
   - **"Criteri Buffett Quality"** — 7 ruleId preesistenti (invariati)
   - **"Criteri Graham Defensive"** — 6 nuovi ruleId
3. Riusare il componente `RuleSignalCard` esistente (stesso pattern GREEN/YELLOW/RED/INDETERMINATE + icona accessibile + alt-text)
4. Sottotitolo osservato per ogni nuova card:
   - `SIZE_LATEST`: "Revenue: $XXB"
   - `EARNINGS_STABILITY_10Y`: "Anni positivi: X/10"
   - `EPS_GROWTH_10Y`: "Crescita EPS: +X.X%"
   - `PE_3Y_AVG`: "P/E 3y: XX.X"
   - `PB_LATEST`: "P/B: X.X"
   - `DIVIDEND_CONTINUITY_20Y`: "Anni consecutivi: XX"
5. Aggiornare i TypeScript types `RuleEngineResult` con i campi metadato dei 6 nuovi ruleId (da OpenAPI TSK-289 o manualmente se non auto-generato)

**Invarianti:** nessuna regressione sull'UI dei 7 ruleId Buffett; responsive mobile invariato

## Implementation Steps

1. Aggiornare i tipi TypeScript `RuleEngineResult` / `RuleResultItem` per i nuovi campi
2. Aggiungere la sezione "Criteri Graham Defensive" con heading separato nel `TrafficLightPanel`
3. Istanziare 6 `RuleSignalCard` con i sottotitoli osservati
4. Verificare rendering mobile (viewport <= 375px) e accessibilità badge (alt-text + icona)

## Definition of Done

- [ ] `/analysis/{ticker}` mostra 13 `RuleSignalCard` totali (7 Buffett + 6 Graham)
- [ ] Le due sezioni sono visualmente distinte (heading separato)
- [ ] Ogni card Graham mostra il valore osservato nel sottotitolo
- [ ] Layout responsive invariato su viewport mobile
- [ ] Badge hanno alt-text accessibile (coerente con US-014)
- [ ] Nessuna regressione sull'UI dei 7 ruleId Buffett preesistenti
