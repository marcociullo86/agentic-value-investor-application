# TSK-084 — Migration V010__fmp_dividend_history_snapshot — tabella cache dividendi

## Cosa fare

1. Creare il file di migrazione `V010__fmp_dividend_history_snapshot.sql` in `./src/backend/src/main/resources/db/migration/`.
2. La migrazione crea la tabella `fmp_dividend_history_snapshot` con almeno:
   ```sql
   CREATE TABLE fmp_dividend_history_snapshot (
     id           BIGSERIAL PRIMARY KEY,
     ticker       VARCHAR(20)  NOT NULL,
     record_date  DATE         NOT NULL,
     dividend     DECIMAL(12,6),
     adj_dividend DECIMAL(12,6),
     label        VARCHAR(100),
     fetched_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
     expires_at   TIMESTAMPTZ  NOT NULL
   );
   CREATE INDEX idx_div_hist_ticker_date ON fmp_dividend_history_snapshot (ticker, record_date DESC);
   CREATE INDEX idx_div_hist_expires ON fmp_dividend_history_snapshot (expires_at);
   ```
3. La tabella segue il pattern `fmp_cache` esistente: `fetched_at` + `expires_at` per TTL 24h.
4. Verificare che Flyway applichi la migration senza conflitti con le migration preesistenti (V001..V009).

## Acceptance Criteria

- [ ] La migration `V010__fmp_dividend_history_snapshot.sql` è applicata da Flyway senza errori su un DB PostgreSQL 17 fresh.
- [ ] La tabella `fmp_dividend_history_snapshot` esiste con i campi e indici attesi.
- [ ] `flyway validate` passa (checksum stabile).
- [ ] Nessun conflitto con le migration V001..V009 preesistenti.
