# TSK-286 — DB — Migration V0XX__fmp_dividend_history_snapshot — tabella cache dividendi

## Context

La cache dei dividendi FMP richiede una tabella dedicata per rispettare il pattern TTL 24h già adottato per `fmp_cache`. Il numero di versione esatto va determinato inspecionando l'ultima migration applicata (VNN) e usando VNN+1.
[^src: management/kanban/EP-010-graham-defensive-completeness/US-037-regola-continuita-dividendi-graham/US-037.md §Business Rules]

## Technical Specs

**File:** `V{N}__fmp_dividend_history_snapshot.sql` in `./src/backend/src/main/resources/db/migration/`

**DDL:**
```sql
CREATE TABLE fmp_dividend_history_snapshot (
  id           BIGSERIAL    PRIMARY KEY,
  ticker       VARCHAR(20)  NOT NULL,
  record_date  DATE         NOT NULL,
  dividend     DECIMAL(12,6),
  adj_dividend DECIMAL(12,6),
  frequency    VARCHAR(50),
  fetched_at   TIMESTAMPTZ  NOT NULL DEFAULT now(),
  expires_at   TIMESTAMPTZ  NOT NULL
);
CREATE INDEX idx_div_hist_ticker_date ON fmp_dividend_history_snapshot (ticker, record_date DESC);
CREATE INDEX idx_div_hist_expires     ON fmp_dividend_history_snapshot (expires_at);
```

Pattern identico a `fmp_cache`: `fetched_at` + `expires_at` per TTL 24h.

## Implementation Steps

1. Verificare l'ultima migration in `db/migration/` e usare il numero successivo come versione
2. Creare il file `V{N}__fmp_dividend_history_snapshot.sql` con il DDL sopra
3. Eseguire `./gradlew flywayValidate` su un DB PostgreSQL 17 fresh — deve passare
4. Verificare che la tabella e i due indici esistano

## Definition of Done

- [ ] Migration applicata da Flyway senza errori su DB PostgreSQL 17 fresh
- [ ] Tabella `fmp_dividend_history_snapshot` con campi e indici attesi
- [ ] `flyway validate` passa (checksum stabile, no conflitti con migration precedenti)
- [ ] Nessun conflitto con le migration precedenti
