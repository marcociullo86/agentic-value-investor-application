# TSK-097 — Test integrazione Filing10KQDownloaderService — cache TTL, limit 50MB, no-regressione FMP

## Cosa fare

1. Creare `Filing10KQDownloaderServiceTest.kt` con Testcontainers PostgreSQL + WireMock.
2. Test da implementare:
   - **Happy path**: mock SEC EDGAR restituisce HTML fixture da 5KB; il servizio persiste il record in `filing_blob` con `chunkable_text` non vuoto.
   - **Cache hit**: stessa chiamata per lo stesso accession number entro TTL → nessuna nuova HTTP call SEC.
   - **Dopo TTL 90gg** (forzando `expires_at` nel passato nel DB): ri-fetcha il filing.
   - **Limite 50MB**: mock restituisce HTML da 51MB (mock string > 50M chars); verificare che il record NON venga persistito e che venga loggato l'evento.
   - **FMP getSecFilings vuoto**: mock FMP restituisce lista vuota → `fetchAndCache` restituisce lista vuota senza eccezione.
3. Verificare che i test FMP preesistenti non siano regressi.

## Acceptance Criteria

- [ ] Happy path: record persisto con `chunkable_text` valorizzato.
- [ ] Cache hit: WireMock non riceve 2a chiamata HTTP SEC per lo stesso accession.
- [ ] Post-TTL: rifetch avviene.
- [ ] Limite 50MB: no persist + log evento.
- [ ] FMP vuoto: lista vuota senza eccezione.
