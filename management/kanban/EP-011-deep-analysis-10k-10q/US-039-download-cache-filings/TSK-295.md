# TSK-295 — BE: fix discovery filing SEC via FMP `getSecFilings`

## Obiettivo
La discovery dei 10-K/10-Q via FMP `/stable/sec-filings-search/symbol` (introdotta in TSK-094) restituiva "No SEC filings" su ticker validi. Sul campo (ticker TTD, mag 2026) l'endpoint si comporta diversamente dalla doc: `from`/`to` sono **obbligatori** (400 senza finestra), **ignora `formType` lato server** e ritorna TUTTI i form type ordinati DESC per `filingDate`. Il fix rende la discovery robusta a questo comportamento reale.

## Scope (cosa è stato fatto)

### `FmpAdapterRestClient.getSecFilings` + helper `fetchSecFilingsByFormType`
- **`from`/`to` obbligatori**: si calcola una finestra temporale `to = oggi`, `from = oggi - lookbackMonths` (default **15 mesi** → ultimo 10-K annuale + ultimi 10-Q trimestrali, con margine per ritardi di deposito). Senza finestra l'endpoint risponde 400 BAD_REQUEST.
- **Una chiamata per `formType`** (10-K, 10-Q) all'endpoint `/symbol` con `formType` in querystring (forward-compatible se FMP attiverà il filtro server-side), poi **filtro client-side** per quel form type — l'endpoint ignora `formType` lato server.
- L'endpoint gemello `/sec-filings-search/form-type` **ignora il `symbol`** (ritorna i filing di tutte le aziende) → inutilizzabile per ticker singolo, scartato.
- **Page-limit ampio** (`SEC_FILINGS_PAGE_LIMIT = 1000`): i 10-K/10-Q (pochi) sono annegati tra decine di Form-4/8-K più recenti; con un limit basso (es. 10) verrebbero esclusi dalla pagina → root cause del bug "No SEC filings".
- **Risultato**: union dei form type richiesti, deduplicata per link canonico (`finalLink` ?: `link`), ordinata DESC per `filingDate`, troncata a `limit` (cap totale, non per-tipo).
- **Parsing data tollerante**: ordinamento per `filingDate` con fallback su stringa vuota per i record con data assente (nessun NPE / nessuna eccezione di parsing su payload incompleti).

### Error policy per chiamata
- 429 → `FmpUnavailableException(429)` (route Resilience4j).
- 5xx → `FmpUnavailableException(status)`.
- 4xx (non 429) → trattato come "nessun filing per quel tipo" (`emptyList`, via sentinel locale `EmptySecFilingsSentinelException`).

## Acceptance Criteria
- [x] `getSecFilings("TTD")` su ticker valido non restituisce più lista vuota spuria (bug "No SEC filings" risolto).
- [x] La chiamata FMP include sempre `from`/`to` (nessun 400 da finestra mancante).
- [x] Una chiamata distinta per ciascun `formType` con filtro client-side sul tipo restituito.
- [x] Page-limit ampio: i 10-K/10-Q non vengono esclusi da pagine dominate da Form-4/8-K.
- [x] Risultato deduplicato per link, ordinato DESC per `filingDate`, troncato a `limit`.
- [x] Nessuna regressione sui restanti metodi `FmpAdapter`.
