# TSK-098 — Migration V012__pgvector_enable + filing_chunks schema + indice HNSW

## Cosa fare

1. Creare `V012__pgvector_enable.sql` in `./src/backend/src/main/resources/db/migration/`.
2. La migrazione esegue:
   ```sql
   CREATE EXTENSION IF NOT EXISTS vector;

   CREATE TABLE filing_chunks (
     id              BIGSERIAL PRIMARY KEY,
     filing_blob_id  BIGINT       NOT NULL REFERENCES filing_blob(id) ON DELETE CASCADE,
     ticker          VARCHAR(20)  NOT NULL,
     filing_type     VARCHAR(10)  NOT NULL,
     filing_date     DATE,
     chunk_index     INT          NOT NULL,
     content         TEXT         NOT NULL,
     embedding       vector(1024),
     metadata        JSONB,
     created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
     CONSTRAINT uq_filing_chunks_blob_chunk UNIQUE (filing_blob_id, chunk_index)
   );

   CREATE INDEX idx_filing_chunks_hnsw ON filing_chunks
     USING hnsw (embedding vector_cosine_ops)
     WITH (m = 16, ef_construction = 64);

   CREATE INDEX idx_filing_chunks_ticker ON filing_chunks (ticker, filing_type);
   ```
3. Verificare applicazione su PostgreSQL 17 con estensione pgvector installata.

## Acceptance Criteria

- [ ] `V012__pgvector_enable.sql` applicata da Flyway senza errori su PostgreSQL 17 + pgvector.
- [ ] La tabella `filing_chunks` esiste con colonne `embedding vector(1024)` e indice HNSW.
- [ ] Il vincolo `UNIQUE (filing_blob_id, chunk_index)` è applicato.
- [ ] `flyway validate` passa.
- [ ] L'indice HNSW è presente (`\d filing_chunks` mostra l'indice).
