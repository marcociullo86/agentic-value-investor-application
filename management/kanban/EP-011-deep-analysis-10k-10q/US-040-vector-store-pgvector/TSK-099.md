# TSK-099 — Sidecar Python FastAPI per embeddings Snowflake Arctic Embed L v2.0 (Dockerfile + app)

## Cosa fare

1. Creare la directory `./src/embeddings-sidecar/` con:
   - `app.py`: FastAPI app con endpoint `POST /embed` che accetta `{ "texts": ["..."] }` e restituisce `{ "embeddings": [[...1024 floats...]] }`.
   - `requirements.txt`: `fastapi`, `uvicorn`, `sentence-transformers>=2.7`, `torch` (CPU-only), `numpy`.
   - `Dockerfile`: immagine base `python:3.12-slim`, installa requirements, scarica il modello `Snowflake/snowflake-arctic-embed-l-v2.0` al build time (`python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('Snowflake/snowflake-arctic-embed-l-v2.0')"`).
2. Il modello è pre-caricato all'avvio del sidecar (non al primo request) per evitare cold start.
3. L'endpoint `/embed` gestisce batch di testi (fino a 32 testi per request): `model.encode(texts, normalize_embeddings=True)`.
4. Aggiungere il sidecar al `docker-compose.yml` / `docker-compose.dev.yml` come servizio `embeddings-sidecar` sulla porta `8001` (interna).
5. Health check: `GET /health` risponde `{"status": "ok", "model": "Snowflake/snowflake-arctic-embed-l-v2.0"}`.
6. Esporre la porta interna solo tra container (no binding pubblico in produzione).

## Acceptance Criteria

- [ ] `docker-compose up embeddings-sidecar` avvia il sidecar senza errori.
- [ ] `POST /embed` con `{ "texts": ["hello world"] }` restituisce un vettore di 1024 dimensioni.
- [ ] `GET /health` risponde `{"status": "ok"}`.
- [ ] Il modello è caricato al build time (il primo request non scarica il modello da HuggingFace Hub).
- [ ] Il sidecar è nel `docker-compose.yml` con health check configurato.

- Batch size 32: ottimale per CPU; per GPU aumentare in futuro.
- Il modello Snowflake Arctic Embed L v2.0 pesa ~450MB: il build Docker impiegherà qualche minuto la prima volta.
- Stack: Python 3.12 + FastAPI + sentence-transformers + Docker. [^src: raw/tech_stack.md]
