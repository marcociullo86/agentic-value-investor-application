# TSK-104 — Configura AnthropicClient + ResilienceConfig circuit breaker per LLM Claude Opus 4.7

## Cosa fare

1. Aggiungere la dipendenza `com.anthropic:anthropic-java:<latest>` in `build.gradle.kts`.
   - Se il SDK ufficiale non è su Maven Central (gap `tpm-anthropic-sdk-jvm-version`), implementare un HTTP client diretto usando Spring `RestClient` verso `https://api.anthropic.com/v1/messages` con header `x-api-key: ${ANTHROPIC_API_KEY}`, `anthropic-version: 2023-06-01`.
2. Creare `AnthropicConfig` in `./src/backend/src/main/kotlin/com/valueinvesting/config/AnthropicConfig.kt`:
   - Bean `AnthropicClient` (o wrapper `AnthropicRestClient`) configurato con `anthropic.api-key` (da env var `ANTHROPIC_API_KEY`).
   - Modello default: `claude-opus-4-7` (configurabile via `anthropic.model`).
3. Creare `LlmResilienceConfig`:
   - `CircuitBreaker` Resilience4j `llm-claude`: `failureRateThreshold = 50`, `waitDurationInOpenState = 60s`, `slidingWindowSize = 5`.
   - `RateLimiter` `llm-claude`: `limitForPeriod = 12` (max 12 chiamate per analisi, US-041), `limitRefreshPeriod = 1min`.
   - `Retry` `llm-claude`: 3 tentativi su `AnthropicRateLimitException` (429), backoff esponenziale 2s→4s→8s.
4. Esporre `anthropic.api-key`, `anthropic.model`, `anthropic.timeout-seconds` in `application.yaml`.

## Acceptance Criteria

- [ ] Il bean `AnthropicClient` (o wrapper) è presente nel contesto Spring.
- [ ] `ANTHROPIC_API_KEY` è letta da env var (non hardcoded).
- [ ] Il `CircuitBreaker` `llm-claude` si apre dopo 3 fallimenti consecutivi (test con mock).
- [ ] Il `RateLimiter` `llm-claude` limita a 12 chiamate/min.
- [ ] L'avvio fallisce con errore chiaro se `ANTHROPIC_API_KEY` è assente (fail-fast).
