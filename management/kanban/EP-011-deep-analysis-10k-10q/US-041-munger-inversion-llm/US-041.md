# US-041 — Analisi Munger-inversione su 10-K + 10-Q via LLM

## Descrizione
Come investitore retail, voglio che il sistema interroghi i filing 10-K e 10-Q ufficiali con un set fisso di 10 query di inversione Munger-style ("cosa potrebbe far fallire questa azienda?"), produca un report strutturato con livello di rischio, lista rischi, lista punti di forza e segnali recenti dal 10-Q più aggiornato, affinché possa valutare il rischio qualitativo che il Rule Engine puramente numerico non vede. [^src: wiki/runbooks/sec-10k-10q-analysis-playbook.md §Step 3 — Analisi Munger-inversione]

## Business Rules
- Modello LLM: **Claude Opus 4.7** (`claude-opus-4-7`), confermato dall'utente come scelta di prodotto.
- Vector store: pgvector con embedding Arctic (US-040), retrieval top-k = 8 chunk per query.
- Set di 10 query fisse di inversione documentato in [[munger-inversion-rag]] §"Le 10 Query Munger" (sezione canonica wiki): risks/competitive/disruption, debt/going-concern/liquidity, technology obsolescence, customer concentration, fraud/governance, regulatory penalties, guidance/missed estimates, subsequent events, supplier dependency, geographic concentration. Le query sono caricate da risorsa Spring `classpath:munger-queries.json` che referenzia la wiki come source-of-truth (no hardcoding in codice).
- Output strutturato JSON con i campi: `livello_rischio` ∈ {`RISCHIO_ESTREMO`, `RISCHIO_ALTO`, `RISCHIO_MODERATO`, `RISCHIO_BASSO`}, `rischi_principali` (lista), `punti_di_forza` (lista), `segnali_recenti_10Q` (lista, derivati dal 10-Q più recente vs 10-K).
- L'analisi opera sempre su un combo: ultimo 10-K + ultimi 1-2 10-Q dello stesso ticker.
- Caching del report: persistere risultato in tabella `deep_analysis_report` con `(ticker, filing_combo_hash) → report_json + generated_at`; nuovo run solo se nuovo filing disponibile o `generated_at > 90 giorni`.
- Costi LLM: il numero massimo di chiamate Claude Opus per analisi è limitato a 12 (10 query + 1 sintesi + 1 fallback) — log evento se la stima ex-ante supera la soglia.
- Tutte le citazioni nel report devono includere il `chunk_index` di origine, permettendo trace-back al testo SEC originale.

## Acceptance Criteria
- [ ] Per un ticker con 10-K + 10-Q indicizzati (US-040 completata) il sistema genera un `deep_analysis_report` con i quattro campi popolati.
- [ ] Il `livello_rischio` è uno dei quattro valori canonici.
- [ ] Ogni rischio elencato include un riferimento al `chunk_index` del 10-K/10-Q che lo cita.
- [ ] La seconda chiamata sullo stesso filing combo entro 90 giorni riusa il report cached (cache hit verificato in test).
- [ ] Test di integrazione su 10-K di test verifica che la pipeline tollera: chunk mancanti (10-Q non disponibile), risposte LLM malformate (retry + fallback), timeout chiamata LLM (errore esplicito loggato).
- [ ] Costo LLM stimato per ticker S&P500 medio (10-K ~150k token) documentato nel runbook con esempio reale.
