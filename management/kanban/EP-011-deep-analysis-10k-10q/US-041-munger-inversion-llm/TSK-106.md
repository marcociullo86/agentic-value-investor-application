# TSK-106 — Migration V013__filing_analysis — tabella cache deep_analysis_report

## Cosa fare

1. Creare `V013__filing_analysis.sql` in `./src/backend/src/main/resources/db/migration/`.
2. La migrazione crea:
   ```sql
   CREATE TABLE deep_analysis_report (
     id                   BIGSERIAL PRIMARY KEY,
     ticker               VARCHAR(20)  NOT NULL,
     filing_combo_hash    VARCHAR(64)  NOT NULL,
     report_json          JSONB        NOT NULL,
     livello_rischio      VARCHAR(30)  NOT NULL,
     generated_at         TIMESTAMPTZ  NOT NULL DEFAULT now(),
     expires_at           TIMESTAMPTZ  NOT NULL,
     llm_calls_count      INT,
     CONSTRAINT uq_deep_report_ticker_hash UNIQUE (ticker, filing_combo_hash)
   );
   CREATE INDEX idx_deep_report_ticker_date ON deep_analysis_report (ticker, generated_at DESC);
   CREATE INDEX idx_deep_report_expires ON deep_analysis_report (expires_at);
   ```
3. Verificare applicazione senza errori.

## Acceptance Criteria

- [ ] `V013__filing_analysis.sql` applicata da Flyway senza errori.
- [ ] Tabella `deep_analysis_report` esiste con vincolo `UNIQUE (ticker, filing_combo_hash)`.
- [ ] `flyway validate` passa.

## Note implementative

- `filing_combo_hash`: SHA-256 della concatenazione degli `accession_number` dei filing usati nell'analisi.
- `expires_at = generated_at + 90 giorni`.
- Stack: PostgreSQL 17 + Flyway 10.x. [^src: raw/tech_stack.md]
