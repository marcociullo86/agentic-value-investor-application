# TSK-158 — FE: LlmBudgetAdminPanel

## Obiettivo
Implementare il pannello admin per la modifica runtime del cap mensile LLM, accessibile solo agli utenti con ruolo `ADMIN`.

## Scope
- Componente React `LlmBudgetAdminPanel` (Next.js App Router, accessibile da una route admin dedicata o come sezione della pagina admin esistente).
- **Lettura cap corrente**: chiamata a `GET /admin/llm-cost` al mount → popola campo numerico con `monthlyCapUsd` corrente + mostra `utilization%` e `totalCostUsd` del mese.
- **Form**: campo numerico `monthlyCapUsd` (validazione client: `> 0` e `<= absoluteMaxUsd` letto dal payload); campo testo opzionale `reason`.
- **Modal di conferma**: mostra diff `old → new` (es. "$50.00 → $75.00"), pulsante "Conferma" / "Annulla".
- **Chiamata PUT**: body `{ "monthlyCapUsd": <decimal>, "reason": "<string>" }` a `PUT /admin/llm-cost/budget`.
- **Gestione errori**: `400 BUDGET_CAP_INVALID` (RFC 9457) → toast con `problem.detail`. Errore 403 → redirect o messaggio "Non autorizzato".
- **Refresh post-successo**: rilegge `GET /admin/llm-cost` e aggiorna utilization% mostrata.
- **Gate UI**: componente non renderizzato (o redirect) se utente non ha ruolo `ADMIN`.

## DoD
- Pannello visibile solo con ruolo ADMIN (test Vitest con mock authStore).
- Modal mostra correttamente old/new (test Vitest).
- Chiamata PUT con body corretto (test Vitest con MSW mock).
- Toast su 400 BUDGET_CAP_INVALID mostra il campo `detail` (test Vitest).
- Nessun side-effect con stesso valore (idempotenza verificata lato BE — questo TSK cura solo il FE).
