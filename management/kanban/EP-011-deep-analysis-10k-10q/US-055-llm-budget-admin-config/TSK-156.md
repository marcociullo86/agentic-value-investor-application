# TSK-156 — BE: servizi cost+budget + endpoint admin

## Obiettivo
Implementare tutta la logica BE di telemetria LLM e configurazione runtime del budget secondo ADR-019.

## Scope

### Servizi
- `LlmCostCounterService`: UPSERT atomico PostgreSQL su `llm_cost_counter` per mese corrente (thread-safe; usa `INSERT ... ON CONFLICT DO UPDATE`).
- `LlmCallLogger` AOP `@Around` su `AnthropicClient.complete` e `GeminiClient.complete`: misura `latency_ms`, calcola `cost_usd` post-call tramite pricing config (env var `LLM_COST_INPUT_PER_1K_USD_OPUS`, `LLM_COST_OUTPUT_PER_1K_USD_OPUS`, `LLM_COST_INPUT_PER_1K_USD_GEMINI_FLASH`, `LLM_COST_OUTPUT_PER_1K_USD_GEMINI_FLASH`), persiste row su `llm_call_log`, chiama `LlmCostCounterService.upsert(...)`.
- `LlmBudgetConfigService`: lettura `monthly_cap_usd` da `llm_budget_config` con cache in-memory (`@EventListener` su evento Spring `BudgetCapChangedEvent` per invalidazione). Fallback su property `llm.budget.monthly-cap-usd` (default `50.00`) se row non esiste.
- `LlmBudgetGuard.check()`: controlla frozen flag (property `llm.budget.frozen`, toggle live via endpoint) → lancia `LlmFrozenException` → HTTP 503 `LLM_FROZEN_BY_ADMIN` (ProblemDetail RFC 9457). Posizionato prima della Resilience4j chain (ADR-017 §5).
- Alert cron `@Scheduled` ogni 5 min: controlla `total_cost_usd / monthly_cap_usd`; 80% → Slack webhook (idempotente tramite `alert_80_sent_at`); 100% → log ERROR + Slack.
- Reset mensile `@Scheduled("0 0 0 1 * *")` UTC: UPSERT nuova row `llm_cost_counter` per mese nuovo con campi a 0.

### Endpoint (tutti `ROLE_ADMIN`)
- `GET /admin/llm-cost`: risponde con `utilization%`, `monthlyCapUsd` (runtime), `totalCostUsd`, breakdown per `purpose`, history 30gg, `frozen` boolean.
- `POST /admin/llm-cost/freeze`: imposta `llm.budget.frozen=true` runtime. Risponde 200.
- `POST /admin/llm-cost/unfreeze`: sblocca. Risponde 200.
- `PUT /admin/llm-cost/budget`: body `{ "monthlyCapUsd": <decimal>, "reason": "<string opzionale>" }`. Validazione: `monthlyCapUsd > 0 && <= LLM_BUDGET_ABSOLUTE_MAX_USD (env, default 10000)`. Risposta `400 BUDGET_CAP_INVALID` (RFC 9457) se fuori range. Idempotenza: stesso valore = no-op. Emette audit entry `LLM_BUDGET_CAP_CHANGED` (tabella audit ADR-008/ADR-010) con `actor_user_id`, `payload_json = { oldCapUsd, newCapUsd, reason }`. Pubblica `BudgetCapChangedEvent` per invalidazione cache `LlmBudgetConfigService`.

## DoD
- `LlmCallLogger` intercetta realmente le chiamate Anthropic/Gemini (verificato in test IT con mock provider).
- UPSERT `llm_cost_counter` sotto carico concorrente (2 chiamate parallele) non produce double-count (test Testcontainers).
- `PUT /admin/llm-cost/budget` con valore valido → row `llm_budget_config` aggiornata + audit entry emessa + `GET /admin/llm-cost` riflette nuovo cap immediatamente.
- Endpoint protetti da `ROLE_ADMIN` (test 403 per USER).
