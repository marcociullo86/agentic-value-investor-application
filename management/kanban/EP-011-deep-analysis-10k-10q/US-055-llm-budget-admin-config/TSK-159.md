# TSK-159 — QA: integration tests LLM budget config

## Obiettivo
Coprire con integration test (Testcontainers + WireMock) tutti i path critici del budget admin config introdotti da ADR-019 §4.bis.

## Scope

### Test BE (JUnit 5 + Testcontainers)
1. **PUT happy path + cache invalidation + audit**: `PUT /admin/llm-cost/budget` con `monthlyCapUsd=75.00` → verifica row `llm_budget_config` aggiornata → verifica audit entry `LLM_BUDGET_CAP_CHANGED` emessa con old/new → verifica `GET /admin/llm-cost` riflette `monthlyCapUsd=75.00` immediatamente (cache invalidata).
2. **PUT invalid — 400**: `PUT /admin/llm-cost/budget` con `monthlyCapUsd=0` → risposta `400 BUDGET_CAP_INVALID` (ProblemDetail RFC 9457, campo `type` + `title` + `detail` presenti). Stesso per valore negativo e per valore > `LLM_BUDGET_ABSOLUTE_MAX_USD`.
3. **PUT ruolo non-admin — 403**: utente con ruolo `USER` su `PUT /admin/llm-cost/budget` → risposta 403.
4. **Kill-switch / freeze**: `POST /admin/llm-cost/freeze` → successiva chiamata `AnthropicClient` simulata → risposta `503 LLM_FROZEN_BY_ADMIN` (ProblemDetail). `POST /admin/llm-cost/unfreeze` → chiamata ripristinata.
5. **Cache invalidation LlmBudgetConfigService**: doppia lettura `monthly_cap_usd` prima/dopo `PUT` verifica che il valore in-memory sia aggiornato (nessuna lettura stale dal DB).
6. **Idempotenza PUT**: stesso valore due volte → nessuna nuova audit entry alla seconda chiamata.

### Test FE (Vitest + MSW)
- Copertura scenari `LlmBudgetAdminPanel` (vedi TSK-158 DoD).

## DoD
- Tutti i 6 scenari BE superano su Testcontainers PostgreSQL 17.
- Test coverage branch su `LlmBudgetConfigService` (cache hit e miss) >= 80%.
