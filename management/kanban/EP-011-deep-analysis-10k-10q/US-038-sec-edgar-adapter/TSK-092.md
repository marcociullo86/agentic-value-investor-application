# TSK-092 — Implementa cache CIK→ticker (TTL 30 giorni) per SecEdgarRestClient

## Cosa fare

1. Aggiungere la cache CIK→ticker in `SecEdgarRestClient.resolveCikFromTicker()` usando Spring Cache o una mappa in-memory con `Caffeine` (TTL 30 giorni).
2. La chiave di cache è il `ticker` normalizzato (uppercase). Il valore è il `CIK` (stringa, 10 cifre con zero-padding).
3. Alla seconda chiamata per lo stesso `ticker` entro 30 giorni, il metodo non esegue la richiesta HTTP a SEC (cache hit).
4. Esporre la configurazione cache in `application.yaml`: `sec.edgar.cik-cache-ttl-days = 30`.
5. Log DEBUG alla prima risoluzione CIK per ticker (`CIK resolved: {ticker} → {cik}`).

## Acceptance Criteria

- [ ] Prima chiamata `resolveCikFromTicker("AAPL")` emette esattamente 1 richiesta HTTP a SEC.
- [ ] Seconda chiamata entro TTL non emette nuova richiesta HTTP (verificato via test con mock HTTP).
- [ ] Scadenza TTL 30 giorni: dopo la scadenza una nuova chiamata ri-emette la richiesta HTTP.
- [ ] La proprietà `sec.edgar.cik-cache-ttl-days` controlla il TTL.
