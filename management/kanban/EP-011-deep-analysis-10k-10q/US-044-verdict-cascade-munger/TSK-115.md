# TSK-115 — Implementa MungerDecisionService con cascade 6 verdetti

## Cosa fare

1. Creare `MungerDecisionService` in `./src/backend/src/main/kotlin/com/valueinvesting/service/MungerDecisionService.kt`.
2. Il servizio espone: `compute(ticker: String): VerdictPayload`.
3. Raccogliere gli input (dai servizi delle US precedenti):
   - `ruleResults`: lista dei 13 `RuleResult` (7 Buffett + 6 Graham EP-010).
   - `livelloRischio` da `MungerInversionReport` (US-041).
   - `newsSentimentDominante` da `NewsSentimentResult` (US-042).
   - `panicDiscount`, `deteriorationWarning` da `PriceActionSnapshot` (US-043).
4. Cascade logica (ordine fisso, primo match vince):
   1. `livelloRischio == RISCHIO_ESTREMO` → `BOCCIATO_QUALITATIVO`
   2. `newsSentimentDominante == STRUCTURAL_DAMAGE` → `BOCCIATO_VALUE_TRAP`
   3. `ruleResults.count { it.signal == RED } >= 4` → `BOCCIATO_NUMERICO`
   4. `panicDiscount AND newsSentimentDominante == TEMPORARY_PANIC AND livelloRischio in {RISCHIO_BASSO, RISCHIO_MODERATO} AND ruleResults.count { it.signal == RED } <= 2` → `APPROVATO_PANIC_BUY`
   5. `ruleResults.all { it.signal in {GREEN, YELLOW} } AND livelloRischio in {RISCHIO_BASSO, RISCHIO_MODERATO} AND newsSentimentDominante != STRUCTURAL_DAMAGE` → `APPROVATO`
   6. Altrimenti → `WATCHLIST`
5. Calcolare `positionSizePct`: APPROVATO_PANIC_BUY → 5.0, APPROVATO → 3.0, WATCHLIST → 0.0, BOCCIATO_* → 0.0.
6. Output `VerdictPayload`: `verdettoCLasse`, `positionSizePct`, `partialBasis`, `motivazioneAggregata`, `ruleCountByColor`, riferimenti agli input.

## Acceptance Criteria

- [ ] Tutti i 6 casi della cascade sono implementati nel corretto ordine.
- [ ] `RISCHIO_ESTREMO` → `BOCCIATO_QUALITATIVO` (step 1 vince su tutto).
- [ ] `APPROVATO_PANIC_BUY` con position 5%.
- [ ] `partialBasis = true` se EP-010 non completata (< 13 ruleId).
- [ ] Il servizio è deterministico: stessi input → stesso output.
