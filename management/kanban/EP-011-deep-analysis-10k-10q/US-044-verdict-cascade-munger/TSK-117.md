# TSK-117 — Test unitari MungerDecisionService — tutte e 6 le combinazioni di cascade + determinismo

## Cosa fare

1. Creare `MungerDecisionServiceTest.kt` con test unitari puri (no DB, no HTTP).
2. Test da implementare per ognuno dei 6 verdetti:
   - **BOCCIATO_QUALITATIVO**: input con `livelloRischio = RISCHIO_ESTREMO` → verdetto atteso.
   - **BOCCIATO_VALUE_TRAP**: `RISCHIO_MODERATO` + `STRUCTURAL_DAMAGE` dominante → verdetto atteso.
   - **BOCCIATO_NUMERICO**: `RISCHIO_MODERATO` + `NEUTRAL` + 5 ruleId RED → verdetto atteso.
   - **APPROVATO_PANIC_BUY**: `RISCHIO_BASSO` + `TEMPORARY_PANIC` + `panicDiscount=true` + ≤ 2 RED → verdetto atteso.
   - **APPROVATO**: tutti i 13 ruleId GREEN/YELLOW + `RISCHIO_BASSO` + `NEUTRAL` → verdetto atteso.
   - **WATCHLIST**: tutti gli altri casi (es. 3 RED + `RISCHIO_MODERATO`) → verdetto atteso.
3. **Test determinismo**: stesso input dummy (APPROVATO_PANIC_BUY scenario) → stesso verdetto su 100 esecuzioni successive.
4. **Test partial_basis**: input con soli 7 ruleId (EP-010 non completata) → verdetto prodotto ma `partialBasis = true`.

## Acceptance Criteria

- [ ] Tutti e 6 i casi della cascade hanno un test dedicato che passa.
- [ ] Test determinismo: 100 esecuzioni → stesso verdetto.
- [ ] `partialBasis = true` con 7 ruleId in input.
- [ ] La cascade rispetta l'ordine: step 1 (RISCHIO_ESTREMO) vince su step 4 (panic_buy).
