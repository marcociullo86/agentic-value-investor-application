# US-046 — Tab "Deep Analysis" sul frontend

## Descrizione
Come investitore retail, voglio una pagina dedicata `/analysis/{ticker}/deep` sul frontend che mostri il verdetto finale Munger, il rapporto rischi/punti di forza, il sentiment news con esempi, il grafico drawdown 52w e i link diretti ai filing SEC analizzati, affinché possa consultare l'intera deep analysis in un'unica vista senza saltare tra strumenti esterni. [^src: wiki/concepts/webapp-architecture-vi.md §Architettura applicativa]

## Business Rules
- Route: `/analysis/{ticker}/deep` come tab della pagina di analisi ticker esistente (`/analysis/{ticker}`).
- **Policy LLM (2026-05-23, ADR-019 v2)**: alla prima apertura della tab l'endpoint è chiamato SENZA `invoke_llm` → la pagina mostra **solo i campi deterministic** (ruleId, Graham, DCF, MoS, price action, filings_used) entro 2s. L'analisi LLM (Munger inversion + news sentiment) è **opt-in via pulsante "Avvia analisi LLM 10-K/10-Q"** in evidenza nell'header pagina.
- **Pulsante "Avvia analisi LLM"**: mostra in evidenza la **stima costo della chiamata** (es. "≈ $0.49") + **utilizzo budget mensile corrente** (es. "Budget mensile usato 23% — $35/$150") + tooltip che spiega "Lo step LLM analizza in profondità 10-K e 10-Q via Claude Opus 4.7. Costo a tuo carico (budget condiviso). Risultato salvato in cache per il mese corrente."
- **Cache user-level hit (ADR-019 v2 §3)**: se l'utente ha già premuto il pulsante per quel ticker nel mese corrente, il pulsante mostra **"Mostra analisi precedente"** invece di "Avvia analisi LLM" (response servita da cache user × ticker × year_month, costo $0).
- Sezioni in pagina (ordine fisso top-down):
  1. Header: ticker + prezzo + verdict badge (deterministic version se LLM not invoked) + **CTA "Avvia analisi LLM"** o **"Mostra analisi precedente"** (cache user-level)
  2. Badge verdict con classe + position size suggerito. Se LLM not invoked: `partial_basis=true` evidenziato (es. "VERDETTO PARZIALE — completa con analisi LLM").
  3. Pannello Munger inversion collapsibile (visibile solo se `llm_status` ∈ {`INVOKED`, `CACHE_HIT`}): livello rischio, lista top-3 rischi, lista top-3 punti di forza, segnali recenti 10-Q. Altrimenti placeholder "Premi 'Avvia analisi LLM' per il rapporto Munger".
  4. Pannello news sentiment (visibile solo se LLM invoked): distribuzione classi, top-3 esempi per classe con link esterno.
  5. Pannello price action (sempre visibile, deterministic): grafico drawdown 52w (linea prezzo + max_52w + min_52w), flag panic_discount / deterioration_warning.
  6. Pannello "Filing analizzati" (sempre visibile, deterministic): lista accession_number con form_type, filed_at, link diretto a SEC.gov.
  7. Footer: timestamp `generated_at` + `llm_status` corrente.
- Sorgente dati: chiamata singola a `GET /api/analysis/{ticker}/deep` (US-045) — senza `invoke_llm` per render iniziale; con `?invoke_llm=true` al click del pulsante.
- Stato di caricamento LLM: skeleton loader durante la cold call (può durare 30-90s) con messaggio "Sto analizzando i filing SEC, potrebbero servire fino a due minuti".
- **Stato budget freeze (ADR-019 v2 §4)**: se backend risponde 503 `LLM_FROZEN_BY_ADMIN`, il pulsante si disabilita con label "Analisi LLM temporaneamente disabilitata dall'admin" + tooltip con motivo.
- Stato errore: render dedicato per 404 (ticker invalido), 422 (no SEC filings), 503 (LLM unavailable) con call-to-action distinte.
- Accessibilità: la codifica colore del badge verdict ha sempre un'alternativa testuale + icona (coerenza con regola accessibilità di US-014).
- Componenti riusati: pattern traffic light già implementato in US-014 per i ruleId numerici (sezione "rule_engine_results" nel payload US-045).
- Nessun ricalcolo lato client: il payload è già pronto dal backend.

### Nota — esecuzione asincrona (2026-05-29)
A seguito del passaggio della deep analysis da sincrona ad asincrona (US-045 §Esecuzione asincrona), la pagina cambia il flusso dati:
- **Apertura pagina**: la pagina chiama `GET /api/analysis/{ticker}/deep/latest` e mostra **l'ultima esecuzione persistita** dal DB. Nessuna ri-esecuzione automatica della pipeline (no auto-rerun). Stati renderizzati: `NONE` (mai analizzato → CTA "Avvia analisi"), `RUNNING` (skeleton/loader), `SUCCESS` (payload `result` = `DeepAnalysisResponse`), `FAILED` (messaggio da `error.reason`/`error.message`).
- **Avvio analisi**: il click su "Avvia analisi LLM" chiama `POST /api/analysis/{ticker}/deep/runs?invoke_llm=true` (risposta 202 con `runId` + `status: RUNNING`) invece della vecchia chiamata sincrona `GET .../deep?invoke_llm=true`.
- **Polling**: dopo il 202 la pagina fa **polling di `GET .../deep/latest`** finché `status` esce da `RUNNING` (→ `SUCCESS` o `FAILED`), poi popola i pannelli Munger + News sentiment dal `result`.
- **Dedupe lato UX**: se all'apertura `status === "RUNNING"`, la pagina riaggancia il polling sul run in corso senza avviarne uno nuovo (coerente col dedupe backend).
- Lo skeleton loader e i render di errore 404/422/503 restano validi: per i run asincroni l'esito d'errore arriva nel campo `error` di `latest` (status `FAILED`).

## Acceptance Criteria
- [ ] La pagina `/analysis/AAPL/deep` al primo load chiama l'endpoint senza `invoke_llm` e mostra badge verdict parziale + CTA "Avvia analisi LLM" con stima costo + budget bar.
- [ ] Cliccando "Avvia analisi LLM" la pagina chiama l'endpoint con `?invoke_llm=true`, mostra skeleton loader durante l'attesa, poi popola Munger + News sentiment.
- [ ] Stessa pagina visitata di nuovo nello stesso mese con stesso utente mostra "Mostra analisi precedente" (cache user-level hit), click → response servita istantaneamente.
- [ ] Backend risponde 503 LLM_FROZEN_BY_ADMIN → pulsante disabilitato con messaggio chiaro.
- [ ] Le 7 sezioni elencate sono presenti; sezioni LLM-only mostrano placeholder quando LLM not invoked.
- [ ] Su ticker invalido (404) la pagina mostra "Ticker non trovato" con link al search.
- [ ] Su `reason = "no_sec_filings"` (422) la pagina mostra messaggio dedicato "Nessun filing SEC disponibile per questo ticker".
- [ ] Su 503 LLM unavailable la pagina mostra "Servizio analisi temporaneamente non disponibile, riprova più tardi".
- [ ] Il badge verdict ha sempre alternativa testuale + icona (test accessibilità).
- [ ] Test E2E (Playwright) coprono almeno: ticker AAPL deep happy path, ticker invalido, force refresh.

### AC esecuzione asincrona (2026-05-29)
- [ ] All'apertura la pagina chiama `GET .../deep/latest` e mostra l'ultima esecuzione dal DB (stati `NONE`/`RUNNING`/`SUCCESS`/`FAILED`), senza auto-rerun.
- [ ] Il pulsante "Avvia analisi LLM" chiama `POST .../deep/runs?invoke_llm=true` (202) e avvia il polling di `GET .../deep/latest` fino a `SUCCESS`/`FAILED`.
- [ ] Se all'apertura lo stato è `RUNNING`, la pagina riaggancia il polling sul run esistente (nessun nuovo run avviato).
- [ ] Su `status: "FAILED"` la pagina mostra il messaggio derivato da `error.reason`/`error.message`.
