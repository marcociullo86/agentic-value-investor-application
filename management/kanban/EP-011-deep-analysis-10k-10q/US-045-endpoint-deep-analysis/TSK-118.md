# TSK-118 — Implementa DeepAnalysisController + DeepAnalysisService orchestrator (GET /api/analysis/{ticker}/deep)

## Cosa fare

1. Creare `DeepAnalysisController` in `./src/backend/src/main/kotlin/com/valueinvesting/controller/DeepAnalysisController.kt`:
   - Endpoint: `GET /api/analysis/{ticker}/deep`.
   - Delegare a `DeepAnalysisService.analyze(ticker)`.
2. Creare `DeepAnalysisService` in `./src/backend/src/main/kotlin/com/valueinvesting/service/DeepAnalysisService.kt`:
   - Orchestrare in sequenza: `Filing10KQDownloaderService.fetchAndCache()` → `FilingRagService.indexFiling()` → `MungerInversionAnalyzer.analyze()` → `NewsSentimentService.classify()` → `PriceActionAnalyzer.analyze()` → `MungerDecisionService.compute()`.
   - Raccogliere anche `RuleEngineService.analyze()` (i 13 ruleId).
   - Assemblare il payload `DeepAnalysisResult`.
3. Gestione errori conformi RFC 9457 (US-021):
   - Ticker non risolvibile su SEC → 404 con `problem+json`.
   - Filing non disponibili → 422 con `reason = "no_sec_filings"`.
   - LLM irraggiungibile → 503 con `reason = "llm_unavailable"`.
4. Audit log: ogni esecuzione logga `(ticker, generatedAt, cacheHits, llmCalls, totalDurationMs)` in `deep_analysis_event_log`.

## Acceptance Criteria

- [ ] `GET /api/analysis/AAPL/deep` risponde 200 con payload completo (tutti i campi valorizzati).
- [ ] `GET /api/analysis/XYZNOPE/deep` → 404 con `problem+json`.
- [ ] Ticker senza filing SEC → 422 con `reason = "no_sec_filings"`.
- [ ] LLM irraggiungibile → 503 con `reason = "llm_unavailable"`.
- [ ] `deep_analysis_event_log` registra ogni esecuzione.
