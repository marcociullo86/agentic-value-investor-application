# TSK-121 — Contract test OpenAPI /deep — schema completo + drift guard

## Cosa fare

1. Estendere il contract test OpenAPI (pattern TSK-037) per coprire `GET /api/analysis/{ticker}/deep`.
2. Il test verifica:
   - Lo schema OpenAPI include il path `/api/analysis/{ticker}/deep` con risposta 200/404/422/503.
   - Il payload di risposta 200 include tutti i campi obbligatori: `ticker`, `generatedAt`, `verdictPayload`, `deepAnalysisReport`, `sentimentSummary`, `priceActionSnapshot`, `ruleEngineResults`, `filingsUsed`.
   - I campi `verdettoCLasse`, `positionSizePct` sono presenti in `verdictPayload`.
3. Il test fallisce se un campo obbligatorio viene rimosso dallo schema (drift guard).

## Acceptance Criteria

- [ ] Contract test passa con la spec OpenAPI aggiornata da TSK-119.
- [ ] Drift guard: rimuovere `verdettoCLasse` dallo schema → test fallisce.
- [ ] I 4 codici di risposta (200/404/422/503) sono documentati nella spec.
