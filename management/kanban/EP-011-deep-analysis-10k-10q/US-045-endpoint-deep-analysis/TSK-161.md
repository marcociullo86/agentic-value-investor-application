# TSK-161 — BE: estendi DeepAnalysisResponse con blocco roe

## Obiettivo
Aggiungere i quattro campi ROE al payload `DeepAnalysisResponse` (DTO) esposto da `GET /api/analysis/{ticker}/deep` (US-045), allineato allo schema OpenAPI 3.1 definito in ADR-020.

## Scope
- Aggiornamento DTO `DeepAnalysisResponse` (o `DeepAnalysisResultDto` a seconda del naming esistente): aggiungere blocco nidificato `roe`:
  ```json
  {
    "roe": {
      "fiveYearAvg": 0.265,
      "tenYearAvg": 0.312,
      "fiveYearDataPoints": 5,
      "tenYearDataPoints": 10
    }
  }
  ```
- `tenYearAvg` e `fiveYearAvg` → `null` se dati insufficienti (IPO recente); `tenYearDataPoints` e `fiveYearDataPoints` indicano il numero reale di anni usati nel calcolo.
- `DeepAnalysisService` / `DeepAnalysisController`: popola `roe.fiveYearAvg` tramite `RoeCalculator.fiveYearAverage(...)` (TSK-160) e `roe.tenYearAvg` tramite `RoeCalculator.tenYearAverage(...)` esistente.
- Aggiornamento schema OpenAPI 3.1 del contratto canonico: aggiungere `roe` object con le quattro proprietà tipizzate (`number` + `integer`), `nullable: true` per i campi avg, descrizione semantica per ognuno.
- Verifica backward-compat: se US-045 endpoint già rilasciato in ambiente (non dovrebbe essere, sprint 7 è in stato `ready`), aggiungere `roe` come campo nuovo non-breaking. Segnalare se breaking.
- ProblemDetail flatten compliance (ADR-012) non impatta questo DTO, ma verificare che non ci siano override nel `GlobalExceptionHandler` che escludano `roe`.

## DoD
- `GET /api/analysis/AAPL/deep` restituisce blocco `roe` con tutti e quattro i campi.
- OpenAPI YAML aggiornato e contract test (drift guard TSK-121 aggiornato o nuovo test aggiunto in TSK-163).
- `fiveYearAvg` e `tenYearAvg` `null` per ticker con dati insufficienti (verifica con ticker IPO test fixture).
