# TSK-114 — Test PriceActionAnalyzer — boundary flags, serie insufficiente, cache TTL

## Cosa fare

1. Aggiungere la migration `V015__price_action_snapshot.sql` inline in questo TSK (tabella `price_action_snapshot`):
   ```sql
   CREATE TABLE price_action_snapshot (
     id                   BIGSERIAL PRIMARY KEY,
     ticker               VARCHAR(20) NOT NULL,
     calc_date            DATE        NOT NULL,
     price_now            DECIMAL(12,4),
     max_52w              DECIMAL(12,4),
     min_52w              DECIMAL(12,4),
     drawdown_pct         DECIMAL(8,4),
     trend_3m_pct         DECIMAL(8,4),
     ma50                 DECIMAL(12,4),
     ma200                DECIMAL(12,4),
     panic_discount       BOOLEAN,
     deterioration_warning BOOLEAN,
     series_days          INT,
     created_at           TIMESTAMPTZ NOT NULL DEFAULT now(),
     CONSTRAINT uq_price_action_ticker_date UNIQUE (ticker, calc_date)
   );
   ```
2. Creare `PriceActionAnalyzerTest.kt` con Testcontainers PostgreSQL + WireMock FMP.
3. Test da implementare:
   - **Panic boundary**: fixture con `currentPrice = 70`, `max52w = 100` → `drawdownPct = -30%` → `panicDiscount = true`.
   - **Deterioration**: fixture con `trend3m = -12%` AND `ma50 < ma200` → `deteriorationWarning = true`.
   - **No deterioration**: `trend3m = -12%` AND `ma50 > ma200` → `deteriorationWarning = false`.
   - **Serie insufficiente**: fixture con 100 record (< 252) → `max52w = null`, flag = `false`.
   - **Ticker inesistente**: WireMock restituisce 404 → eccezione applicativa.
   - **Cache hit**: seconda chiamata stessa data → nessuna nuova HTTP call.

## Acceptance Criteria

- [ ] Boundary `drawdownPct = -30%` → `panicDiscount = true`.
- [ ] Deterioration richiede entrambe le condizioni.
- [ ] Serie insufficiente: campi nullable.
- [ ] Ticker inesistente: eccezione applicativa (non NPE).
- [ ] Cache hit: 1 sola HTTP call.
