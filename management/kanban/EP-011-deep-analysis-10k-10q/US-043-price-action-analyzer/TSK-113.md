# TSK-113 — Implementa PriceActionAnalyzer — drawdown 52w, panic_discount flag, deterioration_warning flag

## Cosa fare

1. Creare `PriceActionAnalyzer` in `./src/backend/src/main/kotlin/com/valueinvesting/service/PriceActionAnalyzer.kt`.
2. Il servizio espone: `analyze(ticker: String): PriceActionSnapshot`.
3. Flusso:
   a. Chiama `FmpAdapter.getHistoricalEodPrices(ticker, 365)`.
   b. Recupera `currentPrice` da `FmpAdapter.getQuote(ticker)`.
   c. Calcola:
      - `max52w = max(close)` degli ultimi 252 giorni di trading.
      - `min52w = min(close)` degli ultimi 252 giorni di trading.
      - `drawdownPct = (currentPrice - max52w) / max52w * 100`.
      - `trend3m = (close[ultimo] - close[-63]) / close[-63] * 100` (ultimi 63 giorni = ~3 mesi di trading).
      - `ma50 = avg(close[-50:])` (media mobile 50 giorni).
      - `ma200 = avg(close[-200:])` (media mobile 200 giorni; richiede almeno 200 record).
   d. Flags:
      - `panicDiscount = drawdownPct <= -30.0`.
      - `deteriorationWarning = trend3m <= -10.0 AND ma50 < ma200` (death cross).
4. Se la serie < 252 giorni: `max52w = null`, `min52w = null`, entrambi i flag = `false` con nota `"serie insufficiente"`.
5. Cache: persiste in tabella `price_action_snapshot` (`upsert` su `(ticker, calcDate)`) con TTL 24h.
6. Creare `PriceActionSnapshotEntity` (JPA) + `PriceActionSnapshotRepository`.

## Acceptance Criteria

- [ ] `analyze("AAPL")` produce `PriceActionSnapshot` con tutti i campi numerici.
- [ ] `panicDiscount = true` quando `drawdownPct ≤ -30%` (test boundary esatto).
- [ ] `deteriorationWarning = true` solo con entrambe le condizioni vere.
- [ ] Con serie < 252 giorni: `max52w = null`, `min52w = null`, flag = `false`.
- [ ] Seconda chiamata entro 24h: cache hit.
