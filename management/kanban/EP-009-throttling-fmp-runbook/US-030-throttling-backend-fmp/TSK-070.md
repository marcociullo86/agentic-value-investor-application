# TSK-070 — WireMock 429 FMP retry + event log

## Context

US-030 AC: simulazione 429 provider → retry/backoff + evento in log osservabilità. ADR-016 mapping `FMP_429_RATE_LIMITED`.
[^src: design_&_architecture/decisions/ADR-016-fmp-operations-throttling.md §3. Mapping errori HTTP]
[^src: management/kanban/EP-009-throttling-fmp-runbook/US-030-throttling-backend-fmp/US-030.md §Acceptance Criteria]

## Technical Specs

- **QA:** Estendere test resilienza esistenti (`FmpResilienceConfigTest` o IT con WireMock):
  - Prima risposta HTTP 429 da FMP mock → retry → successo 200.
  - Riga in `fmp_api_event_log` con event type `FMP_429_RATE_LIMITED` (o equivalente enum).
- **Regression US-006:** scenario circuit open + stale cache fallback ancora funzionante (test già in `AnalysisControllerIT` / resilience suite).
[^src: src/backend/src/main/kotlin/com/valueinvesting/webapp/fmp/ResilientFmpAdapter.kt]

## Implementation Steps

1. Aggiungere stub WireMock sequenza 429 → 200 su endpoint profile o income.
2. Invocare adapter o endpoint che triggera FMP call.
3. Assert retry count e event log persisted.
4. Eseguire suite resilienza completa.

## Definition of Done

- [ ] Test 429 → retry PASS in CI.
- [ ] Evento log tracciato con tipo corretto.
- [ ] Nessuna regressione test US-006 cache stale.
