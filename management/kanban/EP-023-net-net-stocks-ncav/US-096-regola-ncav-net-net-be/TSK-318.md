# TSK-318 — QA Test BE NCAV_LATEST + NET_NET_RATIO

## Obiettivo

Coprire tutti gli Acceptance Criteria di US-096 con test unitari e di integrazione.

## Scenari obbligatori

1. **Caso GREEN**: ticker con `priceLatest < (2/3) × ncavPerShare`:
   - `NCAV_LATEST` → `GREEN`, `ncavTotal > 0`, `ncavPerShare` valorizzato.
   - `NET_NET_RATIO` → `GREEN`, `ratio < 0.6667`.

2. **Caso RED**: ticker con `priceLatest >= (2/3) × ncavPerShare`:
   - `NCAV_LATEST` → `GREEN`, `ncavTotal > 0`.
   - `NET_NET_RATIO` → `RED`, `ratio >= 0.6667`.

3. **Caso INDETERMINATE**: balance sheet con `totalCurrentAssets == null` (o `sharesOutstanding == null`):
   - `NCAV_LATEST` → `INDETERMINATE`.
   - `NET_NET_RATIO` → `INDETERMINATE`.

4. **Caso edge NCAV <= 0** (passivo totale > attivo corrente):
   - `NCAV_LATEST` → `RED`, `ncavTotal <= 0`.
   - `NET_NET_RATIO` → `NOT_CALCULABLE`.

5. **No regression**: lanciare la suite completa del Rule Engine (13 ruleId esistenti) su fixture AAPL/MSFT/KO;
   tutti i segnali e i campi tipati devono essere invariati rispetto al comportamento pre-EP-023.

## Test NcavCalculator

Test unitari diretti su `NcavCalculator.compute(dataset)`:
- Input completo valido → `reason = "ok"`, `ncavTotal` e `ncavPerShare` calcolati correttamente.
- `totalCurrentAssets == null` → `reason = "missing_balance_sheet"`.
- `sharesOutstanding == null` e fallback `weightedAverageShsOut == null` → `reason = "missing_shares"`.
