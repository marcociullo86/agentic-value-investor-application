# TSK-317 — BE NetNetRatioRule

## Obiettivo

Creare `NetNetRatioRule` (`@Component : ValuationRule`) che implementa il segnale decisionale Graham
`NET_NET_RATIO` basato sulla formula `price < 2/3 × NCAV per share`.

## Scope

### `NetNetRatioRule` (`@Component : ValuationRule`)

File: `src/backend/.../ruleengine/rules/NetNetRatioRule.kt`

Logica:
1. Chiama `NcavCalculator.compute(dataset)` (iniettato o richiamato direttamente).
2. Legge `dataset.currentPrice` (da `FmpProfileSnapshot`, già in `FinancialDataset` — fonte ADR-014).

Segnale:
- `ncavPerShare == null` o `priceLatest == null` → `INDETERMINATE`
- `ncavPerShare <= 0` → `NOT_CALCULABLE` (ratio non sensato)
- `ratio = priceLatest / ncavPerShare < 0.6667` → `GREEN` (opportunità net-net Graham)
- `ratio >= 0.6667` → `RED`

Costante: `THRESHOLD_RATIO = 2.0 / 3.0` (companion object).

Output: `RuleSignal.NetNetRatio(signal, priceLatest, ncavPerShare, ratio, thresholdRatio=THRESHOLD_RATIO, observedValue=ratio, rationale=...)`.

### OpenAPI — sotto-schema `RuleSignalNetNetRatio`

Aggiungere a `openapi.yaml` (nel medesimo commit):
- Schema `RuleSignalNetNetRatio` (allOf RuleSignalBase + `priceLatest nullable` + `ncavPerShare nullable`
  + `ratio nullable` + `thresholdRatio: 0.6667`).
- Entry in `RuleSignal.discriminator.mapping` + lista `oneOf`.
- Enum `ruleId` esteso con `NET_NET_RATIO`.

## Invarianti

- I 13 ruleId esistenti restano invariati.
- Ordinamento lessicografico: `NET_NET_RATIO` dopo `NET_MARGIN_10Y_AVG` (confermato ASCII).
