# TSK-316 — BE NcavCalculator + NcavLatestRule

## Obiettivo

Creare `NcavCalculator` (utility condiviso) e `NcavLatestRule` (`@Component : ValuationRule`) che
implementano il criterio Graham NCAV_LATEST nel Rule Engine.

## Scope

### `NcavCalculator` (oggetto utility)

File: `src/backend/.../ruleengine/calculators/NcavCalculator.kt`

```kotlin
object NcavCalculator {
    data class Result(
        val ncavTotal: Double?,
        val ncavPerShare: Double?,
        val reason: String, // "missing_balance_sheet" | "missing_shares" | "negative" | "ok"
    )
    fun compute(dataset: FinancialDataset): Result
}
```

Formula:
```
NCAV = totalCurrentAssets - totalLiabilities   (passività TOTALI correnti + non correnti)
NCAV per share = NCAV / sharesOutstanding
```

Fonte dati (tutti già adapter-wrapped EP-002):
- `totalCurrentAssets`, `totalLiabilities` → `BalanceSheetStatementDto` (annual, latest)
- `sharesOutstanding` → `KeyMetricsDto.sharesOutstanding` (preferito), fallback su
  `BalanceSheetStatementDto.weightedAverageShsOut`
- Regola "campi mancanti = assenti, mai 0" (US-004): qualsiasi campo null → `reason = "missing_balance_sheet"`
  o `"missing_shares"`, con `ncavTotal = null`, `ncavPerShare = null`.

### `NcavLatestRule` (`@Component : ValuationRule`)

File: `src/backend/.../ruleengine/rules/NcavLatestRule.kt`

Segnale:
- Dati mancanti → `INDETERMINATE`
- `ncavTotal > 0` → `GREEN` (calcolo riuscito; la decisione di acquisto spetta a `NET_NET_RATIO`)
- `ncavTotal <= 0` → `RED` (passivo totale > attivo corrente)

Output: `RuleSignal.NcavLatest(signal, ncavTotal, ncavPerShare, observedValue=ncavPerShare, rationale=...)`.

Se TSK-311 ha già definito `RuleSignal.NcavLatest` nella sealed interface, questo task lo usa
direttamente. Altrimenti, creare il sotto-tipo nel medesimo commit (coordinare con be-dev responsabile
di TSK-311 in Scenario B ADR-029 §5).

### OpenAPI — sotto-schema `RuleSignalNcavLatest`

Aggiungere a `openapi.yaml`:
- Schema `RuleSignalNcavLatest` (allOf RuleSignalBase + `ncavTotal: number nullable` +
  `ncavPerShare: number nullable`).
- Entry in `RuleSignal.discriminator.mapping` + nella lista `oneOf`.
- Enum `ruleId` esteso con `NCAV_LATEST`.

## Invarianti

- I 13 ruleId esistenti restano invariati (auto-injection Spring `List<ValuationRule>`).
- Ordinamento lessicografico: `NCAV_LATEST` → dopo `N*` nella lista ordinata (`NcavLatest` < `NetMargin` < `NetNetRatio`).
