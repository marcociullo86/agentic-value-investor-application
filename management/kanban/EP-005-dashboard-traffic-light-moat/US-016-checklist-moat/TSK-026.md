# TSK-026 — MoatChecklistController: endpoint checklist Moat

## Obiettivo

Implementare gli endpoint per la checklist Moat qualitativa utente-per-ticker.

## Scope tecnico

- `MoatChecklistController`:
  - `GET /api/moat-checklist/{ticker}` (auth required): restituisce `MoatChecklist` con
    4 voci (vuote se non ancora compilate dall'utente).
    [^src: design_&_architecture/api/openapi.yaml §/api/moat-checklist/{ticker} GET]
  - `POST /api/moat-checklist/{ticker}` (auth required): upsert voce.
    Body: `{moatType, status, note}`.
    [^src: design_&_architecture/api/openapi.yaml §/api/moat-checklist/{ticker} POST]
- `MoatChecklistService`:
  - `getChecklist(userId, ticker)`: recupera 4 voci per (user, ticker); voci mancanti
    vengono restituite con stato `null` (non persistite finché non modificate).
  - `upsertEntry(userId, ticker, moatType, status, note)`: INSERT ON CONFLICT UPDATE.
  [^src: design_&_architecture/components/backend-components.md §MoatChecklistService]
- L'annotazione qualitativa non altera `RuleEngineResult` (US-016 AC).
  [^src: management/kanban/EP-005-dashboard-traffic-light-moat/US-016-checklist-moat/US-016.md §AC]
- Auth: `JwtAuthenticationFilter` valida token su entrambi gli endpoint.
  [^src: design_&_architecture/decisions/ADR-006-authentication.md §Endpoint policy]

## Criteri di completamento (DoD)

- [ ] GET senza voci persistite → 200, lista con 4 voci a stato null.
- [ ] POST con moatType valido → 200, voce salvata e ritornata.
- [ ] GET successivo restituisce la voce aggiornata.
- [ ] GET senza token → 401.
- [ ] Annotazione non compare in `GET /api/analysis/{ticker}`.
- [ ] Integration test con utente autenticato (token generato da `AuthService`).
