# TSK-027 — MoatChecklist component

## Obiettivo

Implementare il componente checklist Moat nella pagina di analisi.

## Scope tecnico

- `components/moat/MoatChecklist.tsx`:
  - 4 voci: Asset Immateriali (INTANGIBLE_ASSETS), Switching Costs, Network Effect,
    Vantaggio di Costo (COST_ADVANTAGE).
    [^src: management/kanban/EP-005-dashboard-traffic-light-moat/US-016-checklist-moat/US-016.md §Business Rules]
  - Per ogni voce: descrizione sintetica + select stato (`PRESENT`/`PARTIAL`/`ABSENT`) +
    textarea nota.
  - onChange status/nota → `POST /api/moat-checklist/{ticker}` (debounced o on-blur).
  - Fetch iniziale: `GET /api/moat-checklist/{ticker}` → popola stato locale.
  - Persistente: tornando sul ticker, voci caricate dal BE.
    [^src: management/kanban/EP-005-dashboard-traffic-light-moat/US-016-checklist-moat/US-016.md §AC]
  - Radix UI Select per a11y stato.
    [^src: design_&_architecture/components/frontend-components.md §Design system]
- Integrazione in `app/analysis/[ticker]/page.tsx` come sezione sotto il grafico.
- Visibile solo se utente autenticato (con `useAuthStore.accessToken`).

## Criteri di completamento (DoD)

- [ ] 4 voci con descrizione, select stato, campo nota visibili.
- [ ] Modifica stato salvata (POST con 200).
- [ ] Ricaricando la pagina le annotazioni sono presenti.
- [ ] Annotazione non altera i semafori del TrafficLightPanel.
- [ ] Unit test: rendering, onChange, stato iniziale da fetch.
