# TSK-266 — FE ClientAuthGuard e useAuthGuard per static export

## Context
ADR-026 richiede di mantenere static export in produzione e spostare la logica di guard da middleware runtime a layer client-side esplicito riusabile.
[^src: design_&_architecture/decisions/ADR-026-frontend-authguard-static-export-runtime.md §Decisione]
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-087-authguard-client-side-static-export/US-087.md §Acceptance Criteria]

## Technical Specs
- **FE:** introdurre `ClientAuthGuard` + `useAuthGuard` con matrice decisionale unificata.
- **Decision matrix:** `unauth -> login(returnUrl)`, `forbidden -> /403`, `sessionExpired -> logout silente + login`.
- **Input guard:** metadata route-config (`requiresAuth`, `roles`) gia' introdotti da TSK-205.
- **Compatibilita' static export:** nessuna dipendenza da middleware/headers runtime per enforcement UX.

## Implementation Steps
1. Estrarre logica guard in hook client-side riusabile.
2. Implementare componente `ClientAuthGuard` con fallback/loading state deterministico.
3. Integrare controllo ruoli e stato sessione in un'unica matrice decisionale.
4. Esporre API riusabile per layout/pagine protette.

## Acceptance Criteria
- [ ] Esiste un hook/componente client-side che applica i 3 esiti (`login`, `/403`, `sessionExpired`) senza middleware runtime.
- [ ] La decisione guard usa la route map dichiarativa come fonte unica dei requisiti auth.
- [ ] Nessuna regressione su rotte pubbliche (`/`, `/login`, `/register`).
- [ ] La logica e' riusabile da almeno due aree protette differenti.

## Definition of Done
- [ ] Hook/componente introdotti e referenziati nelle aree protette target
- [ ] Matrice decisionale copre `unauth`, `forbidden`, `sessionExpired`
- [ ] Lint/test frontend passano sul modulo aggiornato
- [ ] Code review approvata

## Dependencies
- TSK-205 — route-config dichiarativa
- TSK-211 — useAuthStore basato su cookie httpOnly

## Risk Notes
- Possibile flicker iniziale su hydration: mitigare con stato `isAuthResolved` prima dei redirect.
- Divergenza guard vs route-map: mitigare centralizzando lookup route in un unico helper.
