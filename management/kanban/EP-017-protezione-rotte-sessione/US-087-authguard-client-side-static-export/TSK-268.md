# TSK-268 — FE Hardening middleware.ts come dev-only

## Context
ADR-026 formalizza che `middleware.ts` non e' il meccanismo di produzione con static export e deve restare solo supporto locale in `next dev`, per evitare assunzioni errate in fase operativa.
[^src: design_&_architecture/decisions/ADR-026-frontend-authguard-static-export-runtime.md §Decisione]
[^src: design_&_architecture/decisions/ADR-026-frontend-authguard-static-export-runtime.md §Conseguenze]

## Technical Specs
- **FE:** ridurre `middleware.ts` a fallback dev-only esplicito.
- **Guardrail:** aggiungere check/config che impediscono dipendenza runtime middleware in produzione.
- **Doc tecnica locale (code_path):** chiarire responsabilita': produzione usa guard client-side + backend autoritativo.

## Implementation Steps
1. Marcare middleware come dev-only con condizioni esplicite.
2. Rimuovere/evitare side effect necessari solo a runtime server FE.
3. Aggiornare documentazione tecnica frontend sull'uso corretto.
4. Verificare che build/export non dipenda da middleware.

## Acceptance Criteria
- [ ] In ambiente produzione static export, il comportamento auth non richiede middleware runtime.
- [ ] In `next dev`, middleware resta disponibile come supporto locale.
- [ ] Esiste documentazione tecnica che dichiara chiaramente il perimetro dev-only.
- [ ] Nessun riferimento operativo indica middleware come controllo auth di produzione.

## Definition of Done
- [ ] `middleware.ts` allineato al ruolo dev-only
- [ ] Note tecniche frontend aggiornate
- [ ] Build/export statica validata senza regressioni guard
- [ ] Code review approvata

## Dependencies
- TSK-266 — guard client-side implementato

## Risk Notes
- Rischio confusione team su boundary sicurezza: mitigare con wording esplicito "UX only".
- Rischio regressione CSP in locale: mitigare mantenendo parita' minima su `next dev`.
