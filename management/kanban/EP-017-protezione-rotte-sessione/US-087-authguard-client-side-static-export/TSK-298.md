# TSK-298 — FE Migrazione middleware.ts → proxy.ts (Next.js 16)

## Context
Next.js 16.0.3 deprecata la convention `middleware` in favore di `proxy`: il build emette `⚠ The "middleware" file convention is deprecated. Please use "proxy" instead.`. La migrazione e' una rinomina meccanica (file + funzione esportata) che non altera la firma, i tipi o il `config.matcher`. Il file resta **dev-only** per contratto ADR-026 (in produzione `output: 'export'` disabilita comunque il runtime FE): la migrazione preserva integralmente il guard-rail introdotto da TSK-268.
[^src: https://nextjs.org/docs/messages/middleware-to-proxy]
[^src: design_&_architecture/decisions/ADR-026-frontend-authguard-static-export-runtime.md §Decisione]

## Technical Specs
- **FE:** `git mv middleware.ts proxy.ts`; rinominare `export function middleware` → `export function proxy`; `config` + `matcher` invariati; firma `(request: NextRequest): NextResponse` invariata.
- **Docstring:** aggiornare i riferimenti testuali "middleware" → "proxy" mantenendo invariato il contratto dev-only (ADR-026 / TSK-268).
- **Test:** `git mv __tests__/middleware.test.ts __tests__/proxy.test.ts`; aggiornare i 3 `import('../middleware')` → `'../proxy'` e `mod.middleware` → `mod.proxy`.
- **Doc/commenti:** allineare i riferimenti testuali residui (README, commenti playwright/provider) dove la parola "middleware" descrive questo file.

## Implementation Steps
1. Rinominare il file e la funzione esportata (no codemod automatico: lasciato a mano per allineare docstring e test file).
2. Aggiornare le docstring del file con la nuova terminologia, preservando il wording dev-only.
3. Rinominare il test e fixare i 3 import.
4. `npm run build` → verificare assenza del warning middleware-to-proxy; `npm test` → suite proxy verde.
