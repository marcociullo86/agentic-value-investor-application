# US-075 — Migrazione storage credenziali

## Descrizione
Come security auditor, voglio che l'access token sia conservato esclusivamente in memoria applicativa (non persistito su disco) e il refresh token in cookie `httpOnly Secure SameSite=Strict` gestito dal backend, con localStorage proibito per token, identificativi di sessione e dati personali o finanziari, affinché un attacco XSS non possa esfiltrare credenziali dal browser storage. [^src: wiki/concepts/auth-guard-frontend.md §Storage dei token]

## Business Rules
- **Access token**: conservato in memoria (stato applicativo), non persistito su disco. Re-login dopo reload o rehydration via refresh token.
- **Refresh token**: in cookie `httpOnly Secure SameSite=Strict`, gestito esclusivamente dal backend (il frontend non lo legge né lo manipola).
- **localStorage proibito** per token, identificativi di sessione, dati personali o finanziari.
- Access token a **vita breve** (<= 15 minuti).
- Refresh token con **rotation** ad ogni uso: ogni utilizzo genera un nuovo refresh token e invalida il precedente.
- Revoca server-side in caso di riuso sospetto di un refresh token già ruotato (potenziale token theft).
- Refresh F5 su rotta protetta da utente autenticato non causa flicker verso login (rehydration trasparente).

[^src: wiki/concepts/fintech-security-compliance.md §5.2 — Storage credenziali frontend]

## UI Reference
Nessuna — storia di sicurezza infrastrutturale.

## Acceptance Criteria
- [ ] Nessun token o credenziale è rilevabile in localStorage durante audit manuale (verifica DevTools).
- [ ] L'access token non è accessibile da JavaScript runtime oltre la variabile in-memory dello store.
- [ ] Il refresh token è in un cookie `httpOnly Secure SameSite=Strict` (verificato nell'header `Set-Cookie` della response).
- [ ] Access token ha durata <= 15 minuti (verificato nel payload JWT).
- [ ] Refresh F5 su rotta protetta da utente autenticato: la pagina si carica senza passare per `/login` (rehydration trasparente).
- [ ] Il riuso di un refresh token già ruotato causa revoca di tutti i refresh token dell'utente (simulato in test).
