# TSK-209 — BE AuthController migrazione refresh token a cookie httpOnly

## Context
US-075 richiede migrazione del refresh token da body JSON a cookie httpOnly Secure SameSite=Strict. Questo è il cambiamento architetturale principale di EP-017.
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-075-migrazione-storage-credenziali/US-075.md §AC]
[^src: design_&_architecture/decisions/ADR-024-session-lifecycle-credential-storage.md §3]

## Technical Specs
- **BE:** Modifica `AuthController`
- **POST /api/auth/login** (success):
  - Response body: `{ accessToken, expiresInSeconds }` (NO refreshToken nel body)
  - Set-Cookie: `refresh_token={value}; HttpOnly; Secure; SameSite=Strict; Path=/api/auth; Max-Age=604800`
- **POST /api/auth/refresh**:
  - Legge refresh token dal cookie (non dal body)
  - Response body: `{ accessToken, expiresInSeconds }`
  - Set-Cookie: nuovo refresh token (rotation)
- **POST /api/auth/logout**:
  - Revoca refresh token in DB
  - Set-Cookie: `refresh_token=; Max-Age=0` (cancella)
  - Response: 204 No Content
- **Cookie Path:** `/api/auth` (limita invio ai soli endpoint auth)
- **Access token:** invariato (in-memory, <= 15min)
- **Rotation:** invariata (ogni uso genera nuovo refresh, vecchio invalidato)
- **Revoca riuso:** invariata (riuso token ruotato → revoca tutti)

## Implementation Steps
1. Modificare login endpoint: rimuovere refreshToken dal body, aggiungere Set-Cookie
2. Modificare refresh endpoint: leggere cookie, emettere nuovo cookie
3. Modificare logout endpoint: revocare + cancellare cookie + 204
4. Configurare cookie attributes: HttpOnly, Secure, SameSite=Strict, Path=/api/auth
5. Aggiornare test unitari AuthController

## Definition of Done
- [ ] Login non restituisce refreshToken nel body
- [ ] Cookie httpOnly Secure SameSite=Strict emesso al login
- [ ] Refresh legge da cookie
- [ ] Logout cancella cookie + 204
- [ ] Rotation e revoca invariate
- [ ] Code review approvata

## Dependencies
Nessuna — cambiamento BE indipendente.
