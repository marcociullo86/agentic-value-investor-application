# TSK-211 — FE useAuthStore aggiornato: rehydration via cookie refresh

## Context
US-075 richiede aggiornamento dello store auth FE: rimuovere gestione refresh token dal body, implementare rehydration trasparente al reload.
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-075-migrazione-storage-credenziali/US-075.md §AC]
[^src: design_&_architecture/decisions/ADR-024-session-lifecycle-credential-storage.md §3]

## Technical Specs
- **FE:** Aggiornamento `useAuthStore` (Zustand)
- **Rimozione:** gestione refreshToken dal body di login/refresh
- **Rehydration al reload (F5):**
  1. Store vuoto (in-memory token perso)
  2. Bootstrap component tenta POST /api/auth/refresh (browser allega cookie httpOnly)
  3. Se riuscito: access token → store → pagina renderizza (no flicker)
  4. Se fallito: redirect /login con messaggio sessione scaduta
- **localStorage proibito** per token, session ID, dati sensibili
- **Cookie `isAuthenticated`:** cookie non-httpOnly hint per middleware (TSK-206)

## Implementation Steps
1. Rimuovere refreshToken handling dal login flow
2. Implementare bootstrap rehydration component
3. Impostare cookie `isAuthenticated=true` al login (hint per middleware)
4. Implementare fallback: refresh fallito → redirect login
5. Verificare nessun token in localStorage
6. Verificare F5 su rotta protetta → no flicker

## Definition of Done
- [ ] Nessun refreshToken nel body gestito FE
- [ ] Rehydration F5 trasparente (no flicker)
- [ ] Refresh fallito → redirect login
- [ ] Nessun token in localStorage
- [ ] Code review approvata
