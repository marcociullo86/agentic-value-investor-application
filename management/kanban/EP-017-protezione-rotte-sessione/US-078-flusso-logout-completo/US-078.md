# US-078 — Flusso logout completo

## Descrizione
Come utente finale, voglio che il logout esegua in sequenza la revoca del refresh token lato backend, la cancellazione del cookie, la pulizia dello store applicativo e della query cache, e il blocco della navigazione history verso rotte protette, affinché dopo il logout nessun dato di sessione sia recuperabile da un altro utente sullo stesso browser. [^src: wiki/concepts/auth-guard-frontend.md §Logout]

## Business Rules
- Il flusso di logout esegue in sequenza:
  1. Revoca refresh token lato backend (chiamata API).
  2. Cancellazione cookie `httpOnly` (server-side via Set-Cookie con expiry passato).
  3. Pulizia store applicativo (stato auth in-memory, dati utente).
  4. Pulizia query cache (cache SWR/fetch, dati stale).
  5. Blocco navigazione history verso rotte protette (back button dopo logout non rientra in area protetta).
- Il logout funziona anche se la chiamata API di revoca fallisce (pulizia locale comunque eseguita, errore loggato).
- Dopo il logout, nessun dato di sessione è accessibile via DevTools (localStorage, sessionStorage, cookie applicativo, variabili in-memory).

## Acceptance Criteria
- [ ] Dopo logout, il refresh token è revocato lato backend (verificato: riuso del token restituisce errore).
- [ ] Dopo logout, nessun cookie di sessione è presente nel browser.
- [ ] Dopo logout, lo store applicativo è vuoto (verificato: accesso allo store restituisce stato non autenticato).
- [ ] Dopo logout, il back button del browser non rientra in area protetta (la navigazione porta a `/login`).
- [ ] Se la chiamata API di revoca fallisce (simulato: backend offline), il logout locale procede comunque (pulizia store + redirect a login).
- [ ] Test E2E: login → navigazione in area protetta → logout → back button → verifica di essere su `/login`.
