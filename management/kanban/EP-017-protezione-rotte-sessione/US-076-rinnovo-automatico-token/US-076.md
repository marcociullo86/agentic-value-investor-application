# US-076 — Rinnovo automatico token con coda richieste

## Descrizione
Come utente finale, voglio che il refresh token venga rinnovato automaticamente prima della scadenza dell'access token, con una coda che gestisce le richieste in corso durante il refresh, affinché non debba mai ri-autenticarmi durante una sessione attiva. [^src: wiki/concepts/auth-guard-frontend.md §Ciclo di vita del token]

## Business Rules
- Il refresh token viene rinnovato automaticamente prima della scadenza dell'access token, con un margine di sicurezza di circa 60 secondi.
- Una coda gestisce le richieste HTTP in corso durante il refresh: le richieste partite durante il refresh vengono messe in coda e rilasciate con il nuovo access token.
- Se il refresh fallisce (refresh token scaduto, revocato, o errore server), l'utente viene reindirizzato a `/login` con messaggio informativo (US-073 sessione scaduta).
- Il meccanismo è trasparente: l'utente non percepisce il refresh (nessun loader, nessun redirect temporaneo).
[^src: wiki/concepts/auth-guard-frontend.md §Ciclo di vita del token]

## UI Reference
Nessuna — storia di infrastruttura auth.

## Acceptance Criteria
- [ ] Con access token in scadenza (<60s alla scadenza), il sistema rinnova automaticamente il token prima che scada.
- [ ] Due richieste HTTP concorrenti durante il refresh ricevono entrambe il nuovo access token (non causano doppio refresh).
- [ ] Se il refresh fallisce, l'utente è reindirizzato a `/login` con messaggio "La sessione è scaduta".
- [ ] Test di integrazione: una sessione di 20+ minuti con richieste periodiche non causa mai un 401 percepito dall'utente.
