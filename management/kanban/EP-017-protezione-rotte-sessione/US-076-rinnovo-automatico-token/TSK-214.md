# TSK-214 — QA Test refresh automatico: concorrenza, sessione lunga, fallback

## Context
US-076 AC richiede verifica: no doppio refresh, sessione 20+ min senza 401, refresh fail → redirect login.
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-076-rinnovo-automatico-token/US-076.md §AC]

## Technical Specs
- **QA:** Vitest + mock timer + Playwright
- **Scenari:**
  - Due richieste concorrenti durante refresh → entrambe ricevono nuovo token (no doppio refresh)
  - Sessione 20+ minuti con richieste periodiche → nessun 401 percepito
  - Refresh fallito (token scaduto) → redirect /login con "La sessione è scaduta"
  - Refresh trasparente: nessun loader visibile durante il refresh

## Implementation Steps
1. Test mutex: 2 chiamate fetch parallele durante refresh → una sola POST /refresh
2. Test sessione lunga: simula timer, verifica refresh automatico pre-scadenza
3. Test fallback: mock refresh 401 → verifica redirect login
4. Test UX: nessun loader durante refresh

## Definition of Done
- [ ] No doppio refresh verificato
- [ ] Sessione 20+ min OK
- [ ] Fallback → login con messaggio
- [ ] Code review approvata
