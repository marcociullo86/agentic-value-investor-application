# TSK-213 — FE useTokenRefresh hook: timer pre-expiry + mutex coda

## Context
US-076 richiede refresh automatico prima della scadenza con coda che gestisce richieste concorrenti durante il refresh.
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-076-rinnovo-automatico-token/US-076.md §AC]
[^src: design_&_architecture/decisions/ADR-024-session-lifecycle-credential-storage.md §4]

## Technical Specs
- **FE:** `hooks/use-token-refresh.ts`
- **Timer pre-expiry:** ~60s prima della scadenza access token → trigger refresh automatico
- **Mutex pattern:** un solo refresh alla volta; richieste HTTP in coda (Promise pending) durante il refresh
- **Rilascio coda:** a refresh completato → tutte le richieste rilasciate con nuovo access token
- **Fallback:** refresh fallito → logout flow (TSK-217) → redirect /login
- **Trasparente:** nessun loader, nessun redirect temporaneo percepito dall'utente

## Implementation Steps
1. Creare hook useTokenRefresh con timer basato su expiresInSeconds
2. Implementare mutex: flag isRefreshing + Promise queue
3. Implementare rilascio coda post-refresh
4. Implementare fallback: refresh error → trigger logout
5. Integrare nel fetch interceptor

## Definition of Done
- [ ] Refresh automatico pre-expiry
- [ ] Mutex: un solo refresh alla volta
- [ ] Coda richieste rilasciate con nuovo token
- [ ] Fallback → logout
- [ ] Trasparente all'utente
- [ ] Code review approvata
