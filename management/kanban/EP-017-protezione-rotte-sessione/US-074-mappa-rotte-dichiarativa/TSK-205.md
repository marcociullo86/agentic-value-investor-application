# TSK-205 — FE route-config.ts mappa rotte dichiarativa tipizzata

## Context
US-074 richiede che le rotte siano associate ai requisiti di autenticazione tramite metadata dichiarativi, senza logica if/else inline nell'AuthGuard.
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-074-mappa-rotte-dichiarativa/US-074.md §AC]
[^src: design_&_architecture/decisions/ADR-024-session-lifecycle-credential-storage.md §2]

## Technical Specs
- **FE:** `lib/auth/route-config.ts`
- **Interfaccia tipizzata:**
  ```typescript
  interface RouteConfig { path: string; requiresAuth: boolean; roles?: string[]; permissions?: string[]; }
  ```
- **Rotte iniziali:** login (public), register (public), / (public), /analysis (public), /screener (public), /watchlist (auth), /moat (auth), /profile (auth), /admin (auth+admin)
- **Design:** aggiunta nuova rotta protetta = solo nuovo entry nella mappa

## Implementation Steps
1. Creare `lib/auth/route-config.ts` con type RouteConfig
2. Definire array di rotte con requiresAuth, roles, permissions
3. Esportare helper per lookup rotta → config
4. Documentare il pattern per aggiunta nuove rotte

## Definition of Done
- [ ] Configurazione dichiarativa tipizzata
- [ ] Tutte le rotte esistenti mappate
- [ ] requiresAuth e roles per ogni rotta protetta
- [ ] Helper lookup funzionante
- [ ] Code review approvata
