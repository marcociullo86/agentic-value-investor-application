# TSK-206 — FE AuthGuard middleware.ts Next.js

## Context
US-073 richiede un AuthGuard centralizzato che protegge le rotte, reindirizza a login con returnUrl, gestisce ruoli e sessione scaduta.
[^src: management/kanban/EP-017-protezione-rotte-sessione/US-073-auth-guard-centralizzato/US-073.md §AC]
[^src: design_&_architecture/decisions/ADR-024-session-lifecycle-credential-storage.md §1]

## Technical Specs
- **FE:** `middleware.ts` Next.js (App Router)
- **Logica per stato utente:**

| Stato | Azione |
|---|---|
| Non autenticato → rotta protetta | Redirect `/login?returnUrl={originalPath}` |
| Autenticato senza ruolo | Redirect `/403` |
| Sessione scaduta | Logout silente → redirect `/login` con messaggio |
| Autenticato → /login o /register | Redirect a `/` |

- **Verifica auth:** cookie `isAuthenticated=true` (hint, non security — verità sul server)
- **UX feature:** non controllo di sicurezza (defense-in-depth backend indipendente)
- **Legge** route-config.ts (TSK-205) per determinare requisiti rotta

## Implementation Steps
1. Creare `middleware.ts` con matcher per rotte app
2. Implementare lettura cookie isAuthenticated
3. Implementare redirect logic per i 4 stati
4. Integrare con route-config.ts per lookup requisiti
5. Preservare returnUrl in query string

## Definition of Done
- [ ] Non autenticato → redirect /login con returnUrl
- [ ] Post-login → redirect a returnUrl
- [ ] Ruolo insufficiente → /403
- [ ] Sessione scaduta → logout + redirect
- [ ] Rotte pubbliche accessibili
- [ ] Code review approvata
