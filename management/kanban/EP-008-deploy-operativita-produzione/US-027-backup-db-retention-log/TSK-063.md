# TSK-063 — Script backup pg_dump giornaliero + retention 14d

## Context

US-027 e runbook R1.1: backup giornaliero 02:00 UTC, retention 14 giorni, destinazione `/var/backups/valueinvesting/`, RPO 24h.
[^src: design_&_architecture/operations/deploy-runbook-r11.md §Backup PostgreSQL]
[^src: management/kanban/EP-008-deploy-operativita-produzione/US-027-backup-db-retention-log/US-027.md §Acceptance Criteria]

## Technical Specs

- **Infra:** Script shell `src/docker/scripts/backup-postgres.sh` (o `ops/`) eseguibile da cron host.
- **Comando:** `docker compose -f docker-compose.prod.yml exec -T postgres pg_dump -Fc ...` come runbook.
- **Purge:** `find … -mtime +14 -delete` su directory backup.
- **Documentazione:** sezione runbook già presente — aggiornare solo path script se diverso (handoff, no edit L4 salvo gate umano).

## Implementation Steps

1. Implementare script con variabili da `.env` (`DB_USERNAME`, compose file path).
2. Aggiungere esempio crontab in commento script o `README` docker.
3. Test manuale in staging: generare dump, verificare file non vuoto.

## Definition of Done

- [ ] Script eseguibile genera dump `.dump` con timestamp.
- [ ] Purge rimuove file >14 giorni (dry-run testabile).
- [ ] Runbook referenzia path script effettivo.
