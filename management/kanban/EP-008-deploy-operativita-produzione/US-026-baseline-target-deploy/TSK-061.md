# TSK-061 — docker-compose.prod.yml + nginx TLS

## Context

ADR-015 definisce topologia prod: VM + Compose (`app`, `postgres:17`, `nginx`). US-026 richiede artefatti ripetibili per staging/prod oltre al runbook già in L4.
[^src: design_&_architecture/decisions/ADR-015-deployment-target-r11.md §Decisione]
[^src: management/kanban/EP-008-deploy-operativita-produzione/US-026-baseline-target-deploy/US-026.md §Acceptance Criteria]

## Technical Specs

- **Infra:** Nuovi file sotto `src/docker/` (o path coerente con `docker-compose.yml` dev):
  - `docker-compose.prod.yml` — servizi `app`, `postgres`, `nginx`, reti, volumi DB, healthcheck.
  - `nginx/nginx.conf` (o template) — reverse proxy `:443` → `app:8080`, static da monolite.
  - Placeholder TLS (certbot volume o commento Let's Encrypt).
- **App image:** riuso Dockerfile multi-stage esistente; tag `valueinvesting:prod`.
- **Sizing:** commenti ADR-015 (2 vCPU / 4 GiB host).
[^src: design_&_architecture/operations/deploy-runbook-r11.md §Deploy staging]

## Implementation Steps

1. Derivare `docker-compose.prod.yml` da compose dev con override prod (no bind mount codice).
2. Aggiungere servizio nginx con dipendenza `app` healthy.
3. Documentare variabili in `.env.prod.example` (task TSK-062) o inline README docker.
4. Smoke locale: `docker compose -f docker-compose.prod.yml up` + `curl localhost/actuator/health`.

## Definition of Done

- [ ] Compose prod avviabile con immagine buildata localmente.
- [ ] nginx inoltra `/` e `/api/*` verso monolite.
- [ ] Runbook §Deploy staging eseguibile con questi file.
