# TSK-062 — .env.prod.example e variabili deploy

## Context

Runbook R1.1 elenca variabili obbligatorie (`FMP_API_KEY`, `JWT_SIGNING_SECRET`, `DB_*`, `CORS_ALLOWED_ORIGINS`, opzionali `FMP_RATE_LIMIT_PER_MINUTE`, `FMP_CACHE_PROFILE_TTL_HOURS`). US-026 richiede assenza ambiguità su secret e env.
[^src: design_&_architecture/operations/deploy-runbook-r11.md §Prerequisiti]
[^src: management/kanban/EP-008-deploy-operativita-produzione/US-026-baseline-target-deploy/US-026.md §Business Rules]

## Technical Specs

- **Infra:** `src/docker/.env.prod.example` (committabile, senza secret reali).
- **Mapping:** allineare nomi a `application-prod.yml` Spring e compose prod.
- **CI (opzionale minimo):** step documentato in README o commento workflow per tag `staging-latest` — full automation opzionale Sprint 6.

## Implementation Steps

1. Creare template con tutte le chiavi del runbook + default ADR-014/016.
2. Aggiungere nota permessi file `.env` (`chmod 600`) sul host.
3. Cross-check con `docker-compose.prod.yml` interpolation.

## Definition of Done

- [ ] Ogni variabile obbligatoria runbook presente in example.
- [ ] Nessun secret reale nel repo.
- [ ] Operatore può copiare example → `.env` e avviare staging.
