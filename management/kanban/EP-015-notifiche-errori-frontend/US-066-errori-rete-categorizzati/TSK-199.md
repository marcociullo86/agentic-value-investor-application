# TSK-199 — FE networkErrorInterceptor: categorizzazione + Correlation ID

## Context
US-066 richiede gestione categorizzata errori di rete (offline/timeout/5xx/4xx) con CTA specifiche e propagazione Correlation ID.
[^src: management/kanban/EP-015-notifiche-errori-frontend/US-066-errori-rete-categorizzati/US-066.md §AC]
[^src: design_&_architecture/decisions/ADR-022-frontend-error-notifications.md §4]

## Technical Specs
- **FE:** `lib/api/network-error-interceptor.ts`
- **Wrapper fetch/SWR** che categorizza errori:

| Categoria | Condizione | Livello | CTA |
|---|---|---|---|
| Offline | !navigator.onLine | error | Verifica connessione |
| Timeout | AbortError | warning | Riprova |
| Server (5xx) | status >= 500 | error | Supporto + correlationId |
| Validation (4xx) | status >= 400 < 500 | info/warning | Correzione campo |

- **Cattura header** `X-Correlation-Id` dalla response e propaga al NotificationService
- **Integrazione:** usato come fetcher SWR e per chiamate dirette

## Implementation Steps
1. Creare `networkErrorInterceptor` wrapper attorno a fetch
2. Implementare categorizzazione: offline, timeout, 5xx, 4xx
3. Catturare header X-Correlation-Id e propagare
4. Integrare con useNotification per display automatico
5. Configurare come fetcher SWR

- [ ] Correlation ID catturato e propagato
- [ ] Integrato con NotificationService
