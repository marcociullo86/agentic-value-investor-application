# TSK-197 — FE errorCodeMap + locales/it.json sezione errors

## Context
US-065 richiede mappatura codici errore backend a messaggi user-friendly localizzati con CTA azionabili.
[^src: management/kanban/EP-015-notifiche-errori-frontend/US-065-mappatura-errori-utente/US-065.md §AC]
[^src: design_&_architecture/decisions/ADR-022-frontend-error-notifications.md §3]

## Technical Specs
- **FE:**
  - `lib/errors/error-code-map.ts` — mapping `type` URI ProblemDetail → i18n key
  - `locales/it.json` — sezione `errors` con messaggi localizzati + CTA
- **Mapping 8+ codici:**

| Backend type URI | Messaggio | CTA |
|---|---|---|
| */validation-failed | Controlla i dati inseriti | Correzione campo |
| */invalid-credentials | Email o password non corretti | Riprova |
| */unauthorized | Accesso non autorizzato | Vai al login |
| */forbidden | Non hai i permessi | — |
| */not-found | Risorsa non trovata | — |
| */email-already-registered | Email già registrata | Vai al login |
| */server-error (5xx) | Si è verificato un problema | Riprova + Supporto |
| */fmp-unavailable | Servizio dati non disponibile | Riprova |
| (unmapped) | Errore generico | Supporto |

- **Fallback:** codice non mappato → messaggio generico con Correlation ID
- **i18n:** tutte le stringhe esternalizzate, mai hardcoded

## Implementation Steps
1. Creare `locales/it.json` con sezione errors e 9+ messaggi
2. Creare `error-code-map.ts` con mapping type URI → i18n key
3. Implementare fallback per codici non mappati
4. Integrare con NotificationService per display automatico

## Definition of Done
- [ ] 8+ codici mappati con messaggi localizzati
- [ ] Fallback generico per codici non mappati
- [ ] CTA coerenti per tipo errore
- [ ] Stringhe in i18n (non hardcoded)
- [ ] Code review approvata
