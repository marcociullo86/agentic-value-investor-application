# TSK-143 — DcfCalculator: valore intrinseco per azione + wiring AnalyzeTickerService

## Context

US-052 documenta un falso positivo `mosSignal = GREEN` su TTD (2026-05-23): il DCF totale aziendale (~9,4 miliardi USD) veniva confrontato direttamente con il prezzo per azione (22,38 USD post stock-split 10:1). La correzione richiede che `DcfCalculator.calculate` produca un valore **per azione** dividendo il totale per `sharesOutstanding`, e che `AnalyzeTickerService` passi la sorgente shares al calcolatore.

[^src: management/kanban/EP-007-hardening-produzione/US-052-dcf-fair-value-per-share/US-052.md §Acceptance Criteria]

## Technical Specs

- **File primario:** `src/backend/src/main/kotlin/com/valueinvesting/webapp/ruleengine/calculators/DcfCalculator.kt`
- **Modifica firma:** aggiungere parametro `sharesOutstanding: Double?` a `DcfCalculator.calculate(...)`. La funzione divide il valore intrinseco totale calcolato internamente per `sharesOutstanding` e restituisce il valore **per azione**.
- **Edge case:** se `sharesOutstanding == null || sharesOutstanding <= 0` → restituire un risultato che indica `NOT_CALCULABLE` (la semantica esistente del tipo `DcfResult` deve supportarlo; vedi TSK-145 per il campo audit `sharesUsed`).
- **Sorgente shares in `AnalyzeTickerService`:**
  - File: `src/backend/src/main/kotlin/com/valueinvesting/webapp/service/AnalyzeTickerService.kt`
  - Logica: estrarre `dataset.incomeStatements.firstOrNull()?.weightedAverageShsOutDil` come sorgente preferita (campo `weightedAverageShsOutDil` in `IncomeStatementDto.kt` riga ~50).
  - Fallback: se `weightedAverageShsOutDil == null || <= 0` → usare `weightedAverageShsOut`.
  - Se entrambi assenti o non positivi → passare `null` (il calcolatore restituirà `NOT_CALCULABLE`).
- **Schema DB:** nessuna migration Flyway. La colonna `rule_engine_result.dcf_intrinsic_value` (BigDecimal) cambia solo **semantica** (da totale a per-share). Aggiungere un commento Kotlin `// SEMANTIC CHANGE 2026-05-23: valore ora per-share, non totale` nel sito di persistenza.
- **OpenAPI:** aggiornare la `description` del campo `dcfIntrinsicValue` nello schema `RuleEngineResultResponse` da `"intrinsic value (USD)"` a `"intrinsic value per share (USD)"`. File atteso: `src/backend/src/main/kotlin/com/valueinvesting/webapp/controller/dto/RuleEngineResultResponse.kt` (annotazione `@Schema` o commento OpenAPI inline).

## Implementation Steps

1. Modificare la firma di `DcfCalculator.calculate` aggiungendo `sharesOutstanding: Double?`.
2. Al termine del calcolo del valore totale, applicare la divisione: `intrinsicValuePerShare = if (sharesOutstanding != null && sharesOutstanding > 0) intrinsicValueTotal / sharesOutstanding else null`.
3. Restituire `intrinsicValuePerShare` come campo principale del risultato (o `null` per `NOT_CALCULABLE`).
4. In `AnalyzeTickerService.analyze(...)`, aggiungere l'estrazione `sharesOutstanding` dal primo income statement annual con la logica preferita/fallback descritta sopra.
5. Passare `sharesOutstanding` alla chiamata `dcfCalculator.calculate(...)`.
6. Aggiornare la description OpenAPI nel DTO di risposta.
7. Compilare e verificare che il modulo backend `./gradlew :backend:compileKotlin` passi.

## Definition of Done

- [ ] `DcfCalculator.calculate` accetta `sharesOutstanding: Double?` e divide il totale per shares quando valorizzato e positivo.
- [ ] `AnalyzeTickerService` estrae `weightedAverageShsOutDil` (fallback `weightedAverageShsOut`) e lo passa al calcolatore.
- [ ] Quando `sharesOutstanding` è null o non positivo, il campo `dcfIntrinsicValue` nella risposta è assente/null e `mosSignal = NOT_CALCULABLE`.
- [ ] `dcfIntrinsicValue` per TTD (DCF totale ~9,4B, shares ~477M) risulta nell'intorno di 19,75 USD, non nell'ordine dei miliardi.
- [ ] Description OpenAPI aggiornata a "intrinsic value per share (USD)".
- [ ] Commento semantic change aggiunto nel sito di persistenza.
- [ ] `./gradlew :backend:compileKotlin` verde.
