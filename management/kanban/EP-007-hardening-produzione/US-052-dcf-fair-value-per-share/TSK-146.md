# TSK-146 — Test suite US-052: DCF per-share, MoS semantica, fixture regressione

## Context

US-052 richiede che il fix DCF per-share sia coperto da test unitari aggiornati, test di semantica del MoS evaluator e integration test con fixture per i tre ticker rappresentativi (TTD, AAPL, MSFT). Include il test dell'edge case critico: `sharesOutstanding = null` → `NOT_CALCULABLE`.
[^src: management/kanban/EP-007-hardening-produzione/US-052-dcf-fair-value-per-share/US-052.md §Acceptance Criteria]

## Technical Specs

- **Suite 1 — `DcfCalculatorTest.kt`:**
  - Aggiornare ogni `assert` su `intrinsicValue` che in precedenza verificava il totale aziendale: ora deve verificare il valore per-share.
  - Aggiungere test: dato `dcfTotale = 9_400_000_000.0` e `sharesOutstanding = 477_000_000.0` → `intrinsicValuePerShare ≈ 19.70..19.80 USD` (tolleranza ±5%).
  - Aggiungere test: `sharesOutstanding = null` → risultato `NOT_CALCULABLE` (campo valore = null).
  - Aggiungere test: `sharesOutstanding = 0.0` → risultato `NOT_CALCULABLE`.
  - Aggiungere test: `sharesOutstanding < 0` → risultato `NOT_CALCULABLE`.
  - Verificare che `sharesUsed` sia popolato correttamente nel `DcfResult` restituito.

- **Suite 2 — `MarginOfSafetyEvaluatorTest.kt`:**
  - La logica formula non cambia → verificare che i test esistenti passino ancora (nessuna modifica alle soglie).
  - Aggiungere/aggiornare assertion sui messaggi di `rationale`: verificare che contengano la stringa "per azione" per i casi GREEN/YELLOW/RED.
  - Aggiungere test: input `dcfIntrinsicValue = null` → `mosSignal = NOT_CALCULABLE` con rationale che menziona "shares non disponibili".

- **Suite 3 — `AnalysisControllerIT.kt`:**
  - Aggiornare le fixture mock di income statement per i ticker AAPL e MSFT: aggiungere `weightedAverageShsOutDil` con valori realistici (es. AAPL ~15B, MSFT ~7.4B) in modo che `dcfIntrinsicValue` resti nell'ordine delle decine/centinaia di USD.
  - Aggiungere fixture per TTD: `weightedAverageShsOutDil = 477_000_000` → verificare `dcfIntrinsicValue` circa 19,75 USD e `mosSignal != GREEN` (atteso RED perché 22,38 > 19,75).
  - Verificare che per un ticker senza shares nel mock income statement, il response abbia `dcfIntrinsicValue: null` e `mosSignal: NOT_CALCULABLE`.
  - Le fixture esistenti che assertano `dcfIntrinsicValue` in miliardi devono essere corrette (erano buggate by design per il test precedente — aggiornare all'ordine di grandezza corretto per-share).

## Implementation Steps

1. Aprire `DcfCalculatorTest.kt`, aggiornare i test esistenti che assertano il totale, aggiungere i quattro nuovi test edge case.
2. Aprire `MarginOfSafetyEvaluatorTest.kt`, verificare passaggio test formula invariata, aggiungere/aggiornare assert su rationale stringhe + test NOT_CALCULABLE per dcf null.
3. Aprire `AnalysisControllerIT.kt`, aggiornare le fixture JSON WireMock dell'income statement per includere `weightedAverageShsOutDil`. Aggiungere fixture TTD.
4. Eseguire `./gradlew :backend:test` e verificare suite verde.
5. Correggere eventuali assert in altri test che potrebbero essere impattati dall'aggiornamento di firma `DcfCalculator.calculate`.

## Definition of Done

- [ ] `DcfCalculatorTest` verde con i nuovi test per-share + 3 edge case shares null/zero/negativo.
- [ ] `MarginOfSafetyEvaluatorTest` verde, con assert su rationale "per azione" e test NOT_CALCULABLE per dcf null.
- [ ] `AnalysisControllerIT` verde con fixture AAPL, MSFT, TTD — valori `dcfIntrinsicValue` nell'ordine di USD per azione.
- [ ] Caso TTD verifica: `dcfIntrinsicValue ≈ 19.75 USD` e `mosSignal != GREEN`.
- [ ] Caso shares assenti: `dcfIntrinsicValue: null` + `mosSignal: NOT_CALCULABLE`.
- [ ] `./gradlew :backend:test` verde senza skip.
