# TSK-145 — DcfResult: campo sharesUsed (audit) + OpenAPI description

## Context

US-052 richiede tracciabilità del numero di shares utilizzato per la divisione, per supportare debug e audit dei valori DCF per-share. Aggiungere `sharesUsed: Double?` a `DcfResult` e opzionalmente propagarlo in `RuleEngineResultResponse`. Aggiornare anche la description OpenAPI del campo `dcfIntrinsicValue` (se non già fatto in TSK-143, questo task ne è il consolidamento formale).
[^src: management/kanban/EP-007-hardening-produzione/US-052-dcf-fair-value-per-share/US-052.md §Business Rules]
[^src: management/kanban/EP-007-hardening-produzione/US-052-dcf-fair-value-per-share/US-052.md §Acceptance Criteria]

## Technical Specs

- **File primario:** `src/backend/src/main/kotlin/com/valueinvesting/webapp/ruleengine/calculators/DcfResult.kt`
  - Aggiungere `val sharesUsed: Double? = null` — il valore del `sharesOutstanding` effettivamente usato nella divisione (o `null` se il calcolo era `NOT_CALCULABLE`).
- **Propagazione opzionale in `RuleEngineResultResponse`:**
  - Se il DTO di risposta espone già un blocco DCF, aggiungere `sharesUsedForDcf: Double?` come campo opzionale (non breaking — campo nullable, default null in JSON omitted).
  - Annotazione OpenAPI (`@Schema(description = "Numero di azioni diluite medie ponderate usate per il calcolo DCF per-share. Null se DCF non calcolabile.")`) sul campo.
- **OpenAPI `dcfIntrinsicValue`:** consolidare la description aggiornata a `"Valore intrinseco DCF per azione (USD). Null se shares non disponibili."` — coordinare con TSK-143 per evitare duplicazione.
- **Nessuna migration DB:** `sharesUsed` è un campo computazionale esposto solo nell'API response, non persistito su DB separatamente (il valore shares è già implicito nel valore per-share persistito).

## Implementation Steps

1. Aprire `DcfResult.kt` e aggiungere `val sharesUsed: Double? = null`.
2. In `DcfCalculator.calculate(...)` (già modificato da TSK-143), popolare `sharesUsed` con il valore di `sharesOutstanding` effettivamente usato.
3. Se `RuleEngineResultResponse` espone dati DCF, aggiungere `sharesUsedForDcf: Double?` con annotazione `@Schema`.
4. Verificare che il field sia omesso nel JSON quando `null` (configurazione Jackson `@JsonInclude(NON_NULL)` o equivalente Spring Boot default).
5. Compilare e verificare `./gradlew :backend:compileKotlin`.

## Definition of Done

- [ ] `DcfResult` contiene `sharesUsed: Double?`.
- [ ] `DcfCalculator` popola `sharesUsed` con il valore effettivo (o `null` per NOT_CALCULABLE).
- [ ] `RuleEngineResultResponse` espone `sharesUsedForDcf: Double?` (omesso dal JSON quando null).
- [ ] Description OpenAPI `dcfIntrinsicValue` aggiornata a semantica per-share.
- [ ] `./gradlew :backend:compileKotlin` verde.
- [ ] Nessun campo DB aggiunto (solo API response layer).

## Dependencies

- TSK-143 (DcfCalculator con shares parameter — prerequisito strutturale).
