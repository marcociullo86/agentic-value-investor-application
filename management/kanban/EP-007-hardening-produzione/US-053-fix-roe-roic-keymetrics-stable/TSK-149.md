# TSK-149 — KeyMetricsDtoTest: contract test deserializzazione fixture /stable reale

## Context

US-053 richiede un contract test di deserializzazione che fallisce in assenza del fix `@JsonProperty`. Questo task crea (o aggiorna se esiste) `KeyMetricsDtoTest.kt` con una fixture JSON realistica estratta dallo schema reale `/stable/key-metrics` (da `raw/fmp_docs.json:1176`), e verifica che dopo TSK-148 i campi `roe` e `roic` siano valorizzati.
[^src: management/kanban/EP-007-hardening-produzione/US-053-fix-roe-roic-keymetrics-stable/US-053.md §Acceptance Criteria]

## Technical Specs

- **File test:** `src/backend/src/test/kotlin/com/valueinvesting/webapp/fmp/dto/KeyMetricsDtoTest.kt` (creare se non esiste; se esiste, aggiornare aggiungendo il nuovo test case).
- **Fixture JSON da usare** (estratta da `raw/fmp_docs.json:1176`, payload AAPL reale):
  ```json
  {
    "symbol": "AAPL",
    "date": "2024-09-28",
    "calendarYear": "2024",
    "period": "FY",
    "returnOnEquity": 1.6459350307287095,
    "returnOnInvestedCapital": 0.4430708117427921,
    "revenuePerShare": 25.41,
    "netIncomePerShare": 6.08,
    "peRatio": 34.19
  }
  ```
  (Includere i campi minimi necessari per la deserializzazione; altri campi del DTO saranno null per default.)
- **Test da scrivere:**
  1. `deserializesReturnOnEquityFromStablePayload()`: deserializzare la fixture sopra → verificare che `dto.roe == 1.6459350307287095` (tolleranza delta 1e-9).
  2. `deserializesReturnOnInvestedCapitalFromStablePayload()`: stessa fixture → `dto.roic == 0.4430708117427921`.
  3. `returnsNullWhenFieldAbsent()`: deserializzare JSON senza `returnOnEquity`/`returnOnInvestedCapital` → `dto.roe == null`, `dto.roic == null` (politica DTO: assente = null, non zero).
- **Aggiornamento fixture esistenti:** se `FmpAdapterRestClientIT.kt` o test simili hanno fixture JSON per `key-metrics` con i vecchi nomi (`roe`, `roic` come chiavi JSON), aggiornarle con i nuovi nomi (`returnOnEquity`, `returnOnInvestedCapital`). Altrimenti quei test fallirebbero dopo il fix perché le fixture non rispecchiano il payload reale.
- **ObjectMapper:** usare `ObjectMapper()` con i moduli Kotlin standard (o iniettare il bean Spring se il test è un `@SpringBootTest`); preferire un test puro JUnit5 senza contesto Spring per velocità di esecuzione.

## Implementation Steps
