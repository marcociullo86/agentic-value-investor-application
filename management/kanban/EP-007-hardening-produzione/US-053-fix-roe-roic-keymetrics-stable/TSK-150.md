# TSK-150 — Integration test: ROE_10Y_AVG e ROIC_10Y_AVG classificatori su fixture reali

## Context

US-053 richiede verifica end-to-end che il fix `@JsonProperty` sblocchi effettivamente i segnali `ROE_10Y_AVG` e `ROIC_10Y_AVG` nella pipeline di analisi completa. Questo task aggiorna o aggiunge test di integrazione nel rule engine per i tre ticker rappresentativi.
[^src: management/kanban/EP-007-hardening-produzione/US-053-fix-roe-roic-keymetrics-stable/US-053.md §Acceptance Criteria]
[^src: management/kanban/EP-007-hardening-produzione/US-053-fix-roe-roic-keymetrics-stable/US-053.md §Business Rules]

## Technical Specs

- **Suite target:** `AnalysisControllerIT.kt` (integration test existente che testa la pipeline analisi E2E con WireMock) o `RuleEngineServiceIT.kt` se dedicato.
- **Fixture da aggiornare:** le stub WireMock per l'endpoint `/stable/key-metrics` che oggi probabilmente non includono i campi `returnOnEquity`/`returnOnInvestedCapital` (per questo i segnali erano NOT_CALCULABLE). Aggiornare tutte le fixture mock di key-metrics per AAPL, MSFT con il payload `/stable` reale (vedi fixture da `raw/fmp_docs.json`).
- **Aggiungere fixture TTD:** creare fixture mock `/stable/key-metrics?symbol=TTD` con almeno 5 anni di record contenenti `returnOnEquity` e `returnOnInvestedCapital` valorizzati (valori plausibili sintetici per test).
- **Assert per AAPL e MSFT:**
  - `signal.ruleId == "ROE_10Y_AVG"` → `signal.signal != NOT_CALCULABLE` (il segnale deve essere GREEN, YELLOW o RED).
  - `signal.ruleId == "ROIC_10Y_AVG"` → `signal.signal != NOT_CALCULABLE`.
- **Assert per TTD:**
  - Stessi assert: ROE e ROIC non sono NOT_CALCULABLE con le fixture aggiornate.
- **Nota policy:** se la fixture ha meno di 5 anni di dati valorizzati, il segnale può legittimamente restare NOT_CALCULABLE per policy (US-053 §Business Rules: "se anche dopo il fix il provider restituisce meno di 5 esercizi con ROE o ROIC valorizzati, il segnale resta NOT_CALCULABLE"). Le fixture di test devono quindi contenere almeno 5 record annuali con campi valorizzati.
- **Nessun cambiamento** a `RoeRule.kt` o `RoicRule.kt` — verificare solo che ricevano i valori non-null dal DTO.

## Implementation Steps

1. Aprire il file di integration test esistente per l'endpoint `/api/analysis/{ticker}`.
2. Individuare le stub WireMock per `/stable/key-metrics` e aggiornare il payload JSON con i nomi di campo `/stable` reali per almeno 5 anni (AAPL, MSFT).
3. Aggiungere (o completare) una stub WireMock per TTD `/stable/key-metrics` con almeno 5 record annuali valorizzati.
4. Aggiungere assert che verificano `ROE_10Y_AVG != NOT_CALCULABLE` e `ROIC_10Y_AVG != NOT_CALCULABLE` nelle response per AAPL, MSFT, TTD.
5. Eseguire `./gradlew :backend:test` e verificare suite verde.

## Definition of Done

- [ ] Fixture WireMock per `/stable/key-metrics` di AAPL e MSFT contengono `returnOnEquity` e `returnOnInvestedCapital` per almeno 5 anni.
- [ ] Integration test per AAPL verifica `ROE_10Y_AVG` e `ROIC_10Y_AVG` non sono NOT_CALCULABLE.
- [ ] Integration test per MSFT idem.
- [ ] Integration test per TTD idem (con fixture sintetica aggiunta).
- [ ] I test falliscono se le annotazioni `@JsonProperty` vengono rimosse da `KeyMetricsDto` (regression guard).
