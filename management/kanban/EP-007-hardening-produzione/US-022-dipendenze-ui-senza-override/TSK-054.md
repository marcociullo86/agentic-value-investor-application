# TSK-054 — Rimuovi --legacy-peer-deps da CI e Dockerfile

## Context

Quattro punti usano `--legacy-peer-deps` per `swr@2.2.5` vs `react@19`: `.github/workflows/ci.yml` (3 job FE), `.github/workflows/contract-check.yml`, `src/docker/Dockerfile` stage fe-build.

[^src: management/kanban/EP-007-hardening-produzione/US-022-dipendenze-ui-senza-override/US-022.md §Acceptance Criteria]

## Technical Specs

- **Infra:** Rimuovere flag e commenti follow-up da:
  - `.github/workflows/ci.yml` — job `fe-test`, `fe-e2e`, `fe-e2e-realbe`
  - `.github/workflows/contract-check.yml` — step npm install FE
  - `src/docker/Dockerfile` — `RUN npm ci` / `npm install` stage fe-build
- **Runbook:** `deploy-runbook-r11.md` step build già presuppone assenza flag post US-022 (nessuna modifica L4 richiesta se già testuale).

## Implementation Steps

1. Rimuovere `--legacy-peer-deps` da tutti i workflow e Dockerfile.
2. Aggiornare commenti che citano gap `fe-swr-peer-r19` → risolto con TSK-053.
3. Verificare pipeline CI verde su branch di feature.

## Definition of Done

- [ ] Zero occorrenze `legacy-peer-deps` nel repo (grep).
- [ ] CI frontend + contract-check + Docker build verdi.
- [ ] US-022 AC su CI/container/workflow soddisfatti.
