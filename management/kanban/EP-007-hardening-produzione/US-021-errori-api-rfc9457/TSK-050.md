# TSK-050 — FlatteningProblemDetailHttpMessageConverter

## Context

US-021 richiede extension members (`ticker`, `timestamp`, `reason`, …) al top-level del body `application/problem+json`, non sotto `properties`. ADR-012 accetta un converter dedicato con precedenza sul serializer Spring default.
[^src: management/kanban/EP-007-hardening-produzione/US-021-errori-api-rfc9457/US-021.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-012-problemdetail-rfc9457-flatten.md §Decisione]

## Technical Specs

- **BE:** Nuova classe `FlatteningProblemDetailHttpMessageConverter` in `src/backend/src/main/kotlin/com/valueinvesting/webapp/config/`.
- **Registrazione:** `WebMvcConfigurer.extendMessageConverters` — inserire in testa alla lista dei converter.
- **Algoritmo:** `Map` con campi RFC (`type`, `title`, `status`, `detail`, `instance`) + `problemDetail.properties.forEach`.
- **Output:** `ObjectMapper` applicativo, `Content-Type: application/problem+json`.
- **Non** ripetere mixin Jackson / `@JsonComponent` su `ProblemDetail` (gap documentato in `JacksonConfig.kt`).
[^src: design_&_architecture/decisions/ADR-012-problemdetail-rfc9457-flatten.md §1. Serializzazione dedicata]

## Implementation Steps

1. Implementare `FlatteningProblemDetailHttpMessageConverter` (read/write solo per `ProblemDetail` + media type problem+json).
2. Registrare via `@Configuration` + `WebMvcConfigurer`.
3. Verificare manualmente `GET /api/search/UNKNOWN` → JSON con `ticker` sibling di `status`, non `properties.ticker`.
4. Rimuovere o deprecare commenti "known gap" in `JacksonConfig.kt` se il path è risolto.

## Definition of Done

- [ ] Risposta 404 ticker inesistente espone `$.ticker` al top-level.
- [ ] Nessun campo extension rilevante resta sotto `properties` su handler `GlobalExceptionHandler`.
- [ ] `bootTest` verde senza regressione su endpoint auth/analysis/search.

## Dependencies

- Nessuna (prerequisito per TSK-051, TSK-052).
