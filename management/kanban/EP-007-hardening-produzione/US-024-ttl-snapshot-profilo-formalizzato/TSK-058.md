# TSK-058 — Property fmp.cache.profile-ttl-hours

## Context

ADR-014 formalizza TTL profilo 1h distinto da bilancio 24h. L5 usa costante hardcoded `PROFILE_TTL = Duration.ofHours(1)` in `FmpCacheService.kt`; US-024 richiede property configurabile `fmp.cache.profile-ttl-hours`.
[^src: design_&_architecture/decisions/ADR-014-fmp-profile-snapshot-ttl.md §Decisione]
[^src: management/kanban/EP-007-hardening-produzione/US-024-ttl-snapshot-profilo-formalizzato/US-024.md §Acceptance Criteria]

## Technical Specs

- **BE:** `@ConfigurationProperties` o `@Value` per `fmp.cache.profile-ttl-hours` (default `1`).
- **Env:** `FMP_CACHE_PROFILE_TTL_HOURS` mappato in `application-prod.yml` / runbook deploy.
- **Servizio:** `FmpCacheService` — sostituire `PROFILE_TTL` costante con valore iniettato.
- **Invariato:** TTL bilancio 24h su `fmp_financial_snapshot` (ADR-004).

## Implementation Steps

1. Aggiungere property in `application.yml` + binding classe config esistente o nuova `FmpCacheProperties`.
2. Iniettare in `FmpCacheService` e usare in `getOrFetchProfile`.
3. Documentare in commento riferimento ADR-014 (rimuovere nota gap aperto).
4. Verificare header `X-Data-Snapshot-At` / stale su endpoint che usano profilo.

## Definition of Done

- [ ] Default runtime = 1h senza env override.
- [ ] Override env cambia TTL senza rebuild.
- [ ] Nessuna regressione cache bilancio 24h.

## Dependencies

- Nessuna (prerequisito TSK-059)
