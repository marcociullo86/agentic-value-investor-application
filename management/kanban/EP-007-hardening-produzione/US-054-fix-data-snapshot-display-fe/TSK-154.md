# TSK-154 — Playwright E2E: regressione display dataSnapshotAt su /analysis/AAPL

## Context

US-054 richiede un test end-to-end che verifica la regressione specifica: il campo "Dati al" sulla pagina di analisi di un ticker di fixture non deve mostrare un numero a 13 cifre ma una data leggibile in italiano. Il test copre anche la verifica che snapshot E2E esistenti siano aggiornati per riflettere il nuovo formato senza falsi negativi.
[^src: management/kanban/EP-007-hardening-produzione/US-054-fix-data-snapshot-display-fe/US-054.md §Acceptance Criteria]

## Technical Specs

- **Framework:** Playwright (stack qa frontend — `factory.config.yaml`).
- **Suite target:** aggiornare o estendere la suite E2E esistente per la pagina analisi (probabile file `src/frontend/e2e/analysis.spec.ts` o `src/frontend/tests/e2e/analysis.spec.ts`).
- **Fixture ticker:** AAPL (presente nella whitelist static export — gap `fe-static-export-tickers`; confermato disponibile nel test E2E esistente TSK-022).
- **Test da aggiungere/aggiornare:**

  **Test 1 — Campo "Dati al" mostra mese abbreviato (not epoch):**
  ```
  Given: pagina /analysis/AAPL caricata con fixture backend (WireMock o real backend stub)
  When: il pannello Traffic Light è visibile
  Then: il testo del campo "Dati al" contiene almeno uno dei mesi abbreviati italiani
        (gen|feb|mar|apr|mag|giu|lug|ago|set|ott|nov|dic)
  And:  il testo del campo "Dati al" NON contiene la sequenza "1.779" (timestamp epoch formattato)
  And:  il testo del campo "Dati al" NON è un numero puro a 13+ cifre
  ```

  **Test 2 — Aggiornamento snapshot (se presente):**
  - Se la suite E2E usa `expect(page).toHaveScreenshot()` o assertion snapshot sul pannello Traffic Light, aggiornare gli snapshot baseline per riflettere il nuovo testo del campo data (evitare falsi negativi da snapshot con il vecchio formato epoch).

- **Selettore target:** individuare l'elemento HTML che contiene "Dati al" — probabile pattern `data-testid="snapshot-date"` o un label con testo "Dati al". Se il selettore non esiste, aggiungere `data-testid="snapshot-date"` al componente in `page.tsx` come parte di questo task (modifica minore).
- **Backend fixture:** usare la stessa modalità del test E2E esistente (TSK-022 con WireMock reale backend o fixture statica Next.js). Assicurarsi che la fixture di risposta includa `dataSnapshotAt` valorizzato.

## Implementation Steps

1. Aprire la suite E2E Playwright per la pagina analisi.
2. Aggiungere un test `"campo Dati al mostra data leggibile, non epoch"` con le assertion descritte sopra.
3. Se manca il `data-testid="snapshot-date"`, aggiungerlo in `app/analysis/[ticker]/page.tsx` sull'elemento che contiene il campo data.
4. Se esistono snapshot visivi del pannello Traffic Light, eseguire `npx playwright test --update-snapshots` per aggiornare i baseline con il nuovo formato data.
5. Eseguire `npx playwright test` e verificare suite verde.

## Definition of Done

- [ ] Test E2E verifica che il campo "Dati al" su `/analysis/AAPL` contenga un mese abbreviato italiano.
- [ ] Test E2E verifica che il campo "Dati al" NON contenga la sequenza `"1.779"` (regressione specifica della issue).
- [ ] Snapshot Playwright aggiornati se presenti (no falsi negativi sul campo data).
- [ ] `npx playwright test` verde nella suite analisi.
- [ ] `data-testid="snapshot-date"` presente sul DOM element del campo (per selettori stabili).
