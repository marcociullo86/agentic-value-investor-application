# TSK-153 — Vitest unit test: formatSnapshotDate edge cases

## Context

US-054 richiede un test unitario che copra il componente helper `formatSnapshotDate`, inclusi tutti gli edge case (input null, undefined, NaN, stringa numerica, ISO string, epoch ms). Questo test è il regression guard per la funzione helper e deve fallire se la logica di formattazione viene modificata in modo errato.
[^src: management/kanban/EP-007-hardening-produzione/US-054-fix-data-snapshot-display-fe/US-054.md §Acceptance Criteria]

## Technical Specs

- **Framework:** Vitest (stack qa frontend — `factory.config.yaml`).
- **File test:** `src/frontend/lib/format-date.test.ts` (o `src/frontend/__tests__/format-date.test.ts` — seguire la convenzione di naming esistente nel progetto).
- **Casi di test da coprire:**

  | Input | Output atteso | Descrizione |
  |-------|--------------|-------------|
  | `1779484360919` (number) | `"22 mag 2026, 11:12 UTC"` | Epoch ms corretto |
  | `"1779484360919"` (string numerica) | `"22 mag 2026, 11:12 UTC"` | Stringa numerica |
  | `"2026-05-22T11:12:40.919Z"` (ISO-8601) | `"22 mag 2026, 11:12 UTC"` | ISO string |
  | `null` | `"—"` | Valore assente |
  | `undefined` | `"—"` | Valore non definito |
  | `NaN` | `"data non disponibile"` | Input non valido |
  | `"not-a-date"` | `"data non disponibile"` | Stringa non parsabile |
  | `0` (number zero) | data 1 gen 1970 formattata | Epoch zero — non è errore, è una data valida (opzionale: verificare che non crashe) |

- **Nota locale:** i test Vitest devono usare `vi.stubGlobal` o impostare esplicitamente il timezone a UTC per garantire riproducibilità indipendente dall'ambiente CI (`process.env.TZ = 'UTC'` o `--pool=forks --poolOptions.forks.singleFork` con variabile d'ambiente).
- **Approccio assertion:** usare `expect(formatSnapshotDate(input)).toBe(expected)` — non snapshot test per l'helper (valori deterministici preferiti).

## Implementation Steps

1. Creare il file `src/frontend/lib/format-date.test.ts`.
2. Importare `formatSnapshotDate` da `./format-date`.
3. Scrivere i casi di test elencati sopra in una `describe("formatSnapshotDate")`.
4. Configurare timezone UTC se necessario per la riproducibilità (`process.env.TZ = 'UTC'` in `vitest.setup.ts` o direttamente nel file).
5. Eseguire `npm run test -- format-date` (o equivalente Vitest) e verificare tutti i test verdi.

## Definition of Done

- [ ] File `format-date.test.ts` esiste con almeno 7 casi di test.
- [ ] Tutti i test verdi in ambiente CI (timezone UTC garantito).
- [ ] Il test per `1779484360919` → `"22 mag 2026, 11:12 UTC"` è presente e verde.
- [ ] I test per `null` e `undefined` verificano il ritorno di `"—"`.
- [ ] Il test per input non valido (`NaN`, stringa non parsabile) verifica `"data non disponibile"`.
- [ ] `npm run test` (o `npx vitest run`) verde nel modulo frontend.
