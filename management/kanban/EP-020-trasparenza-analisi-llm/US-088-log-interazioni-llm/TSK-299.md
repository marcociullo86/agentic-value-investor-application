# TSK-299 — Logging gated delle interazioni LLM (prompt+risposta)

## Cosa fare
1. Introdurre una proprietà di config `deep-analysis.llm.log-interactions` (default false) + `deep-analysis.llm.log-max-chars` (default 8000) in `application.yml`, mappate via `@ConfigurationProperties` o `@Value`, con override env (`DEEP_ANALYSIS_LLM_LOG_INTERACTIONS`, `DEEP_ANALYSIS_LLM_LOG_MAX_CHARS`) propagato nel `.env`/compose (entry point unico .env).
2. Creare un piccolo helper `LlmInteractionLogger` (component) con metodo `log(context: String, systemPrompt: String?, userPrompt: String, response: String, durationMs: Long?)` che logga solo se il flag è attivo, troncando ai max-chars.
3. Cablarlo in `MungerInversionAnalyzer.callLlm` (con context `munger-query`) e `callLlmSynthesis` (context `munger-synthesis`), e in `NewsSentimentService.synthesize` (context `news-synthesis`). Misurare la durata della chiamata.
4. Usare il runId/correlazione già nell'MDC (se presente) nei messaggi.

## Acceptance Criteria
- [ ] Flag off → nessun prompt/risposta loggato (comportamento attuale invariato).
- [ ] Flag on → loggati ticker, tipo chiamata, prompt, risposta troncati a max-chars.
- [ ] Test unitario su `LlmInteractionLogger` (gating on/off + troncamento) — verifica via appender/logback test o flag boolean.

## Note implementative
- NON modificare le firme pubbliche dei servizi; solo iniettare il logger e chiamarlo.
- Evitare regressioni sui test esistenti di MungerInversionAnalyzer/NewsSentimentService (mock invariati).
- Stack: Kotlin 2.2 + Spring Boot 3.5.
