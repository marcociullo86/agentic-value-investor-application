# TSK-300 — Campo sintesi narrativa nel report Munger

## Cosa fare
1. `MungerInversionAnalyzer.callLlmSynthesis`: aggiungere al JSON schema del system prompt il campo `"sintesi": "motivazione narrativa ≤1500 char sul perché del livello di rischio complessivo"`.
2. `SynthesisResponseDto`: aggiungere `@JsonProperty("sintesi") val sintesi: String = ""`.
3. `MungerInversionReport` (model): aggiungere `val sintesi: String? = null`; popolarlo in `parseSynthesisResponse`.
4. Persistenza: `report_json` serializza già l'intero report → `sintesi` incluso automaticamente; verificare che la deserializzazione di report legacy (senza `sintesi`) non fallisca (default null).
5. Esposizione contratto:
   - `MungerReportBlock` (DeepAnalysisResponse.kt): aggiungere `val sintesi: String?`.
   - Mapping in `DeepAnalysisService` dove si costruisce `MungerReportBlock` dal report.
   - `design_&_architecture/api/openapi.yaml` §components/schemas/MungerReportBlock: aggiungere `sintesi` (string, nullable).
   - `src/frontend/lib/api/deep-analysis.ts`: aggiungere `readonly sintesi: string | null` a `MungerReportBlock`.

## Acceptance Criteria
- [ ] La sintesi narrativa è prodotta, persistita e ritornata nel payload `/deep`.
- [ ] Report legacy in cache (senza `sintesi`) deserializzano senza errori (campo null).
- [ ] openapi + DTO + tipi FE allineati (contract-check verde localmente/CI).
- [ ] Test di parsing `parseSynthesisResponse` con e senza `sintesi`.
