# TSK-044 — DcfOverrideController: aggiunta GET /api/dcf-overrides/{ticker}

## Context

US-020 AC#1 richiede che l'utente autenticato possa visualizzare quale metodo DCF è stato applicato e se proviene da override personale. ADR-011 §1 introduce un endpoint `GET /api/dcf-overrides/{ticker}` dedicato: ritorna l'override corrente dell'utente (200) o un 404 Problem Details se non esiste. La REST semantics GET separato evita side-effect rispetto a POST.
[^src: management/kanban/EP-004-valore-intrinseco-margin-of-safety/US-020-override-dcf-method/US-020.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §1. Endpoints (estensione di ADR-007)]

## Technical Specs

- **BE:** `DcfOverrideController.kt` — aggiungere handler:
  ```
  GET /api/dcf-overrides/{ticker}
  Auth: richiesta (SecurityConfig già gata /api/dcf-overrides/**)
  Response 200: DcfOverride { id, ticker, forcedMethod, createdAt }
  Response 404: Problem Details type=https://api/errors/dcf-override-not-found
  ```
- **`DcfOverrideService`:** aggiungere metodo `findByUserAndTicker(userId: UUID, ticker: String): DcfOverride?`.
- Ticker normalizzato uppercase prima del lookup (già fatto in upsert, applicare anche qui).
- `401 Unauthorized` già garantita da `SecurityConfig` — non gestire esplicitamente nel controller.
- **Standards:** RFC 9110 §9.3.1 GET, RFC 9457 Problem Details per 404.
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §1. Endpoints (estensione di ADR-007)]
[^src: design_&_architecture/decisions/ADR-007-api-contract.md §Error format]

## Implementation Steps

1. Aggiungere metodo `findByUserAndTicker(userId, ticker)` a `DcfOverrideService`.
2. Aggiungere handler `@GetMapping("/{ticker}")` in `DcfOverrideController` che:
   - Estrae `userId` da `@AuthenticationPrincipal UserPrincipal`.
   - Chiama `service.findByUserAndTicker(userId, ticker.uppercase())`.
   - Se `null` → `ResponseEntity` 404 con `ProblemDetail`.
   - Altrimenti → `ResponseEntity.ok(override)`.
3. Aggiornare `GlobalExceptionHandler` se si usa un'eccezione custom `DcfOverrideNotFoundException`.
4. Aggiornare OpenAPI spec: aggiungere `GET /api/dcf-overrides/{ticker}` con schemi 200/404.

## Definition of Done

- [ ] `GET /api/dcf-overrides/AAPL` autenticato con override esistente → `200` con `forcedMethod`.
- [ ] `GET /api/dcf-overrides/MSFT` autenticato senza override → `404` con `type=dcf-override-not-found`.
- [ ] `GET /api/dcf-overrides/AAPL` senza token → `401`.
- [ ] Integration test `DcfOverrideControllerIT` copre i tre scenari.
- [ ] OpenAPI spec aggiornata.
