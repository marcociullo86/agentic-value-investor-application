# TSK-048 — FE: pannello override DCF con badge source e pre-popolamento form

## Context

US-020 AC#1 e AC#6 richiedono che l'utente autenticato veda, sul dettaglio analisi di un titolo, quale metodo DCF è stato applicato e se proviene da default-policy o da override personale. ADR-011 §3 introduce il campo `dcfMethodSource` nel payload di `/api/analysis/{ticker}` e il `GET /api/dcf-overrides/{ticker}` per pre-popolare la UI.
[^src: management/kanban/EP-004-valore-intrinseco-margin-of-safety/US-020-override-dcf-method/US-020.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §3. Flag dcfMethodSource nel RuleEngineResult (AC#1, AC#6)]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §Frontend impatto]

## Technical Specs

- **FE:** componente `components/analysis/DcfOverridePanel.tsx`.
- **Badge source:** nella `ValuationSummary` o `TrafficLightPanel`, leggere `dcfMethodSource` dalla response `/api/analysis/{ticker}` e mostrare:
  - `dcfMethodSource = "DEFAULT_POLICY"` → badge "Default policy" (stile neutro).
  - `dcfMethodSource = "USER_OVERRIDE"` → badge "Tuo override" (stile accent).
- **Form override:** componente form con dropdown `forcedMethod` (`GREENWALD` / `FCF_FALLBACK`), pulsante "Imposta", pulsante "Rimuovi".
  - Al mount della pagina analisi (se utente autenticato): chiama `GET /api/dcf-overrides/{ticker}` e pre-popola il form con il metodo corrente (se 404 → form vuoto).
  - Submit → `POST /api/dcf-overrides` body `{ticker, forcedMethod}`.
  - Se risposta `422` → mostrare inline-error con il campo `detail` dal Problem Details.
  - Rimozione → `DELETE /api/dcf-overrides/{ticker}`, poi refresh della pagina analisi.
- Componente visibile solo se l'utente è autenticato (`useAuthStore` → `accessToken !== null`).
- Dopo un'operazione POST/DELETE di successo: invalidare/refetch la query `/api/analysis/{ticker}` per aggiornare il badge.
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §Frontend impatto]

## Implementation Steps

1. Creare `DcfOverridePanel.tsx` con il form e il badge.
2. Aggiungere hook/query `useDcfOverride(ticker)` che chiama `GET /api/dcf-overrides/{ticker}` (con gestione 404 → `null`).
3. In `app/analysis/[ticker]/page.tsx`: importare `DcfOverridePanel`; passare `dcfMethodSource` dalla response analysis; chiamare `useDcfOverride(ticker)` per pre-popolare il form.
4. Gestire il caso 422: leggere `body.detail` dalla response e mostrarlo come errore inline.
5. Dopo POST/DELETE riuscito: rieffettuare il fetch di `/api/analysis/{ticker}`.
6. Unit test Vitest: rendering badge DEFAULT_POLICY vs USER_OVERRIDE; errore inline su 422.

## Definition of Done

- [ ] Badge "Default policy" visibile quando `dcfMethodSource = DEFAULT_POLICY`.
- [ ] Badge "Tuo override" visibile quando `dcfMethodSource = USER_OVERRIDE`.
- [ ] Form pre-popolato con metodo corrente se override esiste (GET 200).
- [ ] Form vuoto se nessun override (GET 404).
- [ ] Submit form con metodo non applicabile → errore inline con `detail` dal 422.
- [ ] Rimozione override → badge torna a "Default policy" dopo refresh.
- [ ] Componente non visibile per utenti non autenticati.
- [ ] Unit test Vitest passa.
