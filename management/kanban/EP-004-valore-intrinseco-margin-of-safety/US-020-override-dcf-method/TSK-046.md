# TSK-046 — AnalyzeTickerService: lookup override utente + dcfMethodSource + Vary header

## Context

US-020 AC#4 e AC#6 richiedono che `/api/analysis/{ticker}` sia auth-aware: se autenticato applica l'override personale, se anonimo applica la default-policy; in entrambi i casi il campo `dcfMethodSource` nell'output indica la provenienza del metodo. ADR-011 §3 e §4 specificano le modifiche a `AnalyzeTickerService` e l'aggiunta di `Vary: Authorization` nelle response.
[^src: management/kanban/EP-004-valore-intrinseco-margin-of-safety/US-020-override-dcf-method/US-020.md §Business Rules]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §3. Flag dcfMethodSource nel RuleEngineResult (AC#1, AC#6)]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §4. /api/analysis/{ticker} auth-opzionale (AC#4)]

## Technical Specs

- **BE:** `AnalyzeTickerService.kt` — modifiche al metodo `analyze(ticker: String)`.
- **Nuovo enum `DcfMethodSource { DEFAULT_POLICY, USER_OVERRIDE }`** nel package `model/` o `ruleengine/`.
- **Logica auth-opzionale in `analyze()`:**
  ```kotlin
  val auth = SecurityContextHolder.getContext().authentication
  val userId = (auth?.principal as? UserPrincipal)?.userId
  val override = userId?.let { dcfOverrideRepository.findByUserIdAndTicker(it, ticker.uppercase()) }
  val (method, source) = when (override) {
      null -> ruleEngine.selectMethod(dataset) to DcfMethodSource.DEFAULT_POLICY
      else -> override.forcedMethod to DcfMethodSource.USER_OVERRIDE
  }
  ```
- **`RuleEngineResultResponse`:** aggiungere campo `dcfMethodSource: DcfMethodSource` (obbligatorio; `DEFAULT_POLICY` per anonymous).
- **Header `Vary: Authorization`:** aggiungere a tutte le response di `GET /api/analysis/{ticker}`:
  - Opzione A: `ResponseEntity.headers { set("Vary", "Authorization") }` nel controller `AnalysisController`.
  - Opzione B: filtro Servlet dedicato per il path `/api/analysis/**`.
  - Preferire Opzione A (più esplicita, già al livello del controller).
- `/api/analysis/**` rimane `permitAll` in `SecurityConfig`; il `JwtAuthenticationFilter` popola opportunisticamente il `SecurityContext`.
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §4. /api/analysis/{ticker} auth-opzionale (AC#4)]
[^src: design_&_architecture/decisions/ADR-006-authentication.md §Endpoint policy]

## Implementation Steps

1. Creare `DcfMethodSource.kt` enum.
2. Aggiungere `dcfMethodSource: DcfMethodSource` a `RuleEngineResultResponse` (e al DTO/serializzazione JSON).
3. Modificare `AnalyzeTickerService.analyze()` con la logica auth-opzionale sopra.
4. Iniettare `DcfOverrideRepository` in `AnalyzeTickerService` (se non già presente).
5. In `AnalysisController`, aggiungere `Vary: Authorization` alla response.
6. Aggiornare OpenAPI: campo `dcfMethodSource` obbligatorio nello schema `RuleEngineResult`, header `Vary` documentato.

## Definition of Done

- [ ] `GET /api/analysis/AAPL` anonimo → `dcfMethodSource: "DEFAULT_POLICY"`.
- [ ] `GET /api/analysis/AAPL` autenticato senza override → `dcfMethodSource: "DEFAULT_POLICY"`.
- [ ] `GET /api/analysis/AAPL` autenticato con override GREENWALD → `dcfMethodSource: "USER_OVERRIDE"`, `dcfMethod: "GREENWALD"`.
- [ ] Response contiene header `Vary: Authorization`.
- [ ] Integration test `AnalysisControllerIT` copre i tre scenari.
- [ ] OpenAPI `RuleEngineResult` include `dcfMethodSource` come campo required.
