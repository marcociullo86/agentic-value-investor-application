# TSK-045 — DcfFeasibilityCheck: componente feasibility nel package ruleengine

## Context

US-020 AC#5 richiede che la richiesta di un override su metodo con dati storici insufficienti venga rifiutata con messaggio esplicito. ADR-011 §2 specifica un componente `DcfFeasibilityCheck` nel package `ruleengine/feasibility/` che riusa `GreenwaldMaintenanceCapexEstimator` e `FcfFallbackEstimator` esistenti, esponendo il metodo `.isFeasible(dataset): FeasibilityResult`. Il POST a `/api/dcf-overrides` invoca questo check prima del save.
[^src: management/kanban/EP-004-valore-intrinseco-margin-of-safety/US-020-override-dcf-method/US-020.md §Business Rules]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §2. Feasibility validation (AC#5)]

## Technical Specs

- **BE:** Nuovo `DcfFeasibilityCheck.kt` in `com.valueinvesting.webapp.ruleengine.feasibility`.
- **API interna del modulo:**
  ```kotlin
  data class FeasibilityResult(val feasible: Boolean, val reason: String?, val availableYears: Int?, val requiredYears: Int?)
  fun canApply(ticker: String, method: DcfMethod): FeasibilityResult
  ```
  - Richiede il dataset FMP del ticker (da `FinancialDataService` cached).
  - Per `GREENWALD`: verifica che PPE/Revenue siano disponibili per almeno 5 anni. Se insufficienti → `FeasibilityResult(false, "PPE_RATIO_HISTORY_INSUFFICIENT", availableYears=N, requiredYears=5)`.
  - Per `FCF_FALLBACK`: verifica che FCF storici non siano tutti nulli o negativi. Se insufficienti → `FeasibilityResult(false, "FCF_HISTORY_INSUFFICIENT", ...)`.
- **Nuovo `DcfMethodUnfeasibleException`** in `service/exception/`:
  - Campi: `method: DcfMethod`, `reason: String`, `availableYears: Int?`, `requiredYears: Int?`.
- **`GlobalExceptionHandler`:** aggiungere handler `DcfMethodUnfeasibleException` → `422 Unprocessable Entity` con Problem Details:
  - `type=https://api/errors/dcf-method-unfeasible`
  - `detail` con messaggio leggibile
  - `extensions: { method, reason, availableYears, requiredYears }`
- **`DcfOverrideService.upsertWithFeasibilityCheck(userId, request)`:** chiamare `DcfFeasibilityCheck.canApply(ticker, method)` prima del save; se `!feasible` → throw `DcfMethodUnfeasibleException`.
- Rinominare o wrappare il metodo `upsert` precedente.
- **Standards:** RFC 9110 §15.5.21 (422 Unprocessable Entity).

## Implementation Steps

1. Creare `DcfFeasibilityCheck.kt` con la logica di verifica PPE history e FCF history.
2. Creare `DcfMethodUnfeasibleException.kt`.
3. Aggiornare `GlobalExceptionHandler` con handler 422.
4. Aggiornare `DcfOverrideService`: aggiungere `upsertWithFeasibilityCheck()`, chiamarlo dal controller `POST`.
5. Scrivere unit test `DcfFeasibilityCheckTest` con dataset sintetici (pochi anni PPE, FCF tutti negativi).
