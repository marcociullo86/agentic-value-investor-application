# TSK-047 — Contract-test: 4 path US-020 obbligatori (ADR-011)

## Context

ADR-011 §Conseguenze dichiara obbligatori quattro contract-test: `dcfMethodSource = USER_OVERRIDE` quando bearer + override esistono; `dcfMethodSource = DEFAULT_POLICY` per anonymous; `dcfMethodSource = DEFAULT_POLICY` per autenticato senza override; `Vary: Authorization` presente nelle response di `/analysis`. Questi test sono la regression suite che garantisce che l'isolamento per-utente (US-020 AC#4) e il flag source (AC#6) non regrediscano.
[^src: management/kanban/EP-004-valore-intrinseco-margin-of-safety/US-020-override-dcf-method/US-020.md §Acceptance Criteria]
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §Conseguenze]

## Technical Specs

- **QA:** Suite di contract-test Spring MVC Test o RestAssured con Testcontainers per gli endpoint `GET /api/analysis/{ticker}` e `POST /api/dcf-overrides`.
- **Test 1 — USER_OVERRIDE:** utente autenticato ha override GREENWALD per AAPL → `GET /api/analysis/AAPL` → `dcfMethodSource: "USER_OVERRIDE"`, `dcfMethod: "GREENWALD"`.
- **Test 2 — DEFAULT_POLICY anonimo:** nessun bearer → `GET /api/analysis/AAPL` → `dcfMethodSource: "DEFAULT_POLICY"`.
- **Test 3 — DEFAULT_POLICY autenticato senza override:** utente autenticato, nessun override per AAPL → `GET /api/analysis/AAPL` → `dcfMethodSource: "DEFAULT_POLICY"`.
- **Test 4 — Vary header:** `GET /api/analysis/AAPL` (qualsiasi auth) → response header `Vary` contiene `"Authorization"`.
- **Test 5 — 422 feasibility:** `POST /api/dcf-overrides` con metodo non applicabile al ticker → `422` con `extensions.reason` corretto (usa fixture con dataset sintetico che forza insufficienza).
- Tutti i test usano fixture di dataset FMP pre-configurate (mock o Testcontainers DB con dati sintetici) per controllo deterministico.
[^src: design_&_architecture/decisions/ADR-011-dcf-overrides-api.md §Contract-test obbligatori]

## Implementation Steps

1. Creare (o estendere) `DcfOverrideContractTest.kt`.
2. Setup fixture: utente A con override GREENWALD su AAPL; utente B senza override; dataset sintetico AAPL con PPE history < 5 anni per test 422.
3. Scrivere Test 1: login utente A, GET analysis/AAPL → assert `dcfMethodSource = USER_OVERRIDE`.
4. Scrivere Test 2: GET analysis/AAPL senza auth → assert `dcfMethodSource = DEFAULT_POLICY`.
5. Scrivere Test 3: login utente B, GET analysis/AAPL → assert `dcfMethodSource = DEFAULT_POLICY`.
6. Scrivere Test 4: GET analysis/AAPL → assert response header `Vary` contiene `Authorization`.
7. Scrivere Test 5: login utente A, POST dcf-overrides con method=GREENWALD su ticker con PPE insufficiente → assert 422 con `extensions.reason`.
8. Aggiungere alla CI suite (fase contract-check).
